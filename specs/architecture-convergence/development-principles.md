# CYF统一开发约束：性能、事实归属与DFX

核对日期：2026-11-07。性质：当前用户决定及既有规范的分类收口，不是全仓整改/上线证明。仅适用于CYF。根AGENTS最新用户规则优先；本页承接跨专题原则，具体协议、SQL和验收仍由下列原规格维护，不新增框架、服务、审批或台账。

## 1. 先分事实，再决定改哪一层

| 事实/责任 | 唯一责任边界 | 其他层的用法 |
| --- | --- | --- |
| 外部身份、协议输入 | 认证/接口入口 | 下游使用可信上下文，不层层解析JWT |
| 业务权限、请求/回合状态、完成事实 | API业务服务及事务 | Runtime执行合同，Web展示结果；不各造一套业务状态机 |
| SQL租户隔离 | 既有公共持久化机制 | 不机械为所有DAO追加tenant参数；仅修真实绕过点 |
| 文件/索引分区 | 相应存储适配器 | 不在页面承担安全隔离 |
| 本机身份、目录、进程、会话及执行隔离 | Runtime/codex-bridge | 不重新实现API业务权限，不按技能名/Provider品牌编排业务 |
| 执行步骤、具体外部协议与经验 | 模型编排；工具/技能脚本实现协议；SKILL提供经验 | 通用bridge不长出每种技能的专属业务分支 |
| 消息/成果展示 | API页级读模型，Web渲染和交互 | 不让Web拼接内部领域表、补齐每条请求或裁定业务完成 |
| 发布、回退、磁盘保留 | 既有主机工具及Owner | 不交给应用请求链，也不因清理重启服务 |

同一可信边界内无新风险不重复校验；网络边界认证、数据库并发约束、业务权限不是同一检查。扩大调查范围不自动扩大修改范围。具体规则见[RB-1](../juyiting-skill-execution/responsibility-boundaries.md)及[校验政策](../../api/docs/interface-catalog/validation-policy.md)。

## 2. 用户交互的长期链路

1. 用户输入进入已有请求入口，由API完成准入、绑定和持久事实；消息ID、请求ID、回合ID各有职责，不强行混用。
2. 已准入请求交给Runtime，执行侧复用适用的原生会话。材料请求、工具合同变化不能仅因字段变化就无条件创建新thread或重发全历史；实际隔离边界/原生能力不允许复用时说明原因。**不承诺任何场景都1:1，也不以相同thread ID证明正文必已送达模型。**
3. 流式片段用于实时预览；不每片段查库、确认派发、校验整份历史合同或重新投影成果。派发已接收事实只在需要时转换一次，不能为逐帧优化再引入独立协议而无真实必要性。
4. **保留完整最终回复**，沿最终事务保存权威内容与完成事实。用户早先“删除最终回复、缓存流再落库”的提议已被后续明确撤销；不要恢复该临时方案。工具成果、业务完成事实与聊天正文不是同一种数据。
5. 成果投影优先由真实完成事实触发。数据库提交与通知有先后关系：不能先发完成通知再指望未提交数据已可读。跨进程失败如需恢复，复用已有持久事实与补偿入口，不为正常流程增加全套新兜底表。
6. 页面每次接口请求读取**一页20条消息及该页展示投影**，不是调20次接口；读到21条可仅用于判定下一页。消息、请求摘要、成果元数据由服务端集合读取。禁止逐条补查、浏览器ID集合第二轮补齐、首次全量历史及成果正文预载。
7. 历史按游标显式翻页，成果按固定版本预览/下载；页面窗口释放与事件衔接保持连续、去重和作用域隔离。最终历史、实时预览、任务完成与正式成果验收分开表示。

数据模型保留request→多个turn扩展性；普通用户消息经常对应一个请求，但系统消息、工具事实不是新的用户请求，多轮次关系也不等于每轮重建原生thread。表数不是优化指标：先说明事实所有者、生命周期、约束和读写成本，再删派生/重复字段。详见[数据模型复核](../juyiting-ui-baseline-20261006/optimization/data-model-review-20261105.md)、[限定范围详设](../juyiting-ui-baseline-20261006/optimization/detailed-design.md)。旧模型复核中的合表候选不是最终删表决定。

## 3. 性能：减少工作，不叠缓存和定时器

- 前端以事件/订阅更新为主，取消没有业务变化仍持续读取的轮询；页面退出释放订阅，请求合并及迟到响应隔离放现有生命周期管理位置。
- 后端/Runtime优先真实事件、阻塞等待或已有消息入口。内存唤醒不等于持久队列，不保证进程崩溃后不丢通知。确需补偿时集中、有索引、按待处理状态/游标读取；不每请求/每事务新建扫描定时器，不全库空扫。心跳、SSE连接保活和业务轮询分别统计；不能为“零定时器”删掉必要网络保活。
- 先实测SQL次数、文件/网络字节和分配量，再决定缓存。技能包正文不因“可用内存多”永久整包放全局缓存；文件内容留存储层，下载/安装按需流式处理；确有收益的缓存须说明键、失效、生命周期和增长来源，不借缓存复制所有历史。
- 工具链共享不可变依赖，执行目录/身份/状态仍隔离；不能把“挂载”当作零复制证明。初始化区分能力声明、依赖就绪和实际调用工具，不为探测就绪调用付费/有副作用工具。
- 启动方返回目标进程身份和明确ready事实，不以shell退出、端口存在或反复全进程扫描替代真实就绪。故障重查应限定对应实例，不制造新常驻扫描器。
- 不用无依据包大小、缓存容量、启动时限、消息长度门槛把正常请求拒绝掉；真实容量、传输超时和解码安全预算仍按所属边界处理。
- 优化必须删掉被替代的临时分支、重复检查与对应失效测试，不长期并存新旧执行路径。局部修复不顺带重构全项目。

## 4. 不过度防御，不无限兼容

每个新增/保留校验应能回答：**具体风险是什么、谁负责、何时触发、失败只影响谁、在哪个定向用例验证**。已有代码/测试不是理由。不为填写这些信息新增流程或门禁系统。

- 保留身份/ACL、租户隔离、事务、幂等、资金与文件完整性、锁归属、安装恢复；性能优化不牺牲这些边界。
- 只读合同容忍明确无害新增字段；未知执行语义、缺失授权、不完整证据不能猜测补全。禁止以旧版本号名单代替能力判断，也禁止为任意旧版本保留所有写入/恢复入口。
- 用户允许实验性产品牺牲部分一致性：优先用于可重建展示投影、短暂状态滞后和预览，不推及资金、授权、已提交成果；断网不能凭空保证既立即可用又强一致。失败归属、重试是否有副作用必须明确。
- 历史记录只读保留不等于继续支持旧任务执行。旧协议退役按既定切换范围删除，不自动重放；“旧任务可以删除”不是可扩用的全库生产数据删除授权。
- 事务内约束由业务/数据库维护；跨层不反复对已验证事实全文hash、重建全输入、比对多个副本。摘要保护放写入/传输等真实完整性边界，不因普通页面GET重复验证全部历史。
- CYF不新增/依赖数据库CHECK；业务规则归既有责任层，主键、唯一键、外键、非空、类型、事务不删除。既有生产CHECK需独立授权迁移，不在启动时全库清理。

## 5. DFX与业务解耦

此处DFX指性能、可靠性、可观测性、安全、可维护性和可运维性，不是新建统一DFX服务。

| 维度 | 必须做到 | 不应做 |
| --- | --- | --- |
| 性能 | 同一请求分段观测，减少重复读写/复制 | 用预算强杀请求、截断流、把服务端耗时冒充前端体验 |
| 可靠性 | 真实状态、必要幂等、明确失败域，按既有事实恢复 | 每帧确认/每层兜底、新建补偿表仅掩盖链路缺陷 |
| 可观测性 | 复用request/turn/执行关联及已有日志，失败样本保留 | 每token落库/重日志、为了指标改变业务状态 |
| 安全 | 入口身份、业务ACL、存储/执行隔离各司其职 | 删除必要保护，或每层重验同一授权 |
| 可维护性 | 一个事实一个所有者，契约变化才联动消费者 | 万能编排器、双轨长期兼容、为局部问题新增框架 |
| 可运维性 | 目标进程ready、可恢复安装、明确临时目录归属 | 在生产目录构建，依赖后台无界扫描清垃圾 |

## 6. 验证与发布口径

- 用户发送→API准入→派发→Runtime接收→模型首片段→浏览器首字→最终回复提交→页面结束，按真实同一请求计时。跨主机时钟未校准不直接相减；runtime完整回复时间不等于用户已看到完整回复。
- 报告样本数、冷/热、版本、测试场景、首字/完整回复及失败样本；分位数只在有足够样本且说明方法时报告。GC次数、累计暂停和单次暂停分别分析，不从单个总量推断根因。
- 按根AGENTS的2026-11-09决定：单次构建发布上限600秒，随构建执行的单元测试计入本次；异常重试经归因重新计时，不跨候选/开发过程累计，也不按阶段拆分规避。回归验证与业务验收单独计时、不受此限。预计或实际超限申请该次例外，保留真实失败；不得给业务请求/流/生产服务下传deadline或盲重试。具体工具是否适配按实际入口核实，不以规则更新冒充实现。
- 复用已有定向验证/受控发布工具；固定commit/tree、测试selector/fixture、工具链和制品摘要。设计、源码、测试、安装、健康、业务验收分别报告，不把某轮回归通过写成“所有优化完成”。
- 清理只删除明确失效临时副本；有未提交修改/唯一证据/活动任务的worktree先保全或保留。当前/回退、生产状态、凭据和业务成果不是历史垃圾。
