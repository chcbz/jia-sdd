# UI与交互详细设计

设计基线：完整Demo；以下为**要实现的目标**，包括Demo尚未提供的手动方向按钮。

## 1. 信息架构：场景与办理解耦

```text
聚义厅（首次：厅中实景；可切办事概览）
 ├ 地图人物/热点 ─┐
 ├ 悬赏榜         │
 ├ 厅内议事       ├→ 同一个工作窗口 → 草稿/确认/事项进展/资料/成果
 ├ 百宝箱         │                     └ 选资料 → 临时预览
 ├ 点将册/招贤令 ─┘
 ├ 典籍阁 → 阅读/手札 → 显式引用到草稿
 └ 消息、账户、设置（不含工作空间）
```

名词保持：悬赏榜是入口；其中“我的事项”可含私人委托与协作悬赏，用来源标签区分。“事项”是用户视角集合，不创造通用后台任务。私人收起叫“收入案卷/已查看”；正式任务继续用真实验收/返工术语。

## 2. 全局布局

- 聚义厅木色/暖金用于场景、导航、边框；办事正文用浅色高对比底，不把木纹铺在长文字后面。复用现有地图和肖像，不重新生成美术。
- 顶栏：聚义厅、悬赏榜、厅内议事、百宝箱；好汉、消息、账户为辅助入口。典籍既有热点保留，窄屏“更多”也能直达，不能只能在地图找。
- 二级场景切换：“厅中实景 / 办事概览”。这是内容偏好，不叫横/竖屏。
- 地图工具：“缩小 / 放大 / 全景 / 横屏或竖屏”。**全景只复位镜头，不切方向。** 声音保留在场景工具/设置，不自动开声。
- 开工作窗口后：标题栏始终有“返回（存在上层时）/当前标题/方向控制/关闭”；关闭回地图或概览原位置，没有“回聚义厅”主按钮。
- 窄屏减少顶栏文字与次级工具，不靠缩小主要文字解决拥挤。一次只突出一个提交类主按钮，返回/保存/取消用次级样式。
- 初始设计token：间距4/8/12/16/24/32，正文16px、辅助14px；触控控件以44px为设计目标。都是可调整设计值，不是未经测算的发布硬门禁。长标题可换行，关键状态不能仅靠颜色。

## 3. 横竖屏详设（必须补齐）

独立状态：`homeMode=map|overview`；`orientationPreference=auto|portrait|landscape`；`physicalOrientation`；`presentationMode`；`availableRect`。软键盘只改变最后一项，不能把写到一半的页面切成另一种业务模式。

### 3.1 用户操作
1. 地图工具和活动窗口标题栏提供同一方向入口。点击立即显示“正在切换”；业务操作不因方向请求被终止。
2. 支持的宿主/浏览器申请真实方向；仅在实际确认后提示“已横屏”。不支持时保留页面并明确“请旋转设备；当前布局仍可继续使用”。
3. 微信H5已有虚拟横屏路径可以保留，但明确是“横向布局”，不可声称系统键盘也旋转了；未完成真机验证不标记通过。
4. 已接入小程序的原生横/竖页桥继续复用，迁移前保存服务端草稿及非敏感位置引用；传递ID，不将正文、Token放进URL。接收页重新鉴权后恢复。
5. 桌面入口表达为“布局：自动/横向/纵向”，不假装旋转显示器；演示版也用“布局预览”区分真机方向。
6. 用户主动返回竖屏/退出全屏必须随时可用；只释放本页持有的全屏/方向资源。晚到的成功回调不能把已退出页面重新横过来。
7. 成功/拒绝/不支持/用户退出均保留事项、草稿、引用版本、选择器临时选择、滚动和焦点。新的物理旋转可更新布局，不改地图/概览偏好。
8. 原源码3000ms方向等待逻辑需在W01自检：无证据的等待阈值不可直接沿用为强制取消。改用真实API结束、宿主响应、用户撤回及生命周期归属；非阻断提示与资源拥有权分别管理。

### 3.2 布局矩阵

| 环境 | 地图 | 办理窗口 | 返回与输入 |
|---|---|---|---|
| 桌面宽屏 | 完整既有引擎；热点/人物 | 居中，地图边缘仍可见；内容不必强制双栏 | 单活动层；焦点回触发入口 |
| 手机竖屏 | 仍可默认地图；可一键概览 | 满可用宽高，紧凑顶栏，正文单主要滚动区 | 底部动作避开安全区；选材/预览逐层替换 |
| 手机低高度横屏 | 沿用横图，不挤窄场景 | 近全幅；压缩重复标题，不用右侧半宽抽屉 | 首屏至少识别事项/可信状态/下一步；必要时动作随正文滚动而非压住输入 |
| 键盘开启 | 场景不重建 | 根据实际可用区域收缩；输入与提交可滚到 | 不依据高度重新判断物理方向；保留正在输入/中文组合状态 |
| 宿主切页横屏 | 只保存镜头/来源快照 | 新页鉴权后恢复同一草稿/事项与活动层 | 保存失败不声称已暂存；提供留在当前页/重试/明确放弃 |

以现有390×844、844×390、320×700及1440×900为已知回归样本，不宣称这些尺寸覆盖全部设备。布局按实际容器与内容决定断点；不得把Demo固定视口公式直接复制进生产。

## 4. 页面规格

| 页面 | 默认显示与主动作 | 次级/深层内容 | 失败和空状态 |
|---|---|---|---|
| 地图首页 | 人物、五个热点；“提出需求”“继续上次” | 声音、方向、全景 | 场景失败时办事导航仍可用；不是全页白屏 |
| 办事概览 | 提出需求、最近事项、确需本人处理 | 类型筛选、查看全部 | 加载骨架；分区失败分别重读；成功空集才欢迎引导 |
| 悬赏榜 | 私人/协作标签；标题、可信状态、执行者、最近变化、下一步 | 搜索、范围、案卷 | 不让列表筛选改写首页计数；各来源部分失败可见 |
| 需求草稿 | 需求、输出格式、资料引用条；主按钮“下一步” | 更多要求；来源摘要、保存状态 | 保留输入，说明哪部分未保存；不吞掉校验失败 |
| 交办确认 | 目标、好汉及能力理由、固定输入版本、范围、费用授权 | 更换好汉、查看材料 | 能力失效原地换人；费用未知诚实说明，不编报价 |
| 事项进展 | 目标、可信状态、下一步、最近变化；执行编号可复制 | 资料/成果页签、按需技术明细 | 未知→核对原执行；真实失败→原因/补救；不默认重复执行 |
| 成果 | 来源执行、版本、文件类型、预览/下载 | 比较信息、提出修改 | 无成果不显示“完成”；预览不支持可下载；下载失败不作已领取 |
| 百宝箱 | 资料/成果/回收站标签；文件行列表、搜索、上传 | 文件预览、版本、关联事项、更多管理 | 列表与详情错误独立；模拟上传不进入正式版 |
| 厅内议事 | 明确普通密议/事项讨论/公议及对象 | 历史；选取内容整理成草稿 | 不因全局selectedTask暗换会话；草稿跨范围不串 |
| 点将册 | 已接入好汉、能力、可用性、关联事项 | 招贤/接入既有入口 | 不伪造在线；接入/收费操作另走原授权 |
| 典籍/手札 | 原阅读入口与保存状态 | 引用片段到草稿 | 不覆盖阅读进度、不默认分享整篇私密手札 |
| 消息 | 需补资料/需确认/成果可查看等真实动作 | 原事项定位、只标已读 | 已读不等于验收；无权消息隐藏内容并说明不可访问 |
| 个人中心 | 账户、设置及原有费用能力 | 原管理入口 | 不添加工作空间或另一套文件入口 |

### 4.1 草稿与交办的具体细节

- 用户先写目标，已从人物进入可预填好汉，但必须可见且可更换；无需先懂Agent配置。
- 未选资料不一定错误；由真实输入能力/需求决定必填，不固定“必须传一个文件”。
- 格式选项来自真实capabilities与前端适配交集；Demo的TXT不能直接变生产选项。已有六类图片/Office/PDF能力分别回归，未开放格式不伪装可选。
- 保存状态为“未保存 / 保存中 / 已保存 / 保存失败”；仅收到服务端确认才说已保存。失焦与显式返回触发保存，输入合并节奏是可调交互参数，不是请求截止时间。
- 确认范围默认私人；若来源是正式任务，显示任务实际可见范围，不能用私人确认文案遮盖团队共享。
- 修改版本是新执行：主按钮写“确认修改并执行”，显示旧成果与新增费用授权；不是原查询按钮换一个图标。
- 待确认按钮可防双击，服务端仍需幂等。网络未知不把按钮重新变回“立即生成”。

### 4.2 事项页三个视图

```text
[返回] 活动简报                      [方向] [关闭]
已受理 · 吴用 · 仅自己可见             [核对进展]
执行编号（展开/复制）；状态来源时间
进展 | 资料 | 成果
────────────────────────────────────
该视图的单一主内容区域
```

“查看成果”直接打开成果；“补充要求”到新草稿；“继续填写”到原草稿。技术ID、算法术语、未启用计划不占首屏。正式任务额外动作按既有规则：提交交付、验收/返工；不把这些按钮给私人委托。

### 4.3 百宝箱三级结构

- 独立浏览：L1 文件列表 → L2 文件预览/版本 → L3 更多管理（重命名、回收等）。版本用列表/下拉，不把每个管理功能做大卡片。
- 事项取材：L1 原草稿 → L2 选材 → L3 临时预览；“使用所选资料”直接回L1。取消不改变原引用；上传成功留在选择器并勾选新版本。
- 正常流程不出现第四个可见窗口。删除/回收确认在当前管理面内替换，或内联确认；不能叠一个新的独立modal。
- 当前执行输入版本不可被上传新版本偷偷替换；“已有新版本”只是提示，使用需要新草稿/确认。
- 全局百宝箱不展示独立交付台。文件“用于新委托”进入共享编辑器；关闭后可回原文件位置。

## 5. 层级与状态恢复契约

逻辑最多三层，**视觉始终只有一个活动窗口**。业务详情中的进展/资料/成果是同层页签，不再增加弹窗深度。

- 返回：退一个逻辑层。Escape/系统返回同义，不能直接把所有层清空。中文输入法组合输入时不抢Escape。
- 关闭：退出整次办理会话，草稿先保存；保存失败则停在原窗口说明，允许用户明确选择放弃。临时选材未确认不写入正式草稿，但可在本次会话保留。
- 关闭已受理执行不取消后台工作；不触发POST；刷新通过同一executionId恢复。
- 主导航跳转：先处理未保存草稿，再转新入口；原草稿仍能从最近事项找到。不得跨来源复用同一可变表单。
- 地图输入锁与窗口活动一致；Tab只遍历活动层；关闭恢复触发点，点已消失则聚义厅标题或安全导航。
- 列表滚动恢复用稳定行ID优先、像素位置辅助，筛选变化不滚到不存在的项。地图恢复镜头，不让旧快照回写业务选中人。
- URL/深链只含对象ID、视图/方向偏好，不放需求、聊天、文件URL、Token；深链重新鉴权。

## 6. 文案与状态准则

| 不使用 | 使用 |
|---|---|
| 已提交=已完成 | 已受理，尚未取得成果 |
| 当前无待办（其实加载失败） | 暂时未能读取，重试读取 |
| 重试（实际会再执行/再收费） | 核对原执行 / 确认新执行，分别呈现 |
| 工作空间/交付台多个入口 | 百宝箱取资料；事项里看交付 |
| 匹配度86%=成功率 | 推荐理由：支持读取PDF，最近可用 |
| 已保存（仍只有内存） | 暂存在当前页面 / 已保存到账号，区分 |
| 修改成功（只是创建新运行） | 修改请求已受理，旧成果仍可查看 |

## 7. 本轮Demo差距声明

本轮不修改Demo；手动方向按钮、真方向申请/键盘、服务端保存、真实费用/权限/生成仍属待实现。87项Demo断言只能复用为交互回归用例，不能充当这些能力的验收结果。下一轮交互补样优先覆盖：活动预览层中切横/竖、保存失败关闭、重复提交未知、正式/私人不同成果动作。
