## 1. 结论与业务定位

**保留地图与聚义厅风格，让地图、议事、悬赏榜、百宝箱共同服务于同一件事的完成。**

不是另造一个“工作空间”，也不是把所有功能都塞进弹窗。地图负责进入和人物感，概览负责开始和继续，事项负责目标/进展/成果，百宝箱负责资料复用。横竖屏是布局能力，不是两个业务系统。

首个业务试点：用户带一份非敏感材料，从与好汉讨论开始，形成明确委托，收到可下载的文件，提出一次修改，重新回来仍能找到两个版本。可选PDF或已有受控格式，不能把Demo的预制PDF当作模型产出。

价值假设（待验证）：减少重写需求、找不到事项、重复执行和人工解释；提高“实际获得可用成果且可再次找到”的比例。不预报转化率/收入提升。

## 3. 必须保留与本次调整

| 保留 | 调整 |
|---|---|
| 既有地图引擎、人物、热点、拖动缩放、声音入口 | 地图、顶部导航进入同一办理会话；不移植Demo的简化地图替换melonJS |
| 手动横竖屏切换、物理旋转适配、已接入的宿主方向桥 | 方向与地图/概览切换解耦；任何活动弹窗内能切换，保持内容 |
| 悬赏榜、议事、百宝箱、点将册、典籍/手札 | 统一来源传递、返回、草稿与成果关联；不统一后台权限语义 |
| 私人执行与正式任务、验收/返工既有能力 | 外观一致，业务动作按来源与权限展示；不把私人“已查看”变成正式“验收通过” |
| 个人中心账户、设置、真实费用入口 | 个人中心不恢复“工作空间”；百宝箱无独立“回聚义厅”业务按钮 |
| 文件不可变版本、历史执行、未知意图核对 | 按事项呈现，不让用户自己跨模块拼接 |

旧方案中“地图仅可选、首页优先表单”“横屏右侧半宽抽屉”不再作为目标；**首次默认地图，记住主动选择的地图/概览偏好，且两种方向均可用。**

## 4. 范围与优先级

### 必须交付：可试点的真实闭环
- S01 地图首页+办事概览；原入口完整；显式横/竖屏切换。
- S02 统一工作窗口、二/三级逻辑导航、返回/焦点/滚动恢复。
- S03 有身份隔离的草稿保存与刷新恢复、固定版本选材、明确交办。
- S04 私人事项轻量关联索引；原任务仍用原taskId；同一事项多次执行与成果。
- S05 首页独立待处理/最近列表；加载、部分失败、真空分别表现。
- S06 普通密议与事项讨论显式分开；讨论转草稿需确认快照与范围。
- S07 真实执行回执、未知核对、成果预览/下载/再次修改；终态可靠回传。
- S08 角色/素材/格式真实能力、范围及费用说明；不把推荐值说成成功率。
- S09 桌面、竖屏、低高度横屏、键盘和方向切换回归；真机单列。

### 完整体验收尾
- S10 百宝箱完整版本/回收/恢复、成果反查事项；轻量列表而非功能卡片阵列。
- S11 点将能力页、已有接入入口衔接；典籍引用与阅读返回；消息定位原事。
- S12 业务试点、可用成果与回访观察、后续优化排序。

### 不在本次估算内
重新制作地图美术/寻路引擎、108角色重绘、新文件格式引擎、在线Office编辑、全新AI能力、团队共享云盘、跨组织权限模型、商业账本/真实结算、新语音能力、新小程序产品、原生产历史失败的批量回填。

既有图片/Office/PDF能力要回归，不删除；如回归发现底层格式引擎需新建，列新增工作，不冒充本UI项目已包含。

## 5. 实施原则

1. 体验整合是主线；可靠终态、实际成果是对应业务路径的依赖，不让项目重新变成无穷补丁修复。
2. 前端交互开发与后端/运行时可靠性可并行；不能因UI先做好就扩大推广。
3. 不引入新的任务调度/状态机；新增仅为草稿、私人事项关联及只读投影。
4. 关闭暂存，返回退一层；查询不提交；修改需新意图并保留旧成果。
5. 状态和动作有证据才显示；未知保持未知。慢请求继续可用，不按性能SLO截断。
6. 执行者、输入版本、对象范围显式传入；地图与名册数据流不合并。
7. Owner自检，不设置独立Reviewer。生产DML、额外收费运行、Agent重启不由设计自动授权。
