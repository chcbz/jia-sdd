## 1. 产品定位

**每个用户拥有自己的文件工作空间，统一管理上传资料与 Agent 交付件；文件可独立存在，也可按需关联一个或多个自己的悬赏任务。**

这里的工作空间是用户可见的内容管理空间，不是 Git worktree、Agent 的服务器目录或允许模型任意操作的磁盘。首版按当前认证的 tenant/client/owner 隔离一个逻辑个人空间，不扩展团队协作盘或跨账户共享。

- 用户不发布悬赏，也可以先上传、整理、预览和下载文件。
- 用户可以从空间选择文件交给 Agent，也可在对话中上传；两种入口进入同一文件库。
- Agent 产出的文件自动归入该用户空间；任务页、对话成果卡和空间看到的是同一成果的不同视图，不是三份拷贝。
- 文件保存成功、工具执行完成和用户验收通过分别展示，不把“出现在空间”冒充“已验收”。

## 2. 用户界面与首版管理范围

建议入口：聚义厅/个人中心中的“我的工作空间”；对话附件入口提供“上传文件 / 从工作空间选择”。不要求跳出对话才能操作。

| 视图 | 展示内容 |
| --- | --- |
| 全部文件 | 用户上传与 Agent 生成的文件，显示来源、类型、更新时间、版本、关联任务与处理状态 |
| 我的上传 | 原始资料、图片、用户上传的外部 Office/PDF 文件；不记作 Agent 交付成果 |
| Agent 交付 | 已持久化的生成/修改结果；显示来源 Agent、任务/会话和待确认/已确认状态 |
| 按任务查看 | 某悬赏使用的输入版本、过程/最终成果、修改历史；未关联悬赏的文件可单独筛选 |
| 回收站 | 首版逻辑删除的项目，可恢复；被任务引用的文件说明影响，不伪报已彻底清除 |

首版管理动作：上传、按名称搜索、按类型/来源/任务筛选、重命名、预览、下载、查看版本、关联/取消关联自己的任务、交给 Agent、移入回收站/恢复。高级全文检索、目录树、同步盘客户端、在线内容编辑、分享链接和团队权限后置；简单文件夹若确有整理需求可单独补充，不作为首个闭环前置。

## 3. 三种使用流程

### A. 先有资料，再有任务

上传“季度数据.xlsx”到空间 → 暂不关联任务 → 后续新建“季度汇报 PPT”悬赏 → 从空间选择该文件的 v1 → Agent 读取并生成“季度汇报.pptx” → 新成果同时出现在空间和该悬赏的交付区。

同一数据表可以关联另一个自己的任务。每个任务固定所选版本；后来上传 v2，不会悄悄改变正在执行的 v1 任务。

### B. 不发布悬赏，直接对话处理

选择“方案.docx” → “交给 Agent：精简第二章” → 系统关联既有或新建内部执行 task/run → 生成修改版并归入空间 → 对话预览、下载或继续修改。

**没有公开/用户可见悬赏，不等于没有内部执行记录。** 复用 task/run 和 artifact 做追踪，但不能要求用户先填写悬赏表单。不得给新生成文件伪造一个未发布的公开悬赏。

### C. 在悬赏中持续修改

任务页选成果 v1 → “继续修改”进入同一任务对话 → 明确修改要求 → Agent 获得该版本与被授权材料 → 保存 v2、生成预览 → 空间和任务页显示同一新版 → 用户确认。

同一原件被不同任务改写时，保留各自产出分支/派生关系，不让两个任务争抢覆盖原件。用户明确要求更新某个已有成果时，才按该成果的 expected version/CAS 创建下一版。

## 4. 逻辑对象与唯一事实源（非数据库迁移合同）

| 对象 | 职责 |
| --- | --- |
| 个人空间 | 按认证 owner scope 提供统一文件管理入口，不必先创建物理专属目录 |
| 文件条目 | 稳定标识、显示名称、来源、所有者、创建时间、逻辑删除状态；重命名不改变版本字节或哈希 |
| 文件版本 | 不可变的内容引用、实际类型、字节数、哈希、生成时间及预览引用 |
| 任务文件关系 | 文件精确版本与 task 的关联，区分 input/reference/output；可以一文件关联多任务，但每条均做权限校验 |
| 派生关系 | 输出来自哪些输入/源成果版本，由哪个 Agent、哪个 run、哪次修改请求产生 |

具体落库方案在 C1 冻结；不能据此直接新建平行 artifact 表或第二套任务终态。

- **已有 Agent 成果**：继续以现有 task artifact/version 为内容与版本事实源。空间只添加归档/查询投影及关系，历史成果可按权限纳入视图，不复制内容、不修改旧验收证据。
- **上传原件**：新增或复用 owner-scoped 输入文件元数据和存储能力，允许 task 尚未关联；不能借 `producerAgentId` 把用户上传伪装成 Agent 成果。
- **悬赏关联**：是文件使用/来源关系，不改变文件所有者，不因关联扩大访问权限。任务内仍走既有任务 ACL；工作空间读取只能返回本人有权访问的文件。
- **索引一致性**：文件实际保存后再进入可领取视图；空间索引暂未更新时显示同步状态。使用已有事务/事件和幂等键补投影，能够从权威文件/成果记录重建；重建不重新生成文件。
- **关联/取消关联**：对尚未执行的输入选择可调整；已执行 run 的输入快照和成果来源关系不可被取消关联抹掉。活跃任务要换材料，创建明确修订并检查版本，不暗中替换已领取内容。

## 5. Agent 权限：个人空间不是全量授权

用户可管理自己的整个空间，Agent 只能领取本次执行明确授权的文件版本和必要的历史结果。客户端任务目录只是临时执行环境，不能直接映射用户整个空间。

- 授权从认证用户、明确 Agent、task/run、输入版本绑定推导；下载、预览、缩略图、输出提交均核对当前身份与任务范围。
- 用户只选择 A 文件时，Agent 不能按用户 ID 枚举或读取 B 文件；不能凭文件 ID/哈希或另一个任务的关系绕过授权。
- 在对话中笼统说“处理我的资料”且范围不明确时，先让用户选择/确认，不能自动读取全部上传。
- 用户上传说明或文件内文字不得扩大权限；外部模型调用/资料外发仍需相应授权。
- 撤销关联/授权后停止后续受控领取；已下载进正在执行环境的字节不承诺瞬时收回，按明确取消与清理规则处理并如实告知。

## 6. 保存、删除与找回

- 原件默认保留，修改产生新版本或派生文件；Agent 离线、关闭对话或悬赏归档不使已保存文件消失。
- 首版“删除”明确标为“移入回收站”，不立即物理删除。被运行中任务使用或被正式交付引用时，列明影响，不能一键静默破坏历史记录；不新增授权给已在回收站的文件。
- 任务归档/取消关联不级联删除空间文件；空间重命名/整理不改任务运行时固定的输入版本。
- 永久删除、运行输入保留周期、引用释放和容量策略需单独明确产品语义及实际资源依据；本轮不承诺保留天数、空间额度或自动清理阈值，不执行生产清理。

## 7. MVP 完成定义与顺序

1. 先交付一个 owner 隔离、任务可选的个人文件库，以及文件版本/任务关系合同。
2. 在此基础上打通一个真实文件的“空间选择 → Agent 修改 → 自动归档 → 预览下载 → 再次修改”。
3. 支持悬赏从空间选材料，成果自动双入口可见；同文件复用到两条本人任务时保持独立的输入版本/输出来源。
4. 图片与 PPT/Word/PDF/Excel 各格式沿既有范围分别验收；仅有文件管理页面仍是未完成的 Agent 交付 MVP。

这会扩大 C1/C4 的元数据、查询与管理范围，但不要求建设企业网盘或在线 Office。现有存储、artifact、任务和验收复用原则不变；运行时文件桥接改造范围、真实工具与付费授权仍须按原边界明确，不能由“工作空间”概念自动推导授权。
