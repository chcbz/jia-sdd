# 聚义厅工作空间重设计：以多媒体悬赏议事为中心

日期：2026-09-27。修订：同日收敛多媒体议事、双接应方式、存储边界与影响范围。状态：**proposed / design-only**。

本文件是现有 feature 的设计补充，不修改已冻结合同、版本排期、运行 ledger 或历史验收结论。本轮不改业务代码、线上配置，不触发生成、测试构建或部署。实施前需将确定的合同增量同步至 design/tasks/acceptance/integration，不能将本设计直接视为已实现。

## 0. 最终收敛方案与影响范围（2026-09-27）

**最终推荐：会话优先、产物先持久化、个人归档可选、精确成果验收；保留两种接应方式和现有存储目录，不做存储大迁移。** 本节是本轮讨论的范围收敛入口，后文为详细设计。产品方向收敛不等于 API/迁移合同已冻结或代码已实施。

### 0.1 用户最终流程

提需求并可选工作空间参考资料 → 点将 → 后台自动确保唯一对应悬赏议事并投递需求/资料 → Agent 自主直接答复/生成或必要澄清 → 原会话实时呈现文字、图片、音频、文件 → 持续引用修改 → 按需保存选定内容 → 用户选择最终成果、验收并完成。

- 不增加每轮必点的“开始办理”；既有授权内自动执行，真实权限/费用边界仍必须遵守。
- 普通讨论不等于工具调用；澄清等待不长期占用生成运行的 lease。每次真实生成/修改是可追溯、可恢复的独立执行，保留同一悬赏主会话。
- 展示、生成能力分别验收：必须支持音频展示/播放/下载/保存；不顺带承诺所有 Agent 都会音频生成、语音识别或视频制作。
- 用户未主动保存的会话结果仍持久保管，可继续引用修改；用户空间列表不被每轮试稿自动填满。
- “选为最终成果”是便捷操作，验收时也可直接选择；保存空间不是验收前置条件。

### 0.2 存储与客户端的确定边界

本轮只读核对的本机运行 API 工作目录为 `/opt/cyf/service/api`；其 `application.properties` 配置个人内容根为 `/opt/cyf/service/workspace-private`，正式成果根为 `/opt/cyf/service/task-artifacts-private`。已核对两个目录存在，并观察个人内容对象实际路径符合 `v1/<scopeHash前2>/<scopeHash>/<contentHash前2>/<contentHash>`。这不是所有远端 Agent 的配置证明。

- **不新增第三套文件系统**。会话文件产物先复用 `/opt/cyf/service/workspace-private` 内容存储，以明确产物记录及任务/会话授权引用；底层字节已持久化，不代表已创建用户可见的个人文件条目。
- “保存到空间”创建/复用个人文件与版本关系，引用已验证内容；文本保存冻结选定消息/片段，不重新调用模型。
- 最终交付暂继续使用 `/opt/cyf/service/task-artifacts-private` 和既有正式协议。既有实现可能复制字节，以精确摘要和来源映射保持一致；**本次不追求全平台物理只存一份，不合并目录、不搬迁历史文件**。
- Agent 默认工作目录、山寨安顿/自家接应方式保留。本机 profile 的受控执行根 `/home/isp/apps/codex-ws-agent/data/private-runs` 继续按 task/run 隔离；自家接应使用自己配置的根，不能硬编码平台本机路径。
- 复用“结构化输入/输出清单 → 下载校验 → 本次工作目录 → 明确路径提示词/工具 → 输出字节回传”的协议，补会话产物用途与精确引用输入；不是只改提示词。
- 已就绪成果由平台授权接口预览/下载，不直接暴露 Agent 本机目录。用户本地源文件不自动全盘同步，仅回传本次明确声明且授权的输出。
- 首版不做共享挂载、对象存储迁移、跨用户内容去重或全局文件服务重构。

### 0.3 改动影响矩阵

规模为设计判断，不是已完成工作量估算；不在代码合同和测试选择确定前给出精确人天/文件数。

| 区域 | 必改内容 | 影响判断与回归边界 |
| --- | --- | --- |
| Web 聚义厅 | 可选参考资料、点将后自动进入会话、混排内容块、播放器/预览、引用修改、保存与验收清单 | 中；议事、需求入口和空间选择器。共用 ChatPanel/消息组件时需回归普通聊天，不能宣称完全零影响 |
| API chat | 需求首次投递协调、结构化内容/附件关联、状态事件与历史读取一致、断线恢复 | 中到大；沿用现有会话域及传输，不为本需求新建聊天系统 |
| API agent/workspace/delivery | 新会话产物用途、精确输入授权、逐轮执行、产物先提交而不自动个人归档/正式交付、保存、最终成果发布与验收 | 大且为关键路径；涉及身份/ACL、lease、事务、幂等、最终版本选择 |
| Agent 客户端 | 议事生成意图接入文件执行；输入支持未归档会话产物；补结果内容块关联及音频支持所需桥接/校验 | 中；两种接应方式使用相同版本协议，不迁移默认工作目录、不扫描整个目录 |
| 数据库 | 内容块/产物来源与引用、投递去重、归档与最终成果关系、版本并发所需增量字段/索引/关系 | 中；预计需要增量迁移，准确表结构在合同冻结时确定；优先复用已有关系/执行输出表，不预设全部新建 |
| 部署配置与验证 | 实际客户端能力、格式配置、媒体读取、向后兼容、浏览器双接应模式回归 | 配置变更限定于新链路所需；不换发布系统、不重启或操作无关 Agent，不将本设计当生产/付费执行授权 |

工程边界为三个运行组件（Web、API、Agent 客户端），对应 Web/API/安装客户端三个实现仓及当前 SDD 协调仓。总体为**中等偏大的跨端功能改造，不是页面小修，也不是整个平台重建**。普通任务、已有文件、历史会话应保持兼容，但必须测试，不承诺未经验证的零影响。

### 0.4 必须先定清楚的协议问题

1. 一次点将对应一次可恢复投递意图；现有任务线程能力先核对是否符合用户主议事 ACL，不因已有 team thread 就直接混用。不能由 chat 和 task 两条路径重复执行同一需求。
2. 增量扩展消息结构与内容用途；旧文本消息、旧 PRIVATE/TASK 调用保持原语义。能力不匹配的客户端保留原功能，新功能明确不可用，不偷偷降级为只返回路径。
3. 新会话产物有稳定标识、真实格式/摘要、来源和授权；支持其直接成为下一轮输入。提示词约束不替代文件/API 权限，不把工作目录划分当完整 OS 沙箱证明。
4. 会话存续与单次 run/lease 解耦；用户思考期间不无限延长旧执行。最终发布复用持久生产者出处，并通过独立的、合法的发布授权/状态转换衔接既有正式协议，不能复用过期 lease、要求浏览器持有 producer token，或让用户冒充 Agent 提交。
5. 验收冻结选定成果集合和版本；有在途新稿时明确提示，由用户决定是否等待/取消或只验收已选稿，不能让晚到结果替换已验收内容。
6. 会话附件就绪和最终内容落库才是可恢复事实。现有 conversation event broker 为进程内实时通知，不能把 SSE 自动连接恢复等同于持久事件回放。首版采用持久消息/产物状态补拉和稳定 ID/修订去重，再按实际需要扩展事件游标，不重做全局事件平台。

### 0.5 实施与完成范围

- **A：冻结增量合同。** 明确消息、产物用途、授权、发布/验收衔接、迁移、恢复和兼容；责任 Owner 自检，不创建独立 Reviewer。
- **B：完整图片链路。** 有/无参考图、自动议事、直接生成/必要澄清、至少连续两轮引用修改、真实预览下载、选择保存、精确最终稿验收。图片闭环必须覆盖恢复与权限，而非把可靠性全部留到最后。
- **C：完整多媒体范围。** 文本片段保存、音频播放/下载/保存、混排附件、各自错误恢复，以及两种接应方式的真实回归。图片通过不能将整项需求标为完成。
- 发布依赖建议：先兼容性数据库/API，再具备协议能力的 Agent 客户端，最后开启 Web 新入口；各阶段绑定实际版本与证据。自家接应客户端可能不能同时升级，按真实能力显示支持范围，不擅自远程更新或操作用户设备。
- 当前仅设计及只读盘点，未改业务代码、数据库、存储目录、客户端配置或线上服务，未触发真实生成、构建或部署。

## 1. 现状校正与问题边界

- 当前后端源码已有个人文件列表、上传、版本、预览、下载、回收站；已有 PRIVATE/TASK 执行、runtime 文件桥接、manifest 提交与正式交付。不是从零建设网盘。

- 沿用上一轮浏览器测试记录：事项 414“画一只鸟”只收到 Agent 本机路径，图片不能加载、下载进入重定向循环；议事中的百宝箱入口要求退回，正式执行按钮标为 PDF。本轮未重跑测试，这些现象不证明唯一根因是 Nginx，也不证明当前本地 Web checkout 就是该线上版本。

## 2. 本次用户确认的主流程与覆盖关系

**提需求（可选参考资料） → 点将 → 自动创建“悬赏议事”并投递需求与资料 → Agent 直接答复/生成或先澄清 → 会话中多媒体展示与持续修改 → 用户按需保存到工作空间 → 用户验收并完成需求。**

本次意图以用户最新补充为准，替代本文件上一版及历史设计中不一致的交互假设：

- 不强制增加“开始生成图片”确认步骤；点将完成即启动需求办理。只有真实缺少关键条件、能力不可用或超出已授权费用/资料外发范围时，才请求补充或授权。
- 不要求用户先选输出格式或先打开百宝箱。Agent 可按需求和可见默认值直接处理，无法合理判断时才澄清。
- 不把每轮 Agent 回复自动归入“我的空间”，也不把每轮试稿都当正式交付。用户可选择保存任何满意的中间或最终内容，保存不等于验收。
- 用户在同一个悬赏议事中持续补充内容，不必为每次修改重新提需求、点将、开会话。
- 多媒体展示范围至少含文本、图片、音频和文件；音频展示/播放纳入本次范围，不等于同时承诺录音、语音识别、实时语音通话或音频生成能力全部可用。

历史冻结合同暂不改写。上述变化需要正式合同增量，尤其不能仅靠隐藏“已自动保存”标签冒充用户主动保存。

## 3. 产品模型：三个层次，三个独立动作

| 层次 | 作用 | 持久性与权限 |
| --- | --- | --- |
| 悬赏议事 | 创作现场：需求、澄清、多轮回复、试稿与最终候选 | 消息及已就绪附件由服务端持久保管，按会话/任务 ACL 读取；不依赖 Agent 本机临时文件 |
| 我的空间（百宝箱） | 用户主动整理、复用的内容资产 | 上传原件和用户选定保存的内容；按认证 tenant/client/owner 隔离 |
| 正式交付与验收 | 固定最终采用哪些内容，记录用户决定 | 引用精确版本/内容摘要；复用现有正式交付及验收协议 |

三个动作彼此独立：

1. **发送/生成**：使内容进入会话；不是“保存到我的空间”，不是“需求完成”。
2. **保存到工作空间**：将选定的文本、图片、音频或文件纳入个人文件库；不自动验收任务。
3. **验收并完成**：确认精确最终成果集合，经服务端正式交付及验收成功后完成需求。

“未保存到工作空间”只表示尚未个人归档，不表示只存在浏览器内存或可以随时丢失。会话附件也必须可刷新恢复；保留与清理策略另行明确，不设置任意过期天数。已保存内容不随会话删除而丢失。

同一内容被会话、空间、交付引用时保留一致来源，优先复用不可变内容引用，不要求先完成物理去重迁移。Agent 仅是执行者，其 inputs/outputs/scratch 目录不是以上任意一层的用户文件库。

## 4. 用户界面

### A. 提需求

- 需求描述输入框。
- “添加参考资料”：从工作空间选择，展示缩略图/文件名和精确版本；可以不选，不因此禁止点将。
- 资料可移除、补充。上传新资料可作为辅助入口，但不是必选流程。
- 用户选择的是明确文件版本，不是给 Agent 开放整个空间。若存在真实外发/费用边界，在授权适当位置说明，不对普通流程增加无意义确认。

### B. 点将后自动进入“悬赏议事”

- 自动创建并绑定当前悬赏的议事会话，标题可为“悬赏议事 · 画一只鸟”。重试或刷新复用该会话，不重复新增。
- 自动投递一条可见的“需求与资料”起始消息：需求原文、参考资料卡片、明确接收 Agent；不得假装附件已发送却仅传文件名或机器路径。
- 展示真实状态：正在发送、已送达/待处理、Agent 回复中，或失败与恢复动作。点将成功不代表需求已投递成功。
- Agent 资料不足时在当前会话提问；合理默认值足够时直接给出结果，不固定先走澄清问卷。

### C. 多媒体会话

| 内容 | 会话中的展示 | 主要操作 |
| --- | --- | --- |
| 文本 | 流式文字、经过安全处理的 Markdown | 复制、保存整段/选中片段、引用继续讨论 |
| 图片 | 生成中占位；真实字节就绪后原位显示缩略图 | 放大预览、下载、保存到空间、引用修改 |
| 音频 | 加载状态、内嵌播放器、可用时的时长 | 点击播放/暂停、可支持时拖动、下载、保存到空间；不默认自动播放 |
| 其他文件 | 文件名、实际类型、大小、处理状态 | 支持格式内嵌/抽屉预览；所有已就绪可领取文件提供下载和保存 |

同一条回复可混排文本、多个图片/文件及音频；消息完成与单个附件就绪分别跟踪。多媒体显示支持不等于对应工具具备生成或理解该格式的能力，两者分别标明。

会话输入区始终支持补充文字、从空间附加资料、引用某个已有结果。用户说“把这只鸟改成蓝色”时，界面明确显示被引用的图；上下文无法唯一确定时 Agent 才询问。旧试稿保留，不覆盖消息内容或静默改源文件。

### D. 右侧/顶部辅助信息

议事是主界面；资料、已保存内容和最终成果仅是侧栏/移动端辅助页签。选择资料、预览、保存后回到原会话，保留输入草稿和任务上下文，不要求退出议事。

## 5. 保存到工作空间与验收

### 保存

- 文本、单个附件或一条回复中的多项内容均可选择保存；不强制保存整段聊天。
- 首次保存默认创建独立文件。文本默认保存为 UTF-8 Markdown/TXT，并记录消息和选区快照；不声称现有上传白名单已支持此候选格式。
- 记录来源 task/conversation/message/part、执行标识、精确内容摘要及源文件版本。重复保存同一选定内容应返回已有保存结果；另存副本是明确动作。
- 保存中、已保存、保存失败分开显示；“已保存”提供“在空间查看”。失败重试保存，不重新调用 Agent。
- 新试稿默认可另存；只有用户明确选择“更新已有文件”时才创建该文件的新版本，校验 expected version/CAS。修改参考图不默认覆盖参考原件。
- 不同文本选区是不同保存对象。文本保存冻结该次选择的内容，不能因后续消息修订悄悄变化。

### 验收并完成

- 用户点击后查看最终成果清单，选择本次接受的精确文本快照/图片/文件版本，可排除不满意的试稿；不默认接受所有历史输出。
- “是否已保存到我的空间”不是验收前置条件。可提供可选项“同时保存选中的成果到工作空间”，不能强制多一次保存点击。
- 未保存内容仍可凭服务端持久内容引用形成正式交付，不使用临时 URL 或模型文字承诺充当交付。
- 对“画一只鸟”，最终清单必须含可领取的真实图片；纯文本需求可接受持久文本快照，不强制所有需求都产出图片/文件。
- 系统先确保精确成果集合已正式提交，再应用用户验收决定；只有既有服务端任务状态真正完成时，界面才显示“需求完成”。不能由前端一键直接改状态或绕过现有任务规则。
- 用户可能在正式提交前选择最终稿：需经任务授权的服务端/生产者完成正式提交，再以用户身份记录验收；不把生产者 lease/token 暴露给浏览器或伪装用户为生产者。
- 任一环节失败按真实阶段恢复。保存、提交、验收、完成可能跨事务，不伪称一个原子动作；验收成功但可选个人归档失败时，分别提示并只重试归档，不反复验收。

## 6. 端到端实例

1. 用户输入“画一只鸟”，可从空间选 `参考鸟.jpg / v2`，也可不选；选择扈三娘。
2. 点将成功后出现“悬赏议事 · 画一只鸟”，需求和所选资料自动发送一次。
3. Agent 可以直接生成；也可回复“希望写实还是水墨？”，用户在原会话回答。明确默认值可直接采用，避免不必要澄清。
4. 图片生成中显示状态，服务端接收真实图片后在原会话显示图片和下载/保存按钮，无需刷新。
5. 用户引用图片补充“羽毛改成蓝色，背景保持不变”，Agent 读取这张图并给出新稿，而不是丢掉原图重新猜。
6. 用户可将满意的新稿保存到空间，也可先继续讨论；图片和必要说明可分别选择保存。
7. 用户点击“验收并完成”，确认采用新稿和说明，系统正式提交并验收；未选旧稿不自动成为最终成果。

## 7. 技术设计增量（候选，尚未冻结 API）

### 自动建会话与首条投递

- 建议以 owner/task/assignmentRevision 识别一次点将投递意图；同一悬赏复用稳定议事会话。点将、确保会话、首条投递之间采用可恢复协调，跨模块时优先事务 outbox/幂等消费者，而非浏览器成功回调中的一次性请求。
- 保存需求修订和文件版本快照；服务端验证接收 Agent、任务权限、输入授权后投递。部分资料读取失败不得静默丢弃并宣称全部送达。
- 点将成功但会话/发送失败时明确局部成功，重试补齐缺失步骤，不重复点将或重复生成。
- 重新点将是新 assignment revision，不当作普通网络重试。保留历史并显式投递交接上下文，更新旧 Agent 后续访问/提交权限，校验在途运行，不暗中把全部历史私有资料授权新 Agent。

### 结构化消息与事件

建议在现有 chat 消息/事件协议上增加可兼容的内容块，不直接把以下候选字段当现有合同：

- 消息：`messageId, conversationId, taskId, replyToMessageId, parts[]`。
- 内容块：`partId, kind(text/image/audio/file), state, text或assetRef, mimeType, name, byteLength, contentHash, sourceExecutionId`；图像尺寸、音频时长按实际检测结果补充。
- 素材引用由服务端解析成当前身份可访问的预览/内容入口，不信任模型自行填写的 URL、哈希或本机路径。
- 事件意图：文字增量、附件处理中、附件就绪/失败、回复完成、归档结果；稳定事件 ID/顺序或版本用于去重、断线补拉及历史恢复。
- 工具结果与聊天流按 execution/message/part 关联；聊天结束不代表生图完成。已取消/身份切换后到达的事件不污染其他会话。

“实时展示”首片定义为：文字可增量显示，处理状态及时更新，完整图片/音频一经服务端就绪即在原消息出现。**不承诺图片逐像素生成或未完成音频边生成边播**；若工具实际提供可验证的渐进预览/音频分片，另补协议，不能伪造进度。

### 解耦会话产物、个人归档与正式提交

当前 `PersonalWorkspaceExecutionServiceImpl` 的 PRIVATE 输出提交会创建空间文件；TASK 提交还会建立正式交付。故本需求不是仅增加渲染组件：需要明确新增的“会话产物先持久提交，用户再选择归档/最终提交”边界。

- 优先复用既有私有存储、内容校验、task/run/lease、artifact、manifest 与正式验收；会话资产是引用/可见性/用途关系，不先造一套并行网盘。
- 为新会话执行设计显式产物用途/提交模式，使“会话可见”与“个人归档”“正式提交”分开；旧接口调用继续保留原语义，不能把历史 `OUTPUT_COMMITTED` 偷换为新含义。
- 新模式的输入可包含精确空间版本和经授权的会话产物，支持未归档试稿继续修改。不能强迫用户为每轮修改先保存空间，也不能把会话附件作为无鉴权 URL 传给 runtime。
- 合同冻结时必须补方法/路径、请求/事件形状、错误分类、身份/生产者权限、状态转换、幂等键、版本并发与回放规则，以及旧调用兼容策略；本轮不发布未经实现的虚构 endpoint。
- 现有单输出执行可先复用，消息可组合多次执行产物；展示多媒体不自动要求一次 runtime commit 支持多文件事务。保存多项内容需显示逐项结果，最终交付清单则固定所有选中项，缺项不得伪报完成。
- TASK 使用通用 `document` 分类、文本/音频 MIME 白名单、音频内容读取与播放/拖动能力均需逐项核对，不凭图片成功宣称音频可用。

## 8. 安全、生命周期与恢复

- 用户身份由服务端认证推导；当前私有存储实现 tenant 限定为 `0`，不宣称已开放任意多租户。会话资产、工作空间、正式交付均校验各自 ACL。
- Agent 仅访问本次明确授权的资料和必要上下文；内容或附件中出现的指令不能扩大访问范围。预览/下载/播放器/断点读取均受权限约束，不公开私有目录或长期凭据。
- 附件显示基于真实 MIME/内容校验，不信任扩展名；文本和可执行文档预览安全处理，禁止通过 Markdown/HTML 脚本访问用户凭据。
- 生图和其他工具调用仍限于已明确授权的账户、用途和额度；此产品设计不授权本开发线程启动付费生成，也不授权 Agent 任意增加收费工具。
- 输入快照及输出不可变，多个试稿靠显式来源关系关联；回收站、撤销授权、会话删除和任务归档是不同动作，不能静默破坏正式交付证据或用户已保存文件。
- 未归档会话内容需要清晰保留规则，不凭“临时”任意删除；撤销不承诺收回已被 runtime 下载的字节。
- 网络重试/事件重放使用同一业务意图及原幂等键；响应未知先查状态，404 不证明在途请求未受理。刷新和重新连接不自动再生图。
- 保存失败只重试归档；上传失败优先恢复上传；正式提交失败只恢复提交；用户主动重生成才形成新执行意图。
- 用户取消、真实传输错误、身份切换、租约与锁规则继续保留；慢请求仅观测，不用任意性能 deadline 中止流程。媒体预览失败仍可保留合法下载，但该格式的预览验收不能报通过。

3. **多媒体与可靠性补齐**：文本选区保存、音频播放/保存/下载、混排附件、断线刷新恢复、重复投递/多端并发/权限回归。图片竖切通过只代表该切片，不代表用户本次完整需求通过。

## 10. 完成定义

必须以真实浏览器、真实服务端与真实 Agent 链路取证，不能用开发助手直接生成文件或伪造事件代替：

- 不选参考资料也能点将并自动进入悬赏议事；选择参考图时 Agent 实际读取指定版本，首条消息可看见需求和资料。
- 点将重试/刷新只得到一个对应议事会话和一次初始投递；部分失败可恢复，不重复生成。重新点将遵循单独权限/交接规则。
- 分别验证 Agent 可直接给结果及在确有歧义时澄清；均在同一会话中继续，不强制第二次“开始生成”。
- 图片在就绪后无需刷新即显示，真实解码宽高有效，下载可打开且摘要匹配；本机路径/重定向循环不能算交付。
- 音频在会话中可点击播放、暂停、下载和保存；验证播放器宣称支持的拖动功能。音频来源与对应消息可追踪，不用静态图假装播放器可用。
- 一条回复可混排文字及附件，附件后于文字完成也能正确更新；断线补拉无重复、乱序不回退、历史刷新可恢复。
- 不满意时引用当前图片继续修改，Agent 实际获得该图；新稿与旧稿均可回看，未保存空间也可继续办理。
- 可分别保存文本片段、图片、音频、文件；未选择内容不混入我的空间。重复保存不产生意外副本，明确另存/新版本仍可执行。
- 最终只验收用户选中的精确成果；无需先手动保存，不将全部试稿自动验收；服务端提交/验收/完成失败时不得前端伪报成功。
- 刷新/Agent 离线后仍能读取已就绪且在保留范围内的会话产物与个人归档；其他账号无权读取媒体、执行及历史，身份切换不泄露旧内容。
- 证据绑定部署/源码版本、task/conversation/message/part、execution/run、文件摘要、正式 delivery、用户验收结果及实际预览/下载。当前均为设计验收项，本轮未执行。
