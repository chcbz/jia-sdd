本计划取代尚未完成的 OD08～OD11 实施顺序；OD00～OD07 的历史证据继续保留，但不能直接作为新版主干的发布候选。

已同步的最新引用为：根仓 `origin/master` `2e2c2c2`、API `origin/develop`
`dc1eeea7`、Web `origin/develop` `7b4c570`，以及 `isp-install/master`
`f8c731d`。API/Web 的当前工作树存在未提交的旧方案修改，故没有就地强制拉取；已创建独立、干净的最新基线工作树用于本次评估。后续实现从这些最新 `develop` 引用创建新分支，旧 OD08 修改只作为需求和测试案例参考，不能直接移植。

新版主干已经用下列能力替换了旧 `output-delivery` 模块：

| 已有能力 | 当前位置 | 本轮处理 |
| --- | --- | --- |
| 私有、内容寻址的文件存储；默认关闭 | API `AgentTaskArtifactStorage` | 启用前做权限、容量、备份与真实读写验证；不启动旧 MinIO/ClamAV 候选 |
| 任务成果的精确版本上传、下载、哈希校验 | `/agent/tasks/{taskId}/artifacts` | 作为悬赏交付件唯一文件协议，补 Agent 侧自动发布和用户读取入口 |
| 原子接受/取代成果 | `artifact-outcomes` | 保留为悬赏验收的权威状态，补“退回修改/新 run”语义及页面闭环 |
| 工作台成果传输与裁决面板 | Web `ArtifactTransferPanel`、`ArtifactOutcomePanel` | 保留组件和协议，不新建第二套下载组件 |

当前缺口是：Agent 工作空间生成的文件没有受控 manifest 和自动上报路径；普通对话没有可下载的交付件入口；悬赏榜未把版本、验收、退回修改和重新执行组织成面向用户的闭环。存储默认关闭也意味着当前线上仍不能交付文件。

## 新的交付顺序

所有任务串行执行。涉及身份、ACL、事务、并发或迁移的任务由 `critical_worker` 实现并由独立只读审查人复核；其他 API/Web 任务按 `MODEL_ROUTING.yaml` 路由。每一任务先有冻结 commit、相关真实测试和交接记录，才进入下一任务。

| 阶段 | 目标与交付物 | 关键验收门禁 |
| --- | --- | --- |
| RB00：基线冻结 | 建立 API/Web/isp-install 三仓最新分支；冻结新版 API 契约、现有迁移、当前成果 ACL 与旧 OD 补丁差异 | 三仓均为干净 HEAD；输出 API 删除原因和接口映射；不部署 |

## 设计约束

1. **一个文件协议。** 悬赏与对话复用内容哈希、精确版本和私有存储；不得并行保留旧 `output-delivery` HTTP 协议。
2. **受控工作区导出。** Agent 只能提交 manifest 明确列出的普通文件。manifest 不可引用绝对路径、父目录、符号链接或未声明的路径；快照时必须复核 inode、长度和 hash。
3. **读取先于扩容。** RB01 未验证前，写入保持关闭，已有读取行为不受新功能影响。首期单文件限制沿用现有 16 MiB；超过上限的归档/大文件作为后续独立对象存储升级，不以降低检查标准换取上线。
4. **冻结版本验收。** 只能接受服务端记录的确切 `artifactId + artifactVersion + hash`；返工必须产生新 run 和新版本，不能复写历史成果。
5. **最小改动迁移。** 新增 conversation deliverable 的表和索引；不重建或回填没有归属证据的历史成果。迁移须检查列、索引、外键和 trigger 漂移。

## 最新交付规范的执行方式

本计划采用当前仓库的 SDD 和 M1 发布规则：子仓独立提交、推送后才更新根仓 gitlink；每个 Gradle 命令持有 `/tmp/cyf-gradle.lock`；P0 修改须独立只读复审。RB08 还必须执行最新发布 runbook 的 fail-closed 流程：先检查每个写入文件系统容量，使用精确、干净的锁定工作树构建不可变制品，维护窗口停写与备份后再迁移，最后核验流水线实际 SHA、部署单、运行版本及线上下载行为。
