# OD09 queued review and rework handoff

Preparation only; OD09 remains not_started until OD08 acceptance. One product writer, API then client serially, each frozen for independent review. Consume the accepted OD08 delivery transaction and the existing review/rework OpenAPI contracts; do not begin against the intermediate OD07 tree.

Owner review locks and validates the exact current batch/task versions before writing one final decision. Accept completes the submitted work item and task through the authoritative guarded transition. Request_changes requires a nonblank reason, preserves the old immutable batch/items/pins, clears current submission/lease fields and returns the work item to ready. End the old run and prevent it claiming again. Write review, state/version changes, events and exact receipt in the shared transaction; an injected late failure must roll back every write. Preserve policy0 behavior and unsupported policy1+funded rejection.

Rework is a separate explicit owner action after CHANGES_REQUESTED, never a review side effect. Validate the selected batch/task version, existing execution attempt cap and at most three total review revisions including the initial revision. One transaction creates the new durable command/run and binds dispatched_run_id to the same required work item. Concurrent requests may queue only one new execution. Replays recover that command receipt; they do not create a further run or reset attempts.

Command identity integration needs particular care: AgentCommandCanonicalCodec.taskInviteCommandId is deterministic over scope/task/Agent/type, with no revision dimension. Reusing it for rework would collide with the first command and recover the old run. Reuse the existing supported command/intent machinery with a stable new business intent bound to the authorized rework; verify the actual outbox wire. AgentCommandReissueServiceImpl resends an existing command for transport recovery and is not by itself a new reviewed execution. AgentCommandTransportWriterImpl.prepareHallOutputContext currently creates policy0 contexts: any reused path must explicitly carry authoritative policy1/work-item/run facts and cannot silently downgrade. These source pointers are preparation observations; the final integration design is reviewed with the implementation.

Client handling of the new command must use its new run/lease and export directory, preserving old snapshots and published versions. Do not reuse the previous completed command, leaseToken or pending submit intent. Registration remains truthful about complete R2 support. Heartbeat/submit serialization from OD07/OD08 continues to apply.

Target real MySQL tests for concurrent accept/request_changes, repeat same-key/different-body, stale batch/task versions, unauthorized owner, injected rollback, old-run claim after changes, duplicate rework and command/run identity, max revisions/attempt exhaustion and funded policy0 compatibility. Positive rework must consume a real OD08 submission rather than only seeded delivery rows. Archive commands/raw reports and source associations before independent review; exact browser owner actions follow in OD10/OD11.
