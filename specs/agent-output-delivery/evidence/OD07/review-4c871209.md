## P1-1 policy1 can fall back to the legacy Agent dispatch without trusted run/workItem context

`AgentCommandTransportCapture.prepareTaskOutputDispatch` returns empty contexts whenever compatibility is disabled, command outbox is disabled, or the run service is absent (`agent/jia-agent-service/src/main/java/cn/jia/agent/service/impl/AgentCommandTransportCapture.java:106-113`). All checked starter profiles currently set `agent.command-outbox.enabled=false` (`starter/src/main/resources/application-dev.properties:211`, `application-prod.properties:209`, `application-grey.properties:226`). Even with outbox enabled, policy1 creates the run and binds `dispatched_run_id` at `AgentCommandTransportCapture.java:145-158`, but capture returns only `gate.allowsDispatch(...)` (`:173-231`); DB_SHADOW/MQ_SHADOW/unscoped states therefore return false (`AgentRabbitSafetyGate.java:75-77`, writer admission `AgentCommandTransportWriterImpl.java:311-319`). `AgentServiceImpl` passes this boolean through (`AgentServiceImpl.java:1044-1074`), and after commit a false value calls the legacy `dispatchTaskAssignedActions` (`:2270-2278`), whose `AgentActionIntentDTO` has task metadata only and no outputContext/workItemId/lease requirement (`:2497-2547`); its acceptance text tells the Agent to use old `work.result` (`:2550-2564`). Thus a policy1 task can persist member/workItem/run and start execution through an untrusted legacy command, while policy1 legacy-result guards later reject completion. This violates OD07 and O22/O24/O31 and can strand paid work after execution. Fix must fail policy1 assignment before row mutation unless a trusted dispatch-capable path is available, and must never invoke legacy dispatch for policy1.

## P1-2 release/expiry requeues the item but no product path can create/bind and dispatch a replacement run

Release increments attempt and sets READY then calls `clearLease` (`AgentWorkItemLeaseServiceImpl.java:274-287`); expiry does the same (`:371-407`). `clearLease` clears assignee, executionRunId, and dispatchedRunId (`:777-783`). Repository-wide, the only production call to `bindDispatchedRun` is initial assignment in `AgentCommandTransportCapture.java:153-156`; `prepareTaskOutputDispatch` is only called from initial assignment (`AgentServiceImpl.java:1044-1051`). Recalling assign with existing member/workItem rows takes the idempotent branch (`AgentLegacyTaskCompatibilityService.java:221-234`), whose validator requires a non-null exact assignee and `attemptCount == 0` (`:395-447`, especially `:430--439`). After release/expiry those are null and 1+, so reassignment fails and no new run/command is produced. This violates O16 and OD07’s assign/lease responsibility: the item becomes READY in storage but is not executable. Add an explicit transactional re-dispatch path for READY requeued policy1 work: select/lock target, create a fresh run, bind dispatched_run_id and assignee with version CAS, emit trusted command after commit; prove release/expiry -> new run -> claim and stale old-run rejection.

## P2 lease lifetime can extend beyond the run’s 24h hard recovery deadline

A run fixes `recoveryUntil = createdAt + RUN_RECOVERY_MILLIS` (`OutputRunAuthorizationServiceImpl.java:143-163`; constant is 86,400,000 ms in `agent/jia-agent-core/src/main/java/cn/jia/agent/output/OutputConstants.java:34`). Claim sets `leaseUntil = now + duration` without capping it to run recoveryUntil (`AgentWorkItemLeaseServiceImpl.java:191-228`, specifically `:215-222`). Heartbeat caps only at `now + maxLeaseDurationMillis`, again without run deadline (`:254-271`). The HTTP adapter mutates first and only checks `current.recoveryUntil() >= now`, not `response.leaseUntil <= recoveryUntil` (`agent/jia-agent-service/src/main/java/cn/jia/agent/output/service/OutputLeaseServiceImpl.java:130-155`). A valid request just before recovery expiry can therefore return a lease extending up to 900000 ms beyond the run; after recovery expiry further heartbeat/release is unauthorized until the expiry scanner repairs it. Cap claim and heartbeat to recoveryUntil or reject any requested lease that would cross it, and add boundary tests.
