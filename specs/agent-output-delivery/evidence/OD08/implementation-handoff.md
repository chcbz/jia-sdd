Submission is one authoritative transaction: authenticated current task/source root and run → exact request receipt → current single required work item/lease/version → immutable batch/items/manifest → DELIVERY_PIN or inline equivalent authorization → submitted work item and task currentDeliveryId/revision/version → events, RESULT_SUBMITTED run state and receipt. Borrow an already locked root only under its verified transaction contract; do not construct a fake root to bypass locking/policy. Inject failures after intermediate writes and prove all database changes roll back under the actual shared transaction manager.

Required data checks: canonical expected task/work-item versions; active leaseToken/until and matching execution/dispatched run; each exact immutable artifact version belongs to the task/source and is authorized for this producer to deliver. Object-backed items must be READY, verified and protected against concurrent GC. Never resolve latest, accept an objectId as authority, or require preexisting OWNER_SHARE: ROLE_CANDIDATE stays private until the submission creates delivery authorization atomically. Preserve private artifacts of other producers/reviewers.

Text mode requires a real nonempty inline conclusion; files mode requires the configured downloadable items; mixed requires both. A plain completed report is not a formal result. Client text handling must connect a real published inline artifact to the batch rather than manufacturing a meaningless file to satisfy the form. Stop and await in-flight heartbeat before reading the final version for submit; preserve stable request/key in durable storage. The publication queue's success is not itself task acceptance.

Response-loss recovery: after committed submit, terminal run tickets may only recover the exact persisted receipt under authenticated run/body/key identity. They must not gain fresh lease/publish/submit authority. A replay returns the original batch even if subsequent review advanced current task state; same key with changed body conflicts. Keep leaseTokens/tickets out of prompts, logs, UI and ordinary user responses.

Freeze reviewed API and client changes serially. Target actual MySQL cases for multi-item partial failure, scope/producer/version mismatch, expired/old-run lease, concurrent reassignment/submit, pin/GC race, injected rollback, duplicate same-key/different-body and committed-submit lost response.
