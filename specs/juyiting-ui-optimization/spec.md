# 聚义厅界面细节优化

## Problem

聚义厅的“办事概览”工作台已经具备桌面侧栏、移动底部导航、事项详情、草稿、招贤令、典籍阁、消息与地图等完整入口，但浏览器巡检发现移动端导航层级和视觉规范仍不一致：

1. 软键盘打开后，移动底部导航仍固定占用约 62px，压缩输入区域。
2. 事项详情及非主导航弹层仍可能显示底部导航；招贤令、提出需求等竖屏页面会同时出现返回、关闭与底部导航。
3. 工作台白色体系、历史羊皮纸体系和地图深色体系之间缺少明确边界，同一工作台页面内存在不同的纸色、边框、文字色和控件圆角。
4. 概览、事项、宝库、资料库、草稿和案卷使用多套 Tab/筛选样式，移动端工具栏密度、左右边线和点击尺寸也不统一。

## Goals

- 建立聚义厅移动端导航状态机：仅在四个一级工作台页面显示底部导航。
- 软键盘打开且编辑控件获得焦点时隐藏底部导航，关闭键盘后恢复。
- 竖屏详情页统一使用单一“返回”动作；根级弹层只显示关闭，不与返回重复。
- 为聚义厅工作台建立共享语义设计变量，统一浅色页面、卡片、文字、边框、品牌色、状态色、圆角、间距和焦点环。
- 统一一级 Tab、筛选 Chip、详情子 Tab 三类交互样式。
- 改善 390×844、320×740 和键盘缩短视口下的对齐、密度、滚动和安全区行为。
- 保留沉浸地图的深色主题，不改变现有聚义厅业务数据流和功能入口。

## Non-goals

- 不修改聚义厅后端 API、数据库、鉴权、任务状态机或消息协议。
- 不重绘地图、人物、遮挡素材或水浒人物画像。
- 不重构事项、草稿、资料库、招贤令等业务逻辑。
- 不修改聚义厅以外的页面。
- 不在本次工作中改变桌面端主信息架构或小程序原生横竖屏桥接协议。

## Scope

- API：无代码变更，仅固定当前 `api` revision 作为集成基线。
- Web：
  - `src/components/world/JuyiHall.vue`
  - `src/composables/juyiting/useHallExperienceMode.js`
  - 聚义厅浅色工作台相关组件样式
  - 聚义厅导航、体验模式和组件契约测试
- Documentation：本目录 SDD 文档及 `docs/juyiting-runbook.md` 的稳定约束补充。

## Constraints and risks

- 地图 Agent 与名册 Agent 数据流必须继续分离，不得重新引入 `/agent/active`。
- 任务指派仍须显式传入目标 Agent。
- 软键盘不能只依据视口高度判断，否则横屏和短屏会被误判；必须同时要求可编辑控件处于焦点状态。
- `visualViewport` 在部分 WebView 中不可用，需保留 `window.innerHeight` 回退且不得影响页面挂载。
- 面板关闭、返回和草稿未保存保护必须保持现有行为。
- 案卷阅读器的安全区和小程序胶囊避让规则不得回退。
