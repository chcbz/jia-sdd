## 1. 结论与建议方向

建议采用：**品牌保留水浒特色，办事流程使用日常中文，安全与费用说明准确、就近、按需展开。**

目前不是“文案不够活泼”，而是同一条办事主线上混用了文化隐喻、产品术语和工程排障语言。优先解决：

1. 同一入口多名：资料／百宝箱／工作空间，好汉名册／点将册，事项／榜文／任务。
2. 日常操作不直白：话头、传令、候回话、以原键重放，需要先学习世界观或技术概念。
3. 风险说明不完整或不易理解：仅自己可见、免费联想、他人好汉接收资料、安装费用与执行费用。
4. 正常页面过度解释实现约束：不伪造、不猜测、不制造文件资产等，是研发原则，不适合长期对用户广播。
5. 部分跳转与能力描述仍可能误导：消息实际上是待办列表；搜索框只说查榜号；个别议事成果分支提示下载，但议事预览已决定不提供下载。

**不建议**全面去掉“好汉、议事、典籍”，也不建议为内测另建大段欢迎页、重复确认、强制导览或统一文案框架。

### 3.2 写作规则

- 标题讲用途，按钮讲动作，确认窗口讲后果，错误讲“发生什么＋下一步”。
- 正常反馈不用“不伪造／绝不推断／服务端原子核验”等研发自证语言；异常可展开技术详情，原错误码与恢复标识保留。
- 一处只讲本次动作。不在每页重复整个权限体系；**首次将资料交给承办者、费用确认等关键动作仍须就近说明**。
- 不把“未确认”写成“失败”，不把“已提交”写成“已经运行”，不把“有成果”写成“已验收”。
- 少用泛泛的“请重试”。读操作用“重新加载／查询结果”；允许恢复写入时用“继续原操作”；确认可重试失败才用“重试原操作”。
- 版本默认写“版本2”，空间不足可用“v2”；编号放技术详情。没有名称的真实兜底可保留编号，不凭空起名称。
- title、aria-label、可见按钮同一语义；不只替换看得到的文字。

### 建议验收场景（按变更命中裁剪，不强制重跑无关链路）

| 场景 | 文案验收点 |
|---|---|

| 单项／多选／历史版本／旧整批验收 | 集合和完成后果清晰；打开或关闭不验收 |
| 已完成但记录缺失 | 不推断已验收版本；重试后仍以原权威记录为准 |
| 上传／承办／购买／验收结果未知 | 查询、恢复和新建不混淆，不重复生成或购买 |
| 私聊／公共议事／正式事项 | 范围说明符合各自真实权限；切换身份不显示上一个人的资料 |
| 取消事项／放弃未交付轮次／归档／回收站 | 四种动作后果各自明确，不混称取消，不承诺自动退款 |
| 语音输入与自动发送 | 用户知道转写是否会发出、替换何处，停止等待不等于撤回 |
| 我的／消息／技能／维护 | 不宣传不存在的设置，待办不伪装完整通知，管理权限不靠文字隔离 |
