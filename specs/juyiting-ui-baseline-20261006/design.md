# 界面基准设计与维护约定

## 固定入口

本目录 `prototype/index.html` 是 **2026-10-06 当前源码候选的界面优化对照入口**；10 月 4 日的 `current/`、`adjusted/` 和 9 月 V4 原型保留历史，不覆盖。源码候选不等于已上线；精确 binding 见 `prototype/baseline-source.json`。

## 最新议事约束

1. 公议、密议、榜文议事不再显示 `discussion-brief`，保留真正的任务状态、终止与恢复入口。
2. 输入框外边界内包含文本区、“＋”、语音和发送。
3. 重取回话、话头记录、另起话头放在上部 toolbar。
4. 输入区不出现“工作空间”按钮；“添加资料”和“语音设置”由“＋”展开。
5. 语音设置展示当前 draft-only 的“语音回答”和 AI 语音告知，不发明识别语言、自动发送等新设置；转写只演示放入可编辑草稿，不自动发送。
6. 成果预览/下载/保存放在成果或消息中，验收只从事项详情进入，不为资料保存增加验收前提。

## 还原层级（不能混用）

- **历史 DOM 还原**：主要外壳、办事、事项、创建、点将、详情和资料列表复用 2026-10-04 的脱敏实际页面 DOM 与公开样式，并叠加本次明确的最新界面调整。不是对所有组件重新采样的 10 月 6 日线上截图。
- **最新源码对齐**：议事布局按已合入 develop 的 `446cfbe` 改动校对，冻结的当前源码候选为 `fe6d4d5`。五份相关组件的 scoped CSS 保存在 `source-ui.css`，源文件摘要可核对。
- **补充结构原型**：典籍、消息、资料管理、招贤令、静态地图等缺失页，以当前源码的字段和入口组织代表性示例状态。其内容不是线上采样或逐像素承诺；后续做这些区域的精细视觉优化时，应先补当前组件截图，再更新本基准。
- **明确外部边界**：个人中心只冻结跳转入口，不伪造账号模块；地图只引用项目实际美术及入口，不模拟 melonJS、坐标和遮挡。

## 离线与隐私

资源均在本目录，CSP `connect-src 'none'`，不导入生产应用 JS、不读取用户身份、不连接业务服务。所有文件、Agent、任务和会话均为演示。图片为已有示意插画，音频为示意音。下载只提供示例文件；验收、删除、重命名、回收、书签仅改变离线演示状态。

## 后续优化怎么用

1. 先从 `coverage.md` 选择原型页及状态，并记录 Web commit、viewport 和差异点。
2. 只修改用户要求的范围，明确哪些是布局变化、哪些需要业务合同变化；原型不能暗中授权后者。
3. 在新 revision 中同步改原型、覆盖表和来源摘要；本版本的修订前证据不删除、不伪改为新 PASS。
4. 原型 DOM 检查不是生产测试。真正 Web 改动仍走项目既有 Flow 门禁；docs-only 更新不启动生产构建。
5. 以实际源码为业务事实，以上线 Run/制品为发布事实；不得用原型模拟成功作为上线验收。
