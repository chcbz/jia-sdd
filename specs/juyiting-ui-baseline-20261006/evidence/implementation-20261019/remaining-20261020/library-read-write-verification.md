## 缺陷与修复顺序
1. **P0 账号过滤无效**：`MemoryRepositoryImpl.searchWithConversationBoost/search`将身份条件放在顶层query而KNN无内置filter；生产mapping的jiacn本身是keyword，现用jiacn.keyword不存在。按当前请求实际命中错误scope目标；仅把过滤改到KNN内部、使用jiacn字段的只读对照返回0。修复须覆盖所有检索入口、现有身份权限边界及双账号回归，不只改字段名。
2. **P1 Embedding 404后伪成功**：真实日志NotFoundException404；存储1024维向量与现有Java hash/Random降级算法按float32逐值一致。应先核对真实Embedding端点/模型/1024维契约，再移除伪向量成功降级；失败明确返回业务错误，不继续污染索引。既有向量需盘点来源，只重建授权范围，不能直接删知识库或混用模型。
3. **P1 错误被当作空结果**：`ChatController.searchLibrary`捕获异常返回E0/空数组；前端已有失败提示但收不到错误。应遵守统一接口规范返回明确失败，由页面区分“服务异常”和“没有匹配”。本次不为重现此分支再次停止生产ES，该项为代码核对。
4. **P2 写入/引用标识不完整**：当前Web源码没有/library/documents调用；写接口返回值无文档ID，ES自动ID也未回填，读回id为null，前端临时用conversationId兜底。应在既有需求边界确认内容录入入口及稳定引用ID契约；本次只证实接口可写和摘录可入草稿，不宣称用户端管理闭环完整。
