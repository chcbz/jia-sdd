# 单租户租户键归一与角色/个人数据隔离

## 背景

当前历史实现把登录用户 `jiacn` 同时作为 `tenant_id` 与个人所有者。该模型允许同一 `client_id` 下不同用户重复绑定同一个梁山角色，且阻止将全库 `tenant_id` 归一为 `0`。

## 目标

1. 当前部署只有一个租户：所有持久表的业务 `tenant_id` 最终归一为字面值 `0`。
2. Agent 角色的活跃绑定唯一键为 `(tenant_id, client_id, active_persona_code)`；同租户同客户端只能有一个活跃角色绑定。
3. 单租户不等于共享用户数据。用户资料、典籍阅读数据、书签、手札、聊天和任务仍必须以认证用户为 owner 隔离，不能以 `tenant_id` 作为个人授权键。
4. 对已发现的重复“卢俊义”，由受控迁移运行时输入指定保留 owner；另一条绑定退役。恰好两条实时已分配任务的**执行 Agent 引用**迁至保留 Agent；任务 owner 不迁移，历史事件不改写。
5. 保留 owner 仅作为运行时密参，禁止写入仓库、日志、测试夹具或接口响应。

## 非目标

- 不新增租户，不改变 OAuth 客户端边界。
- 不将 `owner_jiacn` 返回到非所有者客户端。
- 不重写历史事件的 actor；只追加明确的迁移审计事件。
- 不以性能预算、磁盘余量或任意等待阈值拒绝迁移。

## 约束

- 不引入旧 tenant 格式的读写兼容分支。迁移在维护窗口完成，严格版本只读取 `tenant_id='0'`。
- 每一步都以生产快照、精确行数和哈希作为依据；预期发生变化的两个实时任务来自本次用户确认。若执行时不是恰好两条，停止而不猜测。
- 不能以确定 owner 且不能验证父子归属的历史记录，允许按本次用户授权删除；删除必须先入快照、按精确主键范围执行并读回验证，不得借此删除可迁移数据。
- 生产 DDL/DML 仅在用户已授权的本次单租户迁移窗口执行；失败保留快照与精确错误，不盲目重试。
- 仓库中不保留可直接执行的生产 Phase B DML。执行脚本只可在生产盘点完成后，由受控运行环境以密参生成并执行。
