# 聚义厅 Agent 模型、接单与可交付技能治理 R1

> 文档收口（2026-10-23）：保留模型/价格簿/技能治理未交付目标；旧外部邀请规则的同范围实现以接外单D3.1为准。 本轮仅核对文档归属与覆盖，不重新验证源码/上线；执行规则以根AGENTS为准。


更新日期：2026-09-18。状态：`ready`。本规格冻结下一功能列车的业务合同和拆分；**不代表已实施、已发布或已获得用户验收**。

## 1. 问题与机会

聚义厅已能展示 Agent、能力标签和悬赏任务，但用户无法可靠回答四个基础问题：

1. 角色此刻使用/最近可信使用的是什么模型，信息来自哪里？
2. “智力值”为什么是这个值，它和模型费用的关系是什么？
3. 在揭榜前，指定 Agent 的模型路由大致会产生多少费用，预估是否会扣款？
4. 一个 Agent 是否愿意接非 owner 发起的任务；它已确认能交付哪些成果？

现有自由文本 `abilities` 适合运行时推荐，却不能证明交付、授权、安装、收费资格或模型账单。资金化悬赏的既有报价合同又是独立、冻结的经济域，不能因展示需求被悄然改造成真实结算。

## 2. 目标

### G1 — 模型与计费智力值可解释

在 Agent 名册/详情中展示可安全公开的模型标识、模型/路由版本、可信来源、观察时间和价目表版本；基于版本化参考价格簿计算**计费智力值**。该分数只是“按标准工作负载费用归一化的产品展示分”，不代表真实能力、可靠性、安全等级、权限或任务胜任度。

### G2 — 揭榜前可得到无副作用的模型费用预估

任务发布者在显式选择 `agentId` 后，可按服务器解析的目标 Agent 模型路由、不可变参考价目表及任务 token 预算取得预估/最坏费用。预估不创建报价、订单、托管、冻结或扣款；没有权威用量凭证时不得显示“实际费用”。

### G3 — 接单范围默认收敛到 owner

Agent 的当前 canonical owner 可管理接单策略。默认 `OWNER_ONLY`：只接受该 owner 发起且现有 ACL 允许的任务。只有 owner 显式开启 `EXTERNAL_OPT_IN` 后，外部任务发布者才能对已知、精确的 Agent 发起同 tenant/client 内的邀请；仍须通过任务 ACL、canonical binding、显式目标和 Agent 侧接受，不能形成公开市场或自动认领。

### G4 — 建立可复核的可交付技能档案

将运行时能力、已确认可交付技能和任务推导候选技能分开。只从已接受且可归因的任务成果的结构化元数据，以确定性规则生成候选；当前 Agent owner 审阅确认、编辑或驳回后，才可公开为可交付技能。

## 3. 范围

- Agent 模型声明/受管运行时观测、路由事实、版本化参考价目表、计费智力值和展示文案。
- 悬赏详情的无副作用模型费用估算 RPC；预估与真实费用的明确边界。
- Agent 接单策略、owner/binding 变更失效、外部精准邀请/接受以及审计。
- 可交付技能 taxonomy、候选生成、确认/驳回/撤销、可见性与证据摘要。
- API、Web、迁移、事件、兼容、测试与发布边界设计。

## 4. 非目标

- 不调用模型 Provider，不读取或展示 API Key、Provider 账户、prompt、推理过程、私有任务正文或私有成果。
- 不进行真实扣款、资金冻结、托管、报价落库、订单、发票、退款、结算或价格同步；本版本的费用均为 `ESTIMATE_ONLY`。
- 不修改 `specs/agent-economy-marketplace/` 的冻结生产合同和 `bundle.sha256`，也不把其中 synthetic preview 价格伪称为 Provider 实际价格。
- 不建立公开 Agent 市场、外部 Agent 搜索/推荐、跨 tenant/client 接单、自动认领、自动派单或外部任务自动开始执行。
- 不让 runtime ability、模型名称、费用、计费智力值、候选技能或 confirmed skill 成为 ACL、身份、安装、付费、商业承诺或高风险操作授权。
- 不改变聚义厅地图 `/agent/map`、名册 `/agent/roster` 的分流；不恢复 `/agent/active`；所有任务分配仍须显式携带目标 `agentId`。

## 5. 产品原则与成功判定

1. **先说明事实源，再展示结论。** 无可信模型、价目表或用量凭证时显示未知，绝不补零或猜测。
2. **费用与能力不混同。** UI 固定说明计费智力值仅来自费用归一化，不能以高价/高分暗示“更强”或“可接单”。
3. **默认拒绝外单，服务端强制。** 隐藏按钮不能代替 ACL；所有跨 owner 新邀请都由服务端事务校验。
4. **机器只提候选，人确认对外承诺。** 候选规则不消费私密正文，不调用 LLM/Provider，不静默覆盖人工技能档案。
5. **历史可回放、当前可撤销。** 估算、分数、策略和技能均保存其版本/证据；策略关闭不改写历史任务。

本版本完成时，授权用户可解释模型/分数和揭榜预估；未经 opt-in 的外单无法进入可执行状态；用户能审阅任务生成的技能候选。真实收费、Provider 实际用量和公开外部市场仍不算完成。

## 6. 相邻规格与依赖

- `agent-economy-marketplace`：真实报价、资金和结算的冻结经济合同。本规格只能与之只读相邻，不可改变其价格语义。
- `economy-readonly-preview-v1-7`：可复用其 decimal-string、只读/模拟和来源标注原则；模型预估独立于其 `POST /economy/preview/bounty-estimates`。
- `juyiting-task-collaboration`：复用任务 ACL、显式目标、成员状态、CAS/事务和 outbox 约束；不扩大为 M4 的公开协作市场。
- `agent-output-delivery`：已接受且可信的 artifact outcome 是技能候选的可选证据来源；“已分享”本身不等于已接受。
