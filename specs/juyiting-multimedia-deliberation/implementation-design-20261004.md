# 聚义厅多媒体协作：待实施增量详设

2026-10-04。与 [任务清单](tasks.md) 配套；本文件只定义**现有候选到最新需求的差异**。[design.md](design.md) 保留完整产品目标，冲突时以本次更具体的增量合同为准。

**本文件定义最小增量合同；T01–T04已形成源码候选，实时实施/验证状态见 [分版本开发回执](implementation-progress-20261004.md)，不等于已经上线。仍不预设新接口、新表或独立状态机。** 不改页面体系、不重建文件系统、不新建独立图像产品，不把历史已有能力列为从零开发。核对基线 SHA、远端及证据限制见 tasks.md 第1–2节。

## D0. 最新实施约束：简单、够用、快速

1. 用户流程只保留“提需求 → 点将 → 议事修改 → 验收”，资料与保存可选；不增加内部审批、操作模式或技术确认。
2. 优先改现有组件接线和校验；现有功能能用就保留。后端只补影响实际用例的缺口，不先做平台化抽象或大改。
3. 不预设新增交付集合服务、专用 GET 接口、集合版本体系或独立状态机；不新建文件系统、执行引擎、图片服务或历史兼容工程。
4. 功能实现与验证一起推进；不先做全面审计、跑完全部历史测试或写齐证据包再开始。只测本次改动和真实缺陷，复用适用的已有证据。
5. 保留真实权限检查、避免重复执行/扣费、正确验收、用户取消和既有发布要求；不追加性能门槛、数值门禁、Reviewer、逐次批准或重复 CI-only Run。
6. 下面是最小实现路径，不授权新增范围。发现现有结构不能满足某个具体用例时，记录失败用例并做最小补齐，不把假设问题变成工程前置。

## D2. 点将与密议（T02，复用而非重写）

- 创建成功后保留服务端 taskId / task revision / 资料精确引用，跳入现有点将册；不靠卡片显示文字恢复上下文。
- 在点将动作中传明确 targetAgentId，复用 `POST /agent/tasks/{taskId}/point-and-deliberate` 与原键查询。服务端负责唯一会话与首条需求，不由进入页面事件重新派发。
- “与这位好汉密议”沿用独立会话入口，不能调用 point-and-deliberate、伪造正式事项或带出尚未提交的需求资料。
- 返回点将册保留候选和待办；切换好汉密议时历史、草稿、媒体与请求状态按真实会话隔离。身份切换清理旧可见状态。
- 验证 AgentPanel 与父级的显式事件；不混淆 `/agent/map` 与 `/agent/roster`，不恢复 `/agent/active`。

## D3. 附件-only 普通请求（T04，确定合同缺口）

### 已证实差异

Web `HallChatComposer.vue` 的 canSend 要求非空 draft；`hallTypedDeliberation.js::discussionBody` 也拒绝空 content。因此“只补一张图/一个文件并发送”目前在客户端合同上被拒绝，不能只改按钮 disabled。服务端 admission/context 校验必须配套核对修改。

### 拟扩展规则（沿用现有端点/字段）

`POST /chat/conversations/{conversationId}/interactions/discussion` 沿用现有 `schemaVersion: 1`、`intent`、`taskId`、`expectedAssignmentRevision`、父结果/澄清关联及 `sourceSelectors`；不因模型结果采用 v3 改成请求 v3。

| 正文 | 精确资料引用 | 行为 |
|---|---|---|
| 非空 | 空或合法列表 | 保持原行为 |
| 空字符串/仅空白 | 至少一个合法引用 | 允许；原用户正文按实际值持久化，消息显示资料卡，不补造“请处理附件”等用户发言 |
| 空字符串/仅空白 | 空列表 | 沿用请求错误，前端不给发送 |
| 任意 | 越权、未知版本、格式错误引用 | 拒绝对应请求，不偷偷换文件或扩大权限 |

保留当前长度/资料数量合同，不趁本次新增任意门槛。幂等摘要包含真实正文、规范化精确引用及父意图，空正文与不同附件不得撞键。响应继续用现有 accepted 包装；坏参数沿用 INVALID_REQUEST 映射，资料鉴权沿用不泄露存在性的策略。网络结果未知查原请求，不自动换键再次发送。

Agent 读取附件目录后判断按需查阅、澄清还是执行；缺少明确指令可以自然问“希望如何处理这份资料？”，但不能一律要求用户补正文才能入库。用户回答继续原澄清关联。Client 的空正文处理应保持上下文不丢，不凭空赋予执行或付费权限。

最小新增用例：双空拒绝、合法附件无正文可发。沿用现有权限、重放和澄清测试；仅在本次改变其行为时补对应回归，不为这个小改动新建独立测试体系。

## D4. 正确展示本次成果，复用现有验收（T05）

### 已有与缺口

现有 finalization 接口接收 `selectedOutputs`，包含 requestId / stepId / outputId / sha256 / title / purpose；服务端已校验产物归属、真实字节并完成正式交付。**取消用户多选，不等于必须重做这个接口。**

已有实现能处理的成果直接复用。需要补的是：页面知道本次交付哪些内容、改稿不丢其他成果，以及纯文字如何接入正式交付。先检查已有结果元数据/引用是否足够；缺哪一项补哪一项，不将完整清单管理系统列为前置。

### 最短实现路径

1. **成果列表复用**：从现有持久会话结果/任务详情读取本次明确交付的成果引用，展示只读清单。仅展示层隐藏复选框，不去掉服务端来源校验。
2. **改稿复用**：沿用本次请求对原成果的引用关联，替换被明确修改的项，保留其他成果和历史稿。若缺替换关联，在现有结果元数据补这一关系；不引入通用版本管理。不能把全部历史成果或“每种类型最新一个”当本次清单。
3. **不明确就会话澄清**：多张图时用户说“改成蓝色”，无法判断对象才问是哪张；不新增选成果页面。普通问候/澄清答复不能自动成为交付件。
4. **刷新能恢复**：清单依据服务端已有记录和明确关联重建，而非仅存浏览器。输出就绪/改稿成功后复用原结果刷新机制，不新加一条事件链。
5. **验收复用**：点击“确认验收”时将页面实际展示的精确成果引用映射为现有 `selectedOutputs`，沿用原 task/assignment version、幂等键、状态查询、正式提交和完成逻辑。字段名里的 selected 不代表 UI 必须有多选框。
6. **文本最小补齐**：图片/文件继续原 output 通道；纯文字复用已有完成消息/文本快照存储，作为只读来源接入现有正式交付服务。当前 output-only 解析不能直接声称支持纯文字：只为这一缺口扩展受鉴权的消息来源字段/分支与对应测试，不伪造 executionId/runId，不要求先保存个人空间，不重新生成文字文件。

不预设 `delivery-set` 端点、deliverySetId / expectedDeliverySetRevision、独立状态表或专用冲突码；上一版对此的建议撤销。只有具体用例证明确实无法在现有读写接口和元数据内完成，才在实施中说明原因并做最小调整。

### 正确性底线（沿用现有机制，不增加用户步骤）

- 只验收用户看到并确认的精确内容，不能在提交时偷换成刚到的新稿；收到更新时正常刷新待验收显示，不用新增全局锁来阻塞聊天。
- 现有任务/指派版本冲突或来源失效按原错误处理，保留所见成果供核对；未知响应查询原验收，不重复执行。
- 文本来源校验当前用户、任务/会话、完成消息及快照；原媒体权限和字节校验不能为方便接入而删除。
- 保存与验收互不依赖；已验收内容不被后续改稿覆盖。现有在途操作按原记录恢复，不为历史界面建设双轨功能。

针对本次差异只需补“改一项不丢其他项”和“纯文字直接验收”的用例；涉及来源/事务修改时补受影响的权限及幂等回归，不新建全量并发/容灾验收工程。

## D5. 无多选的验收页（T06）

- 事项详情 → 原有“查看正式成果与验收” → D4 当前清单；显示成果卡及预览/下载，无 checkbox、调整交付按钮或折叠后的隐藏选择器。
- 主动作“确认验收”、次动作“继续修改”。继续修改只回原会话，保留清单；用户说明后由 Agent 更新，不直接改已生成文件。
- 没有可交付成果时显示实际处理状态/返回议事，不展示可点击的假验收。处理进度和完成状态沿用现有 finalization；未知响应查原 operation，不新增状态机。
- 验收不要求先保存；可选保存失败不回退验收，验收失败不重跑工具。完成后成果仍可预览、下载、保存；已验收集合不可被后续事件改写。
- 图文音频混合及跨轮修改必须保留正确集合；“自动选中当前全部卡片”不合格。

## D6. 边做边验证已有能力（T07–T08）

T07/T08 是联调过程中顺带核对的范围，不是两个独立的验证项目，更不是动手前的门禁。

- 用当前实际可用的 Agent 接入完成一次主流程：不加资料提出画鸟需求，自动议事、看到真实结果、修改、预览下载、可选保存、验收。
- 同一轮补资料混选/只发附件，查看音频播放和文档预览或下载；不要求每种媒体都有专门的生成模型，也不遍历格式矩阵。
- 刷新后检查已有消息、结果和保存记录仍可读，重复操作沿用现有去重；不为本次 UI 改动另外搭故障注入环境。
- 保留密议与账号作用域隔离。改到身份/来源/事务时运行相关回归；否则复用已有有效测试，不重做整个权限体系的审计。
- 山寨安顿/自家接应共用合同，不改接入架构。只改 Web 不要求所有部署形态各跑一遍；改到 Client 适配路径则检查对应路径，未实测形态不声称已验收。

失败仅修影响当前功能的明确问题。没有触及的历史统计、资金、平台运维问题另列，不以假设风险阻塞主线。图片必须是真实 Agent 输出，不能拿原型 SVG 充数；继续使用现有能力，不凭模型名称引入新图片服务器/付费服务。

## D7. 最小验收与发布

| 检查 | 最少应看到什么 | 执行方式 |
|---|---|---|
| 主流程 | 无资料提需求→点将→真实成果→同会话改稿→预览下载→可不保存直接验收 | 一次真实业务闭环，覆盖 T01–T07；不逐任务再跑一遍 |
| 资料/保存 | 混选资料、只发附件；相关媒体可查看，保存后空间可重新打开 | 接着主流程检查；未知格式可下载，不扩展新解析器 |
| 文字/多成果 | 纯文字可验收；修改一个成果不丢其他成果，刷新仍一致 | 各一个代表用例；不要求遍历所有媒体组合 |
| 易用性 | 密议入口保留；＋可用；桌面和一个实际手机窄屏不遮挡 | 复用原型/组件证据，只复测实际 UI 差异；有问题再加对应尺寸 |
| 改动回归 | 附件双空校验、明确替换、文本来源；涉及权限/事务的相关用例 | 选相关既有测试补缺口，不强制新建整套测试或重跑所有历史验证 |
| 发布事实 | 改动组件正式云测/构建、同Run制品、真实运行版本与上线后主流程 | 复用既有 Flow 与发布健康检查；不额外加 CI-only、人工审批或第二条验证流水线 |

本表是完成核对，不引入新 gate 系统。已有云端正式测试与实际健康要求继续遵守；每个改动组件在本次正式发布 Run 内验证，不因不相关组件未重新构建而阻塞。未改变且适用的测试/制品证据复用，不能把旧证据冒充新源码通过。

不添加任意超时、包大小/资源阈值、百分比覆盖率或“全部历史测试/双接入全格式全故障通过才可开始”的前置。真实测试失败、错误内容/权限泄露、源码制品不匹配等实际问题仍需处理，不能为求快伪报完成。

接手时只读确认现有 Run/操作归属，不抢占；普通已授权发布无需反复确认。本次只改文档，不调用 Provider、构建或流水线，也不恢复暂停的业务开发。
