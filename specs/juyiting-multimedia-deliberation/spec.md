## 1. 问题与目标

用户希望从“画一只鸟”等自然语言需求出发，在同一悬赏议事中完成参考资料选择、Agent 澄清/执行、图片/音频/文件展示、多轮修改、主动保存和最终验收。现有空间和正式交付能力应复用，不能把 Agent 返回的本机路径当成可领取成果。

前期浏览器测试的事项 414 只收到本机路径，图片无法加载、下载出现重定向循环；这仅是历史失败现象，不证明唯一根因，也不是本次新测试结果。前期源码/本机配置观察整理在 `current-state.md`，产品设计不能替代当前部署核验。

**方案：会话优先、产物先持久化、个人归档可选、精确成果验收。** 保留山寨安顿（server）和自家接应（local），不改变每个 Agent 的独立工作目录，不建设第三套文件系统。

## 2. 用户主流程

1. 用自然语言提需求，通过唯一“添加资料（可选）”从工作空间混选图片、文档、音频等精确版本；也可以不选。画鸟仅为其中一个验收案例。
2. 显式选择目标 Agent 并点将；服务端自动创建/复用对应“悬赏议事”，投递需求原文和精确资料版本，前端自动进入会话。
3. Agent 在信息充分时直接答复或调用已授权能力生成；确有缺失条件时在原会话澄清。不固定增加“开始生成”按钮。
4. 会话持续显示文字、执行状态、图片、音频和其他文件。服务端验证媒体字节就绪后无需刷新即显示，可预览/播放、下载。
5. 用户继续补充文字、选择空间资料或引用上一稿修改；保持同一悬赏会话，不要求先保存试稿或重新点将。
6. 用户可将选定文字片段、图片、音频、文件保存到工作空间；不满意试稿不自动填满空间。
7. 用户选择精确最终成果并验收；服务端正式提交、记录验收并完成需求。保存空间不是验收前置条件。

## 4. 产品与技术边界

- “一份内容、三种用途”：会话、个人文件、正式成果共享可追溯内容身份；不承诺跨用户或跨物理根目录只存一份字节。现有正式交付允许复制字节，但须摘要一致。
- 会话已就绪输出不依赖 Agent 在线，未个人归档也必须持久保管；不设置未经确认的临时过期删除时间。
- 文本输出、文件生成、个人归档、正式提交、验收、任务完成是不同事实；不能互相替代。
- 多媒体展示至少包含音频播放/保存/下载；不承诺任意 Agent 都具备音频生成、语音识别或视频生成能力。
- 兼容老消息、现有 PRIVATE/TASK 执行与正式交付。不偷偷改变旧 OUTPUT_COMMITTED 的语义。
- 不做共享挂载、全盘扫描/同步、对象存储替换、历史文件搬迁、在线绘图/Office 编辑器、实时语音通话或全局聊天重构。
- 不扩展本次产品之外的治理、交易或技能市场范围；不沿用历史 1.10–1.13 排期作为新版本承诺。

## 5. 与 fast-deliberation 分支的关系

复用其 request/turn/outbox/snapshot/event，避免第二套会话持久化。该分支当前有冲突和 F1 身份、F2 能力协商、F3 冷上下文、F4 INSPECT 声明问题，需原开发修正后集成。修正后的基础是完整联调依赖，不阻止契约设计、Web mock 与独立媒体存储工作并行。

分支合入不会自动完成本需求。新增内容块、会话产物、受控执行桥接、主动归档与精确验收仍须开发。只读 CHAT 不能直接放开任意执行工具；模型执行意图须经服务端校验后转到既有执行链路。

## 6. 影响与完成标准

影响三个运行组件（API、Web、Agent Client）和一个 SDD 协调仓；属于中等偏大的跨端功能，不是小页面修改，也不是全平台存储改造。关键风险在 ACL、事务/幂等、异步恢复与正式交付衔接。

完整完成要求 `acceptance.md` 全范围通过；先交图片纵向切片，但不能据此宣称音频、文本选区和双接应方式已验收。必须经真实浏览器→平台→目标 Agent→平台产物回传完成证据链，开发助手直接生图不算。
