## 2. 从 feature 到已发布版本（每版执行）

1. 仓库组件 Owner 在各自隔离 worktree 自检，并补相关单元/服务/迁移/安全/浏览器回归及证据；Gradle仅通过 `/home/isp/wsps/cyf/ops/orchestration/cyf_orchestrator.py gradle` 串行。没有独立Reviewer，责任 Owner 自检；对失败归因后修复而非盲重试。
2. 确认 API/Web/Client 与 SDD exact commit/tree 和 wire/schema/运行目录匹配、线上当前版本和已有在途发布。合入各组件 `develop` 并推送readback，不把脏主工作区/未完U1功能带入。Agent Client 源版必须有安装/能力回读与 server/local 正向证据。
3. 当前本地例外下执行相关测试+生产构建，冻结同SHA独立 `release/<version>`，记 `build_origin=local_user_authorized`、源码tree、测试、制品SHA-256、联调/迁移策略；若走云效则记录实际 Flow Run、相同Run制品及发布事实，不能两套证据互换。
4. 经发布互斥/进程归属/授权检查，先API实际健康和兼容再Client接应能力readback，再Web静态切换与在线媒体ACL/结果查询；保留可恢复安装与旧服务兼容，不取消其他线程的进程或Flow Run。安装和真实数据库变更需核对授权边界；未授权生产数据DML/扣费不做。
5. 产品验收与“发布健康”分开：冻结测试账号/Agent版本、任务/会话/请求/执行/run/part/asset/file/delivery/decision ID 和真实图片字节/MIME/hash；检查浏览器预览、下载、二次修改和正式验收阶段。失败逐项注明原因与下一步修复，不能用HTTP 200或模拟数据代替。
6. **仅当目标版本实际在线并且对应验收流程可运行**时通知用户：说明版本号、访问入口、准确的画鸟步骤及可选参考图测试、已通过与未通过项目，不发送明文凭据。如工作尚未就绪只汇报进度、不宣称“可以验收”。
