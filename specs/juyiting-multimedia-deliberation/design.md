- 保留现有聚义厅页面、导航、布局、样式、点将入口和工作空间；复用已有组件及后端能力，不新增四步向导、独立页面或路由。
- 仅在现有提需求位置统一“添加资料（可选）”；在现有点将链路补齐自动进入悬赏议事及需求/资料传递。
- 仅在现有议事消息和输入区补齐多媒体展示、预览/下载、继续补充及可选保存；在现有验收入口补齐最终成果选择与完成。
- 已经正常工作的部分不重写，不为符合原型外观改色、换布局、拆页面或重构架构。只针对实际功能缺口修改必要代码。
- 原型反馈修订：保留现有底部“办事 / 事项 / 资料 / 我的”，移除顶部切页菜单和四步流程导航；通过现有入口和页面内动作继续操作。
- 下方 P1–P6 是功能场景标识，不是新增页面清单。旧原型只解释内容和交互，不是视觉、导航或页面重做依据；后续原型应基于现有页面标注局部变化。

## 1. 产品目标与边界

**提需求 → 选 Agent → 在会话中看结果、继续调整 → 验收完成。**

用户只需要说清想做什么，不需要理解模型、工具、工作目录、授权令牌和执行协议。四步是业务步骤；添加资料、预览及反复修改是可选操作，不加入强制确认链。

| 做 | 不做 |
|---|---|
| 图片、文档、音频等统一作为资料 | 独立“参考图”“生成图片”“受控请求”入口 |
| Agent 按需回答、澄清、查阅资料和执行 | 让用户选择 CHAT / INSPECT / EXECUTE |
| 同一会话继续补充、修改和接收多媒体结果 | 每次修改重新提需求、重新点将 |
| 结果可预览、下载、可选保存，最终正式验收 | 强制先保存工作空间才能完成需求 |
| 复用现有 Agent 接入、工具和内容存储 | 要求另配图片服务器或独立 Images API |
| 新请求统一走新流程，保护存量内容与未完成操作 | 为旧界面搭建新兼容层、双轨入口或新文件系统 |

“画一只鸟”只是验收案例；整理文档、分析音频、制作文件使用同一套产品流程。展示某类媒体的能力不等于当前 Agent 已具备生成该类媒体的能力。

## 2. 页面结构与原型

[打开交互原型](prototypes/index.html) · [全部原型图与交互说明](prototypes/README.md)

原型为此前独立绘制的流程示意，**不作为页面重做依据**。实际保留现有页面结构、导航与样式，只在原位置补齐以下功能；不落地原型的独立页面或侧栏。原型已移除四步进度条和顶部评审菜单，并补回底部菜单。

| 页面/层 | 主要内容 | 唯一主要动作 | 次要动作 |
|---|---|---|---|
| P1 提需求 | 一段需求描述、已选资料 | 选择 Agent | 添加资料（可选）、预览、移除 |
| D1 选择资料 | 当前用户工作空间文件，多选 | 添加所选资料 | 预览、取消 |
| P2 选 Agent | 需求摘要、可用 Agent、简短能力说明 | 开始议事 | 返回修改、选择其他 Agent |
| P3 悬赏议事 | 完整会话、多媒体结果、统一输入框 | 发送 | 添加资料、引用结果、预览/下载/保存、验收 |
| D2 媒体预览 | 大图、音频播放器或文档预览 | 下载 | 保存到工作空间、关闭 |
| P4 验收 | 本次最终成果集合、需求摘要 | 验收完成 | 返回继续修改、调整最终成果集合 |
| P5 已完成 | 完成状态及精确最终成果 | 查看成果 | 下载、可选保存、新需求 |
| P6 工作空间 | 已有文件及用户主动保存的内容 | 打开文件 | 预览、下载；继续使用现有空间管理能力 |

### 2.1 P1：提需求

- 只有需求正文必填。标题可由正文提炼，用户不必再填标题、媒体类型或“资料用途”。
- 统一按钮“添加资料（可选）”，默认展示所有可读文件；图片、文档、音频及其他文件使用同一个选择器。不得仅改文案而内部仍只查询图片。
- 已选资料以紧凑卡片展示文件名、类型提示/缩略图、预览及移除。不展示 MIME、摘要、路径、内部编号和固定版本术语。
- 选择文件时后台冻结精确版本；默认选当时的最新可用版本。高级版本查看沿用工作空间，不增加提需求必经步骤。
- 移除只改变当前草稿，不删除工作空间原文件。取消选择器不改变原有选择。返回本页保留正文与资料。
- 空白正文不能提交；无资料可以提交。服务端创建需求后返回稳定任务身份，再进入选 Agent；重复点击不能重复建任务。
- 空空间提示“暂无资料，也可以直接提需求。”未支持预览的格式仍允许按实际文件策略选择/下载，不能伪装可解析。

### 2.2 P2：选 Agent

- 展示名称、真实连接状态和一句能力说明；不显示模型参数、接入密钥、协议版本或无依据能力评分。
- 点选仅改变候选；点击“开始议事”才以明确 `targetAgentId` 提交。可以默认突出推荐项，但不能隐藏实际接收者。
- 完成点将后自动创建/复用任务的“悬赏议事”，自动发送原需求及所选资料并进入会话；不再出现“发送需求”确认。
- 点将已提交但会话尚未就绪：当前页显示“正在进入议事…”，后台继续；返回后读取原操作，不重新点将。
- Agent 不可用时如实提示并允许更换；不能用另一个 Agent 静默代替选中对象，也不能仅因慢于性能目标而终止请求。

### 2.3 P3：悬赏议事（核心页面）

- 顶部只显示需求标题、接收 Agent、简短任务状态和“验收”；不常驻工具执行面板、授权面板及大侧栏。
- 需求和资料作为首条真实用户消息出现。后续仍用一个输入框和“发送”，支持正文、资料及已有结果引用；附件-only 补充也可发送，不伪造用户文字。
- 每条结果可以混合文本、图片、音频和文件。图片直接显示缩略图；音频默认不自动播放；普通文件按真实格式预览，不能预览时明确可下载。
- 结果卡保留“预览 / 下载 / 保存”；“继续修改”只把该结果作为引用放入输入框，不另开生图表单。文字结果/文字选区也可保存。
- “参考图”是 Agent 对资料用途的理解，不是文件类型、用户必选项或独立文件目录。
- Agent 信息不足时直接在会话提问，用户原位回答；不会问“是否允许查阅/是否签发执行”这类工程问题。
- 用户可在一次答复后说“改成蓝色”，也可加新资料。当前有多个可能被修改的结果时，先用简短问题明确对象；不要暗改旧稿。
- **实时展示**：文本增量及时显示；媒体在服务端确认可读取后原位出现。未完成文件只显示“处理中”，不把本机路径、Markdown 外链或 Provider 回执当成已交付文件。不承诺逐像素生成图片。
- 正在处理时可以继续编辑草稿；当前轮未结束时不对同一任务并行重复执行。用户明确取消时走既有取消机制，不能靠关页面假装取消。
- 关闭页面不停止后台任务；重进会话读取历史与当前状态，不重发原需求。

### 2.4 P4/P5：验收与完成

- 有可验收结果时，“验收”打开成果清单；默认选中本次明确标记的最新完成成果组，不按文件时间戳盲选全部历史稿。
- 用户可预览并调整最终集合。文字、图片、音频和普通文件均可作为成果；纯文字要冻结精确消息/选区快照，不能直接引用仍在变化的流式正文。
- 点击“验收完成”即表达对清单中成果的正式验收。后台完成正式交付快照、验收记录与任务完成；**不另加“确认提交/确认批准”弹窗**。
- 任一关键阶段未成功，只显示真实状态；响应丢失先查询原操作，不新建验收、不重新生成。
- 只有任务领域确认完成后显示“已完成”。已完成页仍可预览、下载、可选保存；继续创作应发起新需求，不暗中修改已验收交付件。
- 保存工作空间与验收互不依赖。保存失败不重跑 Agent，不阻止已经成功的验收，也不把验收状态回退。

### 2.5 移动端、可访问性与文案

- 窄屏不显示常驻侧栏；资料选择、预览和验收采用可返回的全宽面板。输入框随键盘可视区域调整，正文滚动，不遮挡发送按钮。
- 按钮有可见文字或可访问名称；图标使用项目实际存在的资源。弹层可关闭，支持 ESC、焦点恢复和键盘操作；音频不自动播放。
- 状态限于“待开始 / 处理中 / 需要补充 / 待验收 / 已完成 / 未完成”等用户词汇。内部阶段不逐条翻译成通知。
- 错误只提供对应的一步动作，例如“发送未完成，请重试”“资料已更新，请重新选择”“暂时无法读取，稍后重试”。不显示 raw code、堆栈、路径、Provider、CAS 或幂等键。

## 3. 一条请求链路，不是两套产品

```text
需求及可选资料 → 明确点将 → 自动悬赏议事
                                 ↓
                    Agent：回答 / 澄清 / 动作
                                 ↓
                      按需查阅资料、使用工具
                                 ↓
                    持久结果 → 会话实时展示
                       ↙                 ↘
               可选保存工作空间      正式交付、验收完成
```

### 3.1 fast-deliberation 与 multimedia-deliberation 的长期融合

两者共享任务、会话、消息、请求状态、事件和可靠投递机制。`fast-deliberation` 的价值是**没有必要就不加载重资料/工具**，不是永久禁止普通请求使用工具。

| 内部处理 | 输入 | 输出/后续 | 用户看到什么 |
|---|---|---|---|
| 轻量判断 CHAT | 当前需求、必要历史、资料目录、真实可用动作描述；不默认读取全部文件字节/加载全部工具 | `ANSWER`、`CLARIFY` 或 `ACTION_REQUEST` | 答复、问题或“处理中” |
| 按需查阅 INSPECT | Agent 选中的已授权精确资料版本与原需求 | 回答、澄清或后续动作 | 会话里的自然答复 |
| 实际执行 EXECUTE | 需求、已核验来源、匹配的现有工具、执行目录 | 验证后的结果文件/文本 | 结果卡片 |

- 这些是后台处理方式，不是三个页面或用户要选的三种模式。资料目录不代表内容已读取。
- 用户明确要求生成/修改时，无需先闲聊再“提出绘图申请”；Agent 可立即请求已有执行动作，后台自动承接。一次内部路由不增加用户步骤。
- 动作目录由当前 Agent 的真实适配器和已有账号权限生成。只暴露实际可用操作；不凭模型名称推断能力，不写入未经核实的模型型号。
- 不把每轮动作变成新用户授权；也不因“统一授权”擅自开启账号范围外的新付费服务。确有能力/配置缺失时说明真实缺项，不能默认要求新配 Images API。
- 工具慢只显示处理状态并继续等待；保留真实传输错误、用户取消、权限及锁归属，不增加任意性能拒绝门槛。

### 3.2 自动续办与结果恢复

1. 需求、点将及初始资料版本写入业务记录；可靠投递确保唯一会话与首条需求，不依赖浏览器回调继续执行。
2. Agent 最终答复、澄清或动作意图持久化；最终结果与对应投递事件同事务保存。
3. 动作消费者核对原用户、任务、会话、当前指派和资料权限，自动查阅/执行；引用原真实用户消息，不能伪造“同意执行”的用户消息。
4. 工具输出先上传并校验，后成为持久会话资产；会话事件驱动刷新和增量展示。
5. 重连、重投复用同一操作身份。已有本机结果但上传失败时仅恢复原字节；状态未知时先查，不再次调用工具/重复付费。
6. 确定失败、取消或权限变更写入真实终态；暂时网络/服务错误允许既有恢复机制继续。不能为了“稳定”无限重试同一确定性错误。

## 4. 一份内容，三种用途

```text
持久内容 + 不可变版本/摘要
 ├─ 会话引用：用户在议事中看到、预览、下载
 ├─ 工作空间引用：用户主动保存后，成为个人资料
 └─ 正式成果引用：验收时冻结选定集合，形成正式交付
```

- “一份内容”指同一内容身份、版本和来源可追踪，不承诺底层绝对只有一份物理字节。现有存储边界必要复制时校验同一摘要；不建第三套文件系统、不强制历史文件搬迁。
- 会话输出不自动占据个人文件列表，不自动作为正式交付。保存和验收分别建立相应业务关系和权限。
- 用户可保存整条完成文本、选区或媒体文件。普通保存重试返回原结果；另存副本、覆盖已有文件/新版本只能是明确用户操作，不能自动覆盖。
- 未保存的会话成果仍由平台持久保存，可在刷新或 Agent 离线后读取；不得依赖浏览器 Blob 或 Agent 的临时目录。
- 文件被撤权后不能继续领取；移除当前资料引用不删除源文件。已保存内容、正式成果不随会话删除而消失；本期不新增无依据的自动清理/过期策略。
- 浏览器不接触平台磁盘路径。平台实际存储根由部署配置决定；现有逻辑存储包含个人/会话内容存储及正式任务成果存储，本详设不把历史路径断言为当前线上目录。

### 4.1 最小逻辑模型（优先复用已有记录，不按本表新建同名表）

| 逻辑对象 | 必须保存的事实 | 核心约束 |
|---|---|---|
| 需求 | 任务、正文修订、所选资料精确版本、创建者 | 无资料合法；不授予整个空间权限 |
| 指派/会话 | 明确 Agent、指派修订、稳定会话、首轮操作 | 重试不重复建会话/消息 |
| 用户请求 | 原消息、资料快照、父结果/澄清关联 | 重投不变原意图，不能假造用户输入 |
| 内容/结果 | 内容身份、MIME、大小、摘要、来源、可读状态 | 验证字节后才可见为就绪；新稿不覆盖旧稿 |
| 保存关系 | 来源快照、目标文件/版本、保存操作 | 重试复用；更新已有文件有版本检查 |
| 正式交付 | 用户选定成果集合、精确版本/摘要、验收记录 | 验收期间不被“最新稿”替换 |

## 5. Agent 如何读取与输出

平台工作空间与每个 Agent 客户端工作目录不是同一个目录，也不需要共享挂载。

```text
平台授权的资料版本 → 客户端按本次任务领取 → 本次执行 inputs/
                                                      ↓ Agent/工具
平台持久结果 ← 上传与内容校验 ← 本次执行 outputs/
                               scratch/ 仅工作临时文件
```

以下是**执行沙箱逻辑布局**，不是声称现有各客户端磁盘已经采用此路径：

```text
<该客户端配置的工作根>/<本次执行隔离目录>/
  inputs/      本次实际领取的只读资料
  outputs/     本次准备交付的输出
  scratch/     临时文件，不自动发布
  manifest     输入/输出与业务身份、版本、摘要的关联
```

- 客户端适配层分配真实目录、领取并校验资料，再把真实输入清单、相对路径和输出目录告诉 Agent/工具。**提示词要说明读哪里、写哪里；权限和上传不能只靠提示词。**
- “山寨安顿”和“自家接应”使用同一业务合同；区别只在客户端运行位置、配置工作根及接入方式。不要求客户端直接读平台私有根目录。
- 客户端只上传明确声明的本次输出，不扫描整个工作目录；校验路径穿越、符号链接逃逸、大小/MIME/摘要和真实执行归属。
- 图片/音频原生输入必须由适配器实际传入支持的模型/工具。只传文件名或文字摘要时不得声称已经“看图/听音频”。
- 图像生成/编辑复用已有 Agent 工具；`gpt-image-cli` 是可选的现有适配器能力，不是普通用户必须选择的产品模式。
- 升级客户端必须验证真实运行版本及能力，不以代码推送或能力自报替代实际可用性验证。

## 6. 接口与前后端职责

下面是从 API 候选 `75357f13` 核对的**现有源码入口**，不代表当前线上已启用。具体 DTO 以相应 Controller/Wire 为准；产品模型不允许直接冒充已支持的请求字段。缺少的通用能力在这些入口内最小扩展，不新建平行“图片 API”。

| 业务 | 复用源码入口 | 页面职责 / 服务端职责 |
|---|---|---|
| 创建需求 | `POST /agent/tasks` | 提交正文和统一资料 / 验证归属并保存需求快照 |
| 选择 Agent | `POST /agent/roster` | 显示真实候选 / 返回当前用户可操作 Agent；不用 `/agent/active` |
| 点将并议事 | `POST /agent/tasks/{taskId}/point-and-deliberate`；`GET .../point-and-deliberate/request` | 明确 `targetAgentId`、任务/需求修订 / 幂等点将、自动会话和首轮投递 |
| 普通会话请求 | `POST /chat/conversations/{conversationId}/interactions/discussion` | 同一输入框提交正文及 `sourceSelectors` / 冻结上下文、按需续办 |
| 最终结果 | `GET /chat/conversations/{conversationId}/requests/{requestId}/typed-outcome` | 渲染状态/结果 / 返回真实持久状态，不因 GET 执行工具 |
| 实时更新 | 既有 `/chat/conversation/events` 及 durable 消息/状态读取 | 事件去重、断线补读 / 按会话授权推送 |
| 资料与附件 | `/agent/personal-workspace/files`、精确版本内容/预览；任务/会话 `file-links` | 统一选择、展示 / 仅关联可读版本，正文-only 和混合类型均合法 |
| 会话媒体 | `GET /chat/conversations/{conversationId}/assets/{assetId}` 及 `/content` | 预览/下载 / 校验会话与资产权限，按支持格式提供字节及音频 Range |
| 可选保存 | `POST /chat/conversations/{conversationId}/archive-operations`；GET 操作状态 | 保存文本/媒体 / 来源快照及目标文件权限、幂等结果 |
| 正式验收 | `POST /agent/tasks/{taskId}/finalizations`；GET 原请求/操作状态 | 提交选定集合 / 正式交付、验收与领域完成 |

- 写操作沿用已定义的幂等键、版本和响应包装；身份来自登录态，不接受浏览器指定 owner 或模型自述授权。
- 前端不依靠是否存在 SSE 订阅来启动工作，不在刷新时自动生成新请求；遇到发送结果未知保留原键并查询。
- 会话模型结果复用 v3：`ANSWER / CLARIFY / ACTION_REQUEST`。模型只能选择服务端提供的动作/来源身份，不能自造任意路径、URL、账号或费用许可。
- 模型结果版本与浏览器请求 `schemaVersion` **不是同一个合同**，不能见 v3 就把所有端点请求版本改成 3。
- **必须补齐核验的能力**：当前 finalization 源码使用 `selectedOutputs`（request/step/output/hash 等），不能据此声称任意消息文本或所有媒体已能正式验收；须将纯文字快照、不同媒体结果映射为可追踪正式成果，并补合同/测试。同理验证附件-only、混合资料、真实音频/文档预览及保存支持，不以 UI 卡片存在代替实现。

## 7. 最小异常与数据安全设计

| 情况 | 用户反馈 | 系统动作 |
|---|---|---|
| 提交响应丢失 | 正在确认发送状态 | 查原请求；不换键重建任务/执行 |
| 资料更新、删除或无权限 | 请重新选择这份资料 | 拒绝错误版本；不偷偷换成最新文件 |
| Agent 离线/能力缺失 | Agent 暂不可用，可稍后重试或更换 | 保留草稿/已受理事实；不谎称送达或自动换人 |
| 工具确实失败 | 本次未完成，请调整后重试 | 保存失败事实；用户新意图才启动新执行 |
| 工具有结果但回传失败 | 结果正在恢复 | 复用原输出字节/清单，不再次生成 |
| 保存失败 | 保存未完成，可重试 | 仅恢复保存；原会话结果不受影响 |
| 验收响应未知 | 正在确认验收结果 | 查原 finalization，不重交付/重新验收 |
| 登录身份变化 | 请重新登录/当前内容不可访问 | 取消旧身份请求，清理其可见缓存，重新鉴权 |

每次读取、领取、保存和验收均校验真实用户/客户端/任务/会话及精确资料版本。素材正文是数据，不是可越过系统规则的指令。权限、事务、锁、取消和实际费用范围保留在后端，但不变成普通用户操作教程。

## 9. 验收清单

| 编号 | 场景 | 必须看到的真实结果 |
|---|---|---|
| N01 | 不加资料提“画一只鸟，照片风格”并点将 | 自动会话、真实目标 Agent、实际图片字节可解码/预览/下载 |
| N02 | 混选图片、文档、音频后提交 | 统一入口、精确版本、Agent 按需实际使用资料；未读不得声称已读 |
| N03 | 信息确实不足 | 同一会话自然澄清；回答后继续，不出现执行批准链 |
| N04 | “改成蓝色”并引用前一结果 | 新结果有来源，旧稿与原资料不被覆盖，可指定最终稿 |
| N05 | 多媒体混合回复 | 文本增量、图片可预览、音频可播放、支持格式的文档可预览；其他格式可下载 |
| N06 | 保存文字选区/整条答复及媒体 | 空间中能重新打开同一内容；重复保存/恢复不重复建文件 |
| N07 | 不保存直接验收；保存失败后验收 | 最终成果集合正确、正式交付可读，完成状态真实，不依赖保存成功 |
| N08 | 纯文字或文档任务 | 不进入图片特例，能形成正式成果并验收 |
| N09 | 刷新、断线、关闭页面、回传失败 | 后台继续、原结果恢复，不重复派发/执行/付费，历史可读 |
| N10 | 跨用户/跨任务越权、资料撤回、身份切换 | 无越权字节/私有路径/他人缓存泄露；精确错误不伪成功 |
