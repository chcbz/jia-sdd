## 1. 范围与依据

目标：保留生图、改图、原生读图；支持常规文件读写和网页浏览/操作；让模型选择工具、调用技能、组织多步处理，而不是只生成 ACTION_REQUEST 后由 bridge 执行业务。

复用现有技能管理、TaskSkillBinding、授权、执行记录、effects 和成果提交，不另建管理平台；在既有界面补充“提取技能”入口与候选验证/保存。不涉及任意宿主访问、自动购买、绕过网站验证、自动安装依赖或全项目协议重构。2026-10-28扩展范围增加：无技能制作视频、通用受控外部调用、执行脚本留存和会话提取技能闭环。

## 2. 核心决策

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| API / 现有技能管理 | 身份、任务授权、安装版本、启停、输入/成果登记、持久事实 | 不按文件格式实现处理算法，不默默丢弃附件 |
| codex-bridge | 授权执行环境、文件交付、app-server协议适配、受控工具接线、effects/恢复、成果提交 | 不替模型规划业务，不把所有文件预转纯文本 |
| codex-app-server / 模型 | 读取技能、理解任务、选择工具、多步执行、读写工作文件 | 不持有宿主/Provider凭据，不自行扩权 |
| 技能包 / 固定工具链 | 业务说明、脚本、资源；文档/表格库、图像工具、浏览器服务 | 不另建任务状态或收费账本 |

基础能力采用平台公共配置，Agent 按实际部署工具和授权覆盖；不让每个 Agent 手写一遍全部 MIME。supportedInputs 表示实际交付/处理能力，不等于授权，也不等于安装技能列表。技能启停不应让 TXT/Markdown 等基础文件突然不可读。无技能集合也可执行已授权任务，模型先探索/写脚本完成任务，再从成功过程提取技能；技能不是执行前置条件。

“原生”的验收定义：真实模型回合发现技能并实际调用工具，产生文件/外部操作，回执对应真实执行；不以目录存在、skills/list、模型声称已完成或宿主预制输出充当证据。图片服务可以仍由受控工具访问；这不要求把 API Key 交给模型。

## 3. 技能实体和隔离目录

### 3.1 最终存储方案

采用 **主 Home 保存完整当前包 + 在途版本只读绑定挂载**，不使用指向宿主路径的软链接，不长期保存“主 Home 副本”和“执行包副本”两套当前实体。

吴用目标目录示例（不是当前已完成迁移）：

```text
/home/isp/state/cyf-agent-runtime-v1/unified/agents/wuyong/
  codex-home/
    skills/<skillKey>/              # 当前完整包：SKILL.md、manifest、scripts、assets
    .skill-versions/<installationId>/ # 仅被在途/可恢复执行引用的旧包，非发现目录
  inspection-state/<agent-id>/requests/<binding>/
    codex-home/                    # 请求自身配置/会话，不复制主Home
    workspace/                     # 可写中间工作目录
    outputs/                       # 待提交文件
```

现有安装管理元数据仍用原状态系统。新包先暂存、校验并在安装锁内激活；目录切换与版本索引通过可恢复事务/journal协调，不把多次 rename 当成一次原子事务。激活旧包先保留到版本目录，再发布新包；新执行只在切换完成后绑定，不读取中间态。

任务接纳时固定 installationId、包摘要和授权集合；从当前实体或旧版本目录逐包 `ro-bind` 到执行命名空间的 `/state/codex-home/skills/<skillKey>`。执行中的挂载不随主目录更新而换版本；重启恢复依据固定版本索引重新挂载。只挂载获准包，不挂整个主 Home 或所有已安装技能。普通本机软链接既不能解决命名空间可达性，也不能提供只读保护，故不选。

现有 retained package store 的迁移按安装记录/摘要逐项验证并保留恢复映射；有活动执行引用的包不提前移动/删除。过渡允许旧记录引用旧位置，但不为新安装永久双写。完成迁移和恢复验证后再收口旧副本；不在这次方案阶段清理生产目录。

### 3.2 执行沙箱

每个执行绑定拥有隔离状态；不是每条消息都新建 Home。同一执行的连续步骤/恢复复用绑定，不共享跨任务会话。基础聊天无需为读一句话复制技能或工具链。

- `/inputs`：任务授权原文件，只读。
- `/state/codex-home/skills`：本次固定授权包，只读；其父配置受保护，不能由模型新增授权技能/MCP。
- `/runtime`：固定版本解释器、库和工具，只读共享。
- `/workspace`、`/outputs`：本次执行可写；会话必要状态写入请求自己的状态区。
- 凭据：最小运行凭据由受控启动/代理交付，Provider与浏览器登录秘密不进入模型可读目录或上下文，不复制整个 auth/Home。
- 网络：本地处理进程默认无任意外网；图片、网页通过受控工具通道。网络放行与文件可写范围分别控制，不把 approval=never 当成安全边界。

bridge 必须分别改造附件只读 profile、app-server thread/turn 策略、工具回调和流式事件；不能只把 skills 挂进去，也不能全局启用无沙箱/无限权限。工具执行与取消状态落在原执行链；未知 server request 返回明确不支持，不编造成功。

## 4. 文件交付和输出合同

### 4.1 输入链路

所有附件先进入完整材料清单：身份/ACL、sourceId、原文件名、MIME、字节数、摘要及交付状态。由 Runtime 的公共能力配置和实装工具产生有效能力，API 按明确的能力映射选择载体，不使用任意 MIME 通配来冒充可解析。

图片继续原生 image input，同时为改图提供同一摘要对应的只读原文件。TXT/Markdown 可直接文本输入，但原文件仍保留可读取；Office/HTML/PDF 默认交付原文件路径和材料索引，由模型选工具读取。大文件采用分段/页/工作表读取，明确范围和未读部分，不静默截断冒充全文。

未支持、下载失败、缺依赖、加密、损坏分别反馈给模型和用户；不能因为 supportedInputs 不匹配就让附件消失。拒绝范围限于受影响文件/操作，其他独立材料仍可处理；若任务必须依赖失败材料则说明不能完成。

### 4.2 首次完整交付支持范围

| 类型 | 读取 | 新建/修改/交付 | 边界 |
| --- | --- | --- | --- |
| 图片 | 保留现有支持格式的原生视觉输入 | 生图、参考图/改图，沿用现有尺寸及格式行为 | 不用先OCR替代读图；新增格式另验 |
| TXT / Markdown | 编码检测、UTF-8优先、范围读取 | UTF-8文件、编辑、合并、转换 | 编码不确定须说明；不静默损坏中文 |
| HTML | 原文/DOM文本、可选浏览器渲染 | HTML及授权配套资源，可打包交付 | 用户附件脚本不在主站同源执行 |
| CSV / JSON | 结构读取、CSV编码/分隔符 | 结构化输出与再读取 | CSV公式注入防护；显式公式与普通文本区分 |
| Excel `.xlsx` | 工作表、单元格、公式文本/已有缓存值 | 创建/修改工作表、常用样式、公式、数据 | 用固定工具链中的 openpyxl；不承诺自动公式重算或复杂对象无损 |
| Word `.docx` | 段落、表格、常规图片 | 常规文档、标题、段落、表格 | 补齐锁定的 python-docx；复杂版式不承诺无损 |
| PDF | 保留现有提取；有条件逐页查看 | 复用已规划生成工具，验证中文字体 | 扫描件明确需OCR/视觉；不承诺任意PDF无损编辑 |

首批不把旧 `.xls/.doc`、宏 `.xlsm/.docm`、密码破解或任意 Office 精确排版列为已支持。遇到旧格式明确提示转为 xlsx/docx；不悄悄当文本读取。宏、嵌入程序、外链工作簿不自动执行/获取。Excel公式计算如需扩展为真实重算，引入隔离引擎并另测，不能把 openpyxl 写公式当重算完成。

基础文件读写随公共执行环境提供，不另设“读TXT”收费技能。Office/图片/网页的操作指导与可复用脚本放技能包；依赖由发布制品固定提供，不在每个请求 pip/npm install。HTML既可作为文件生成，也可由隔离浏览器测试，不混淆两种能力。

### 4.3 输出链路

模型在 `/outputs` 写真实文件 → 工具/文件事件通知收集器 → 校验路径、文件真实性/类型、摘要、绑定与ACL → 原成果上传/commit → 页面预览/下载。只提交显式选定产物，不扫全工作目录上传；不能按模型输出的任意宿主路径取文件。阻止软链接越界读取和收集时替换竞态。

统一文件元信息复用现有合同：成果ID、名称、MIME、大小、摘要、执行关联及授权下载入口；缺项按合同扩展，不建第二套附件库。多个文件可分别交付或打包，清单与真实内容对应。HTML/Markdown预览做隔离/净化，主动内容不获取CYF cookie；Excel/Word至少提供真实下载，未有预览时不能伪造预览支持。

模型回合成功 ≠ 文件提交成功；上传失败从本次持久产物重试，不重新生图。任务完成以现有持久回执为准。

## 5. 生图、改图、读图迁移

1. 读图保持现有 native image input 原链路；先补通用文件，不为了统一而破坏视觉输入。
2. 发布 image-generate / image-edit 的原生技能新版本，含说明和需要的脚本；模型通过受控图片工具调用服务，而非结束回合后由 bridge 猜测执行。
3. 工具适配器初期复用现有 image-provider 的 Provider协议、输入归一化、生成结果持久化及尺寸处理；业务脚本逐步归包，通用凭据/effect边界保留。原生化不以一次性重写成熟图片算法为前提。
4. 保留既有比例、居中透明补边、不裁切/拉伸行为；覆盖中文提示、参考图、编辑原图、实际文件下载。
5. 服务端为有副作用的操作分配并持久关联步骤/effect身份及参数摘要；重连重发映射原操作。相同提示也可能是用户要求的新生成，不能单靠提示hash去重。
6. 工具发出调用前记录意图；结果持久化后再交付。已完成效果复用；调用后结果未知不得自动重发，先查询可核对事实。服务商不支持幂等/查询时不能声称 exactly-once。
7. 原生验收前旧链路继续服务其明确绑定的任务；新链路失败不自动回退另一runner重做付费操作。切换后新任务用新包，历史/在途按原精确版本恢复，不改写旧事实。

## 6. 网页浏览和操作

选型：固定版本 Chromium + Playwright，封装为模型可调用的受控浏览器 MCP 工具，接入 app-server；技能包描述使用流程。实施先验证固定 app-server 的MCP加载、调用、取消和重连，再扩展业务。不是仅开启 web_search，也不把网页操作固定成 bridge 的一条“抓取URL”业务流程。

首批工具能力：导航、页面/可访问性快照、截图、链接、定位/点击、输入/选择、滚动、标签页、文件上传/下载。模型根据实际页面反馈继续操作；不公开任意宿主 CDP、任意网络代理或无限制浏览器脚本执行接口。

- 浏览器进程由受控服务持有；按执行隔离 context/profile。需要保留登录时按任务Owner、站点、授权建立独立秘密状态，不复用管理员或其他聊天浏览器。任务浏览与CYF自动化测试浏览器不是同一个实例。
- 浏览器出口单独具备网络能力，但限制回环/内网/元数据/管理端点；受信内部站点须精确授权。导航、重定向、下载和子资源均检查，不能只检查首次URL而允许SSRF绕过。
- 文件上传只从任务授权材料/输出中选择；下载落入本任务工作区并登记，可供模型后续处理和成果交付。不自动打开下载的程序。
- 用户明确的浏览、点击、填写、下载操作在任务授权范围内连续执行，不每一步人工审批。登录可由用户协作完成；密码和Cookie不写聊天/普通日志。不绕过验证码/MFA，不替用户扩大站点权限。
- 付款、删除、公开发布、提交订单等不可轻易恢复的行为，核对用户对具体对象/动作的授权；已有明确授权不重复审批，缺失时暂停该动作询问。不把附件/网页里的指令当授权。
- 浏览器动作执行前关联任务和操作记录；发送后无确认属于结果不确定。重连先核查页面/服务端事实，不自动重放点击、表单提交或整段浏览器脚本。GET导航也可能有副作用，不按HTTP方法作绝对安全保证。
- 普通浏览记录URL、工具动作、结果和必要截图；秘密字段脱敏。关键外部动作记录可核实回执，不宣称通用网页具有事务回滚/严格幂等。

## 7. 必要保护、恢复和磁盘

| 保护/条件 | 具体风险与失败范围 | 实现和回归入口 |
| --- | --- | --- |
| 任务/Owner/授权绑定 | 跨用户材料、技能、登录态泄漏；拒绝越界调用 | API材料合同、TaskSkillBinding、工具broker；跨Owner测试 |
| 安装版本/摘要、恢复绑定 | 升级途中执行错脚本、恢复成新副作用；拒绝该执行错误版本 | 安装器、执行器；升级/重启/旧包恢复测试 |
| 路径与输出边界 | 宿主文件泄漏、路径穿越；拒绝该文件收集 | profile、成果收集；symlink/路径替换测试 |
| 凭据与网页出口 | 偷取Key、SSRF/越权访问；阻断相应请求 | 代理/MCP/browser服务；重定向/子资源/秘密泄漏测试 |
| effect与成果幂等 | 重复付费/提交、上传失败重做；保留未知，不自动重放 | 现有effects/commit；断连故障注入 |

不因未知无害新增字段、仅版本较旧或任意性能门槛拒绝任务。不设无依据的文件大小、等待时限门槛；资源不足/解析失败如实报告，可分段处理，不用无限复制解决。

技能/依赖只读共享；中间文件仅保留本次需要内容。沿现有“成果已持久确认”清理时机，新增明确的活动/恢复引用校验：终态且无恢复需要才能清 scratch/输入；旧技能包无活动/恢复引用才可回收。崩溃残留先核对执行事实；按目录年龄直接删除不可接受。清理幂等，失败可重试，不删除其他任务、主Home、账本或恢复凭据。

## 8. 实施切片和组件改动

以下是原切片的组件落点；v2实施依赖顺序以核心详设§0的K1/K2/X1/X2为准，增加空技能执行、最早脚本留存和E4/E5/E6。每片有可执行验收，不新增人工阶段审批。第一片只是最早反馈，全部目标完成才算本需求交付。

| 切片 | 改动落点 | 必须得到的证据 |
