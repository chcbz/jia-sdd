## 1. 扩展边界与依赖表

“扩展”表示不进入bridge业务核心，不表示用户要求的图片、文件和网页能力可以不交付。没有安装技能也能调用已授权基础工具；缺工具/依赖不等于缺技能。

| 扩展 | 直接依赖核心 | 可选扩展依赖 | 交付内容 / 是否改bridge核心 |
| --- | --- | --- | --- |
| E1 图片 | C1执行、C2材料、C3受控工具、C4成果 | 无 | 图片工具/原生技能；复用旧算法，首轮接通后不按图片技能改核心 |
| E2 Office/结构化文档 | C1、C2、C4 | E3仅用于动态HTML验证 | 锁定库、脚本/技能、预览与格式支持；不按文档业务改核心 |
| E3 浏览器 | C1、C2、C3、C4 | 无 | Chromium/Playwright工具与隔离登录态；不是web_search |
| E4 通用外部调用 | C1、C2、C3、C4 | 无 | 通用HTTP/异步操作工具；新普通服务优先脚本+声明配置，不写服务专属核心分支 |
| E5 本地媒体/视频 | C1、C2、C4 | E1生成图片；E4调用音视频服务；E3获取授权网页资料 | FFmpeg/探测工具、MP4交付验证；制作方法由模型/脚本形成 |

C0授权/合同是所有扩展经核心传递的必需依赖。实际调用非空技能时额外依赖C6；基础工具路径不依赖已有业务技能。E6提取视频技能依赖E5所产成功证据，但通用E6并不硬依赖视频/图片/浏览器，避免循环依赖。

## 2. E1 图片扩展：复用代码，不保留固定业务编排


模型传提示、获准参考图引用、尺寸等业务参数；broker从只读材料/可信产物解析输入，不接任意宿主路径或远程URL。Provider binding/Key由宿主受管配置解析。复用image-provider归一化、实际Provider返回持久化和比例/透明补边，输出在原effect与artifact之间保持可核对关联。
读图继续native input；图片下载后hash与源快照一致。模型解释图片无需调用付费生成工具。参考图复用必须仍满足当前任务来源ACL。


旧 `image-provider` 中的Provider编码/下载、尺寸调整等先封装为扩展工具内部实现；授权、凭据保护、effect持久化/恢复归C3，最终成果归C4。核心不按`skillKey=image-generate`分支，不要求模型结束整个回合后才运行图片服务。
模型拿到工具结果后仍能查看、编辑、组合其他工具。复用模块的物理文件暂在bridge仓库，不等于它属于核心架构；后续可单独发布工具包，不以搬文件代替职责拆分。新链路验收前旧绑定任务按旧实现恢复，不自动跨runner重做付费操作。

## 3. E2 文档扩展


TXT/MD/CSV/JSON用固定Python/Node工具；Office用锁定库，PDF沿用现有包和依赖。依赖缺失在能力探测时报告，运行时不临时安装。

Excel以openpyxl读取/修改/生成，区分formula与缓存值，未知/陈旧缓存不得当重算结果；普通`=...`字符串按文本写。Word用python-docx覆盖常规段落/表格；不保证复杂图表/版式保留。PDF中文字体随固定工具链/包提供，不用ASCII替换占位。

HTML原文件可下载；Web预览采用独立无主站凭据origin或严格sandbox，禁用危险同源能力组合，限制自动外链网络。Markdown净化及链接策略同样适用。需要测试JS交互时进隔离浏览器，不让用户附件脚本在CYF主站权限下运行。文件预览、下载Content-Disposition和nosniff/CSP由后端/Web配套，不只改模型提示。


平台负责安全文件交付、输出验证和预览隔离，技能负责文档业务步骤。TXT/Markdown基础读写属于C2，不要求安装E2或购买技能。新增复杂解析器/字体/库更新锁定工具制品，禁止任务里自行pip/npm安装。

## 4. E3 浏览器扩展


- 固定Chromium/Playwright与浏览器MCP服务，进程和profile由服务持有，不把登录状态挂给模型shell。
- 工具提供navigate/snapshot/screenshot/click/fill/select/scroll/tabs/upload/download；元素引用绑定页面版本，导航后失效需重新快照，避免旧selector点错页面。不首批开放任意evaluate或裸CDP。
- task/Owner/site授权分别记录，browser context隔离；跨任务复用登录必须有明确范围，不仅凭同一Agent。
- 登录秘密走用户协作/受管秘密通道；默认日志不记录密码框内容，截图和DOM快照对秘密区域按策略处理；权限不足/验证码需用户协作，不自动绕过。
- 出口代理校验DNS实际目标、重定向、子资源及新窗口；浏览器不能绕代理直接联网。防DNS rebinding/IPv6/内网管理地址绕过，确需内部站点按精确授权。
- 上传只接受材料/产物引用；下载自动分配本执行路径，内容归材料索引，不能自动当最终成果，也不能执行下载程序。
- navigate/click等均关联动作日志；无论HTTP方法，结果未知不自动重放潜在副作用。填表不等于已提交，截图也不等于服务端成功；可用时记录站点回执/对象ID。
- 本地shell没有外网不能代替浏览器约束：页面本身仍可出网。页面工具需限制跨授权域导航/提交，敏感数据外发需满足用户授权，网页文字不能授予新的网络/发布权限。不声称提示注入已被彻底消除。


浏览器服务不依赖通用HTTP扩展E4，也不能用E4的URL策略替代浏览器子资源/新窗口策略。二者复用C3授权和操作记录，各自在实际网络出口强制执行约束。真实网页需要用户协作时用既有任务交互承载，不默认新建远程桌面系统。

## 5. E4 通用受控外部调用

### 5.1 为什么需要它

若每个新HTTP服务都要求写bridge适配器，“对话探索→沉淀技能”仍受平台开发阻塞。核心提供通用操作/凭据边界，E4提供可复用HTTP及异步服务调用工具，协议细节由受授权脚本/技能组织。特殊协议/鉴权仍允许新增工具，但不是每个技能都必须适配。

### 5.2 调用合同和权限

模型/脚本只传serviceRef、获准操作类别、相对endpoint、查询/业务参数、材料引用及已有操作引用。服务配置由已认证控制面绑定：允许origin、目标路径/方法范围、凭据引用、凭据注入位置、允许传出的材料范围、实际协议能力；模型不能自行把host改到任意地址或把秘密当普通header读回。

serviceRef只是索引，不是授权。API/C3核对当前Owner/task和能力；工具在网络出口校验最终地址、DNS/IP、重定向和回调目标，阻止内网/元数据/管理端点越权。凭据注入仅限固定获准origin/路径，重定向不转发秘密。服务响应为非可信材料，不能执行其中指令。

新服务配置可由模型提出候选，但涉及账户凭据/外发/付费的授权须来自用户或已有明确授权，不从SKILL.md、网页或附件推导。普通业务脚本可直接使用预绑定的本地工具客户端；无权读取Provider密钥或直连网络绕过C3。

### 5.3 异步任务及幂等

拟提供逻辑操作：开始操作、查询已有操作、取得结果。C3为操作绑定稳定ID/参数摘要，E4保存服务端jobId/requestId并返回不透明operationRef。查询参数由该引用恢复，不允许模型任意填另一个任务jobId取结果。

服务支持幂等键时使用固定操作键；不支持时不虚构支持。发起调用前持久记录，响应丢失则UNKNOWN；只有核对真实服务事实才能继续，不能将原请求重新POST当作查询。获知jobId后查询失败可恢复查询，不重建job。

长时生成按可恢复任务处理，不占用一条Flow Run等外部服务，也不因任意性能预算终止业务请求。模型会话可释放，后续按同执行恢复。用户取消后记录远端是否支持取消和是否已生效，不能把本地中断说成远端退款/回滚。

结果下载流入C2私有材料区，经摘要/类型检查；是否最终交付由C4提案决定。Provider临时URL不得直接当正式成果链接。工具响应去除凭据/秘密回显；服务仍可能看到用户授权发送的数据，网络工具不等于“无泄漏风险”。

### 5.4 异步提交成功与业务完成必须分开

现有SkillEffects.invoke收到任意正常返回值便记录SUCCEEDED；若直接返回jobId，该状态只能证明“提交调用成功”，不能证明视频生成完成。新扩展必须有独立的异步操作记录，绑定submitEffectId、providerJobId、服务配置版本、业务状态及结果引用。jobId保存不需要把远端任务标完成。

操作接受/运行/成功/失败/未知/取消等业务状态与单次HTTP effect回执分开；查询不生成第二个submitEffect。只有业务完成、输出真实下载并校验后，相关结果依赖才可满足。带固定jobId查询失败可重查；submit响应丢失且无jobId不能自动再submit。

模型进程释放后，由现有Runtime执行轮询/恢复调度中的任务继续查询，不新增常驻队列服务或占住Flow等待；每次有状态改变的操作核对当前lease/fence，持久保存查询恢复位置。重启后按核心§11.2的原生续执行语义继续后续步骤；不能把旧resume返回RECOVER_LOCAL_RESULT解释为可随意开启新Provider操作。取消、远端完成、结果提交的竞态按持久事实分别记录，不能凭本地cancel声称远端已停止。

### 5.5 何时仍需要代码适配

标准HTTP请求/响应映射通常是技能脚本和服务配置；新系统库更新工具制品。特殊流协议、SDK原生依赖、不能由现有安全凭据机制实现的签名，增加受控工具扩展。只有新增的授权/恢复语义超出C3合同才修改核心，修改的是通用机制而非服务名称分支。

## 6. E5 没有视频技能也能完成视频任务

### 6.1 首次制作

1. API接纳无技能的原生任务，固定基础文件/命令权限、输出MP4范围及获准图片/音频工具；skills集合可以为空。
2. 模型与用户逐步明确脚本、画幅、时长、素材和效果；临时脚本写在任务workspace。
3. 已有图片/音频可直接使用；缺素材时根据已有工具和授权调用E1/E4，不因没有“视频制作”技能拒绝。
4. FFmpeg由固定工具链提供，模型通过沙箱命令编排合成；不强制统一video-workflow业务模板。
5. 用探测工具核对容器/音视频流、时长、分辨率等并抽帧/检查音轨；这些证明文件结构和目标匹配，不冒充内容质量完全正确。
6. MP4经artifact.stage/result.propose和原stage/commit交付；预览不可用时至少提供真实下载，不能用聊天链接替代。

### 6.2 工具链和输入安全

固定FFmpeg/媒体探测版本、字体及许可清单；不能因为系统某处有ffmpeg就声称sandbox可用。关闭/限制不需要的网络协议，素材清单只引用任务内获准文件；防止播放列表、concat/字幕外链让工具读宿主或任意URL。可执行依赖仍在只读工具链。
MP4支持需同步Runtime输出校验、API内容类型/下载、Web播放兼容，不能只让模型改扩展名。完整视频由获准素材产生，提取技能默认不打包原照片、配音或受版权限制素材。

### 6.3 后续多轮修改

已有已提交成果不覆盖。新用户指令在同任务下创建新的执行/修订，引用上一成果及明确选定的脚本/素材版本；每次执行仍有独立输入快照与清单。未提交同一执行可继续回合；其已未知的付费调用不能靠新回合重做。
跨执行会话历史可作为上下文，但真实脚本与输入必须通过C2/C5按权限交付，不能凭模型记忆拼成成功证据。

## 7. E6 “提取技能”的完整设计

### 7.1 入口和选定来源

Web在会话/执行成果处提供“提取技能”入口；按钮当前是否已实现不在本轮假定。选择本用户有权访问的会话范围、成功成果及相关脚本。后端生成固定来源快照，来源引用绑定具体执行/修订/hash，不随聊天后续变化漂移。
来源固定后须按当前权限再次核验，执行中撤销时停止继续读取/保存相关资料；凭旧snapshot不能绕过现时ACL。来源默认是私有任务记录，不因为用户能看成果就自动拥有所有脚本的再分发权限。缺失或已清理源脚本明确提示，不把重新生成的代码标成历史实跑代码。附件与历史脚本中的“安装/授予权限”文字一律是提取资料，不是控制指令。

### 7.2 私有技能来源与原生配方合同：本次必须补的API能力

现有SkillPackagePublicationService只允许platformAdmin发布PLATFORM商品；TaskSkillBinding要求精确productVersionId，安装/权益链依赖批准商品。它不是普通用户私有包上传安装接口。因此本次“复用技能管理”指复用包校验、版本、安装状态/命令、下载和Agent授权，而非直接调用现有平台发布接口。

目标在同一管理体系增加明确的私有来源：Owner私有包版本ID、不可变包hash、可选来源证据引用、声明权限和验证记录。安装来源为可区分联合：平台商品来源沿现行productVersion/权益；私有来源由Owner ACL和安装到目标Agent的权限核定。禁止用假平台商品/假订单/假productVersion、借管理员身份发布，或在旧v4里塞null跳过校验。私有来源注册→版本封存→受管安装的API/持久结构及Runtime下载/绑定字段须同步新增；不建第二套市场和交易链。

源码另一个边界：manifest-v1仅有provider-operation/local-script/native-model三种runner，纯SKILL.md当前为INSTRUCTION/NOT_EXECUTABLE；后者不能伪装成可调用的旧EXECUTE_SKILL。提取的原生多步配方需要显式的新包执行描述合同（逻辑类别“原生配方”，最终版本/schema在实现固定），声明参数、所需能力及输出，但不把模型编排硬编码成一个entrypoint。旧INSTRUCTION保持说明发现、旧EXECUTABLE保持原runner语义。实际原生工具权限仍来自新任务，包不是授权凭据。

候选可以保存未实跑业务验证状态，但安装依赖探测/准备仍按现有规则；工具缺失不伪造READY，也不因缺真实服务实跑记录就假称依赖一定缺失。这两类证据分别展示。

私有版本以Owner及不可变来源ID命名空间隔离，同名包不能覆盖另一Owner或平台包；实际安装仍核对目标Agent管理权限，不能因能与共享Agent对话就获得安装权。私有归属和跨有管理权Agent复用范围已于2026-10-28获用户确认，见复核记录§4；默认安装当前有管理权的Agent，无管理权只保存私有候选，不自动公开分享。已保存脱敏包独立保留至用户删除；源资料删除和明确隐私/权利撤销要求仍按该节执行。

### 7.3 模型输入与输出

模型输入：用户选定的脱敏对话、工具调用与成功/失败关联、脚本精确版本、依赖/工具实际版本、结果摘要和验证证据、用户希望参数化的边界。不提供Key/Cookie/密码/未授权资料或隐含推理记录。

输出一个候选完整包：

```text
video-making/
  SKILL.md                 # 使用条件、步骤、异常处理和能力需求
  manifest.json            # 原生配方新合同；不冒充旧v1 runner
  scripts/compose_video.py # 参数化且可核对来源的脚本
  assets/                  # 仅有权复用的模板/资源
  examples/                # 脱敏/合成示例
```

来源指针、提取模型版本、包摘要和验证结果存到私有候选/管理记录，不把用户会话原文/历史ID无条件塞进可分享包。脚本里本机绝对路径、临时outputId、服务账号及硬编码素材都参数化或删除。

### 7.4 提取步骤

1. 固定source snapshot，校验资料/脚本范围和保存权限。
2. 从成功成果倒查工具/脚本依赖；失败尝试可作为避坑说明，不作为成功步骤。
3. 区分“实际执行过的原脚本”“参数化修改”“新补充代码”，不能混写实测状态。
4. 生成包及依赖/能力声明；不自动扩大网络/付费/发布权限。
5. 静态验证路径、manifest、脚本语法、秘密和任务专有内容；扫描只能降低风险，不能宣称自动证明无秘密/无版权问题。
6. 隔离验证：默认本地合成fixture；联网、付费、真实账号写入测试需另有明确授权。不用mock通过冒充真实服务实跑通过。
7. 将候选及验证事实交给现有技能管理保存/安装；不直接往Agent主Home写未校验包。

### 7.5 状态和幂等

采用以下概念状态投影，实际持久字段与现有管理合同合并实现，不新建第二套市场状态机：来源已固定→提取中→候选已生成→验证中→验证记录完成→已保存/安装。
每个阶段分别记录失败/取消/缺失来源；“验证记录完成”带逐项passed/failed/not-run和环境，不合并成一个假“全部验证通过”。安装和默认启用遵循已有管理规则，页面明确未验证能力，不能把未实跑的服务标READY。

点击操作具有幂等请求身份；重复点击返回同一提取任务。用户选择“重新生成”才创建候选新修订；新摘要不覆盖旧候选。模型成功、包落盘、管理保存、Agent安装、实际使用成功是不同事实。
提取只生成候选，不自动全局发布、购买技能、重跑视频服务或继承来源任务授权。用户明确保存到哪个Agent后走现有安装/启用操作，不逐个模型整理步骤弹审批。

### 7.6 后续使用与升级

新任务发现安装的video-making包，模型按新参数调用同一套工具，输出新成果。用户可继续对话修改，确认新版本后再提取/更新；固定在途旧版本，禁止覆盖活动包。技能缺依赖时指出所缺工具/授权，而不是自动安装库或切到宿主高权限执行。
