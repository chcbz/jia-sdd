## 2026-10-28 用户更新：技能原生调用与用户自配凭据

本节为用户后续决定，覆盖本功能文档中“生图/改图等必须经bridge专用Provider工具出口”“新增服务必须先改bridge受控工具”的目标要求；既有身份、执行隔离、已发生操作事实与成果提交保护不因此删除。

- 模型通过app-server原生执行技能包中的脚本，由脚本调用图片等外部服务；具体协议、SDK、编码和转换逻辑属于技能脚本/其依赖，不在bridge通用执行层重新实现。读图仍优先使用原生图像载体。
- 技能安装与用户凭据配置分离。后续用户可为自己安装的技能单独配置密钥；密钥不写进分发包、SKILL.md、源码、提取的技能或聊天正文，不复用其他用户的凭据。此决定不要求本轮增加配置UI或新凭据管理平台。
- bridge只提供通用执行环境、获准配置/凭据交付、文件/网络隔离和成果快照回传；API保留身份/任务权限、安装归属和业务完成事实。不再为生图/改图增加专用Provider授权wire或固定工具编排。
- 客户机上的同一管理员本可访问本地两种实现；宿主工具隐藏密钥与向原生脚本提供密钥仍是不同执行边界。按新方案，获准脚本可使用交付的密钥，不能再声称模型执行环境绝对接触不到密钥；配置不得向未获准任务/其他技能无差别共享。具体交付粒度需按真实沙箱能力实现，不声称环境变量天然提供脚本间隔离。
- 当前仅开放模型Provider的受限网络以及最小shell工具链不足以保证图片脚本运行。须按技能实际依赖配置网络/库/凭据，保留既有图片算法与功能，不直接放开整个宿主环境，也不把“移动代码目录”当完成。
- 外部服务协议的幂等/查询/恢复由技能脚本按实际服务实现；bridge不能保证任意脚本的外部副作用可自动识别或恰好执行一次。未知调用不得因引擎重连自动重放，已有UNKNOWN事实不改写，成果提交仍以真实文件及权威回执为准。不新建通用Provider状态平台。

本条覆盖本功能文档与先前handoff中“有限历史恢复/待旧执行迁出后再删”的旧要求；不扩大为全项目安装、交易等业务的恢复机制删除。当前只是规格更新，源码删除与实际切换尚未执行。

## 3. 跨层合同（RB-08）

只复用/扩展以下职责接口，不为每个技能新增业务端点：

1. Web→API：用户意图、附件/资料引用、管理/取消等明确动作。API负责身份、任务关系与幂等。
2. API→bridge：执行绑定、输入快照、允许能力、输出范围、可为空的获准技能集合、lease/fence及恢复许可。不下发固定图片/视频业务步骤。
3. bridge→引擎：固定真实schema、隔离路径、受管技能/工具视图和指令；不暴露宿主秘密。模型从能力集合中选择具体步骤。
4. 引擎→工具：业务参数和获准材料引用。连接预绑定执行；工具不能信任模型自填Owner、凭据或目标执行。
5. bridge→API：操作事实、真实成果stage/commit和恢复查询。API核对身份、关系、摘要和业务提交条件；不解析脚本或Provider响应来重演任务。
6. API→Web：明确的执行关联、权威状态、成果列表/下载引用。进度可转发真实事件，但不是新的完成权威。

新合同在现有管理合同及DTO/schema中明确版本和消费者；不能给旧v4单技能字段塞null、伪造商品/订单/manifest。无害新增字段按统一兼容规则处理，未知执行语义不能猜。本文不预定尚未实现的wire编号或端点名。

## 4. 通用机制与业务算法的界线（RB-09）

- 可以按协议版本、工具能力、载体/MIME、实际文件安全性选择技术适配器；不得按skillKey、角色名、Provider品牌选择整个任务流程。
- 图片编码/缩放、Office读取/写入、FFmpeg合成、网页点击属于工具/脚本；不是因为有业务类型就全部删除。
- API/bridge可验证输入输出合同、字节摘要、容器/格式有效性；解析算法应在适配器，不能在多层重复实现公式计算、图片处理或视频编辑。业务内容正确性由模型/工具处理及验收验证。
- API决定数据访问规则；bridge和工具落实文件、进程、凭据和网络边界。这是授权与强制执行分离，不是无依据的重复校验。
- 同一个工具操作的持久身份跨重连稳定。API保存通用副作用事实，工具保存/查询远端协议状态，bridge组织恢复；不新增通用DAG或第二套任务调度器。
- 新技能使用已有工具/输出合同，只增加包和受管安装记录；新库更新工具制品；新Provider协议只增加工具适配。仅实际新增授权/恢复语义或用户交互/安全预览需要修改对应公共合同。

## 5. 失败处理与必要校验（RB-10）

只覆盖实际能发生且会影响授权、完整性、重复副作用或用户恢复的失败。不因“未来可能”增加统一框架或门禁。

| 真实风险/触发条件 | 所属层及处理范围 | 回归入口 |
| --- | --- | --- |
| 用户/任务授权或lease已失效 | API拒绝受影响访问/提交；bridge停止受保护新操作，不删除历史事实 | API ACL/lease测试 + Runtime取消恢复 |
| 用户文件可替换、路径穿越/链接、复制时仍写入 | bridge候选收集拒绝不安全或不稳定文件，不扩大为整站不可用 | snapshot路径/稳定性测试 |
| 外部调用发出但响应丢失 | 工具查询已有操作；bridge/API记录UNKNOWN，无证据不重发 | effect故障注入和原ID恢复 |
| 上传/commit响应丢失 | bridge查原回执/同ID同字节恢复，API幂等；不重新调用模型生成 | stage/commit HTTP及恢复测试 |
| 引擎终态事件丢失 | bridge核对原回合；不能从最终文字/候选存在推断成功 | adapter事件丢失回归 |
| 页面收到含活动内容的文件 | API下载策略、Web隔离预览，不以主站权限运行附件 | Web预览/下载回归 |

新增校验须在本任务handoff注明具体风险、条件、失败范围和测试；已有代码/测试本身不是必要性证明。不新增审批层、运行费用门禁、任意超时/大小阈值。Flow每Run600秒仍按项目明确要求执行。

## 6. 已有越界功能的处置（RB-11）

**目标不是永久兼容越界实现；是删除错误位置的实现，同时保住已要求的用户能力和真实历史事实。**

- 直接删除：本任务设计中新增的越界职责、无实际需求的框架及重复编排要求；经核实无生产者/消费者/在途引用的死分支。
- 迁移后删除：仍在提供生图、文件生成等能力的旧业务编排。先将必要算法留在工具/包，通用入口改为模型调用；同一开发候选删除旧新任务业务入口、重复编排和无引用代码，不先把功能删坏再上线补。
- 单轨删除：同候选移除旧接纳/执行/恢复实现，不等待历史引用清空。旧未完成任务不续跑、不补传/补提交；已提交成果只读，未知外部事实不改写。新方案正常恢复不受影响。
- 待核实：只有文件名或旧文档线索，未确认当前调用方的，不能直接宣称越界并整文件删除；定向核对后归入上述三类。未核实不等于允许永久保留。

当前已核对源码的删除项、接收职责、退出条件与测试见核心详设§16。删除结果要有diff、调用方和定向回归证据；“目录移动”“旧代码未被新入口调用”“文档标废弃”均不能单独作为源码删除完成。

## 7. 如何严格执行（RB-12）

不新增独立Reviewer、人工审批或门禁系统，沿现有Owner自检、handoff、测试和Flow：

1. 每个改动在现有handoff标明RB编号、职责接收层、修改路径、为何需要公共合同变化；没有明确职责归属的功能不加入本次实现。
2. 现有源码删除逐项关联核心详设§16的D编号，记录待迁移/旧执行与恢复入口已删/实现已删及证据；不能只写“完成重构”。
3. 验收必须包含：无业务技能读写文件；新增普通技能不改Web/API/bridge通用业务文件；通用外部工具无技能名分支；历史已提交成果只读、旧恢复不可达、新方案恢复不重放；原生直接执行成果可发现。
4. 静态搜索只能给定位线索，按实际调用链和运行测试判断，不能用“没有关键词”证明职责分离或把MIME适配全部当越界。
5. 文档状态、源码完成、候选验证、安装和线上业务验收分开记录。未通过对应条件不能宣称边界已落实。
6. 本规则同样适用于后续功能和外部Runtime仓任务交接。项目AGENTS和本特性spec提供入口；不修改共享技能/全局规则。
