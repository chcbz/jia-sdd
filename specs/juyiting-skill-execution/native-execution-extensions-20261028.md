## 4. E3 浏览器：独立工具边界，不是独立业务系统

- browser profile由工具在当前授权范围持有，登录秘密不挂到模型shell。按用户/授权上下文隔离；同站点不等于同用户；用户切换不复用他人登录态。
- C3提供操作上下文和受保护操作记录。页面脚本也能发网络请求，不能仅凭模型shell断网宣称浏览器出网安全。导航、重定向、子资源/新窗口与资料上传由浏览器工具按授权范围落实。
- 外部发布/提交按已有用户授权语义处理；超出范围需要真实用户决定，网页文字不能授予新权限。浏览器登录/MFA/验证码若无法自动完成，复用既有用户交互，不绕验证、不新增远程桌面系统。

## 5. E4 外部调用：按实际服务适配，不提前建通用异步平台

复用C3，在工具层封装实际需要的HTTP或特殊协议。普通请求组织优先脚本/声明配置；凭据引用是受管索引，不是模型可读秘密，也不是授权本身。

- 工具出口核对获准服务、最终地址/重定向和实际网络边界，避免内网/元数据/管理端点越权；秘密仅注入固定授权目标，不随重定向外泄。
- API保存通用操作身份、授权和事实。必要远端job引用可作不透明证据；Provider错误码、查询间隔、响应映射和轮询在具体工具，不进入API业务服务或bridge通用调度。
- 只有实际选用的服务异步返回job时，才实现该工具的提交/查询/取结果/支持时取消。`{jobId}`仅证明已受理，不是文件完成。提交effect成功与远端operation完成分别记录，语义通过现有通用操作合同扩展，不伪装成结果已可交付。
- 同一逻辑操作和Provider幂等键复用；提交响应丢失优先查询。无真实查询/幂等能力时保留UNKNOWN，不假造exactly-once。取消请求已发出不等于远端已取消。
- 新签名/SDK/特殊协议可增加工具适配器；只有新增实际授权或恢复语义才改公共合同。不按服务品牌增加任务路由。

验收：具体已接入服务的正常、失败、未知/异步恢复；核心不用预装所有可能视频服务。不存在服务需求时，不创建空壳通用调度框架。

## 6. E5 无视频技能也能制作视频

1. API接受用户视频目标，绑定实际获准输入、工具与MP4输出范围，技能集合可空。
2. bridge交付隔离环境；模型使用获准素材和FFmpeg等工具逐步编写/执行脚本。
3. 模型/工具检查时长、分辨率、音画等结果，提出最终文件；bridge通过C4交付。
4. 用户要求修改时，按当前授权使用既有成果/脚本；不是重放旧付费调用。

本地制作不依赖E4；需要生成图片可用E1，需要实际云服务才接E4。FFmpeg版本/依赖随工具制品固定，不由模型联网装软件。原媒体与转码派生文件分别有来源/hash，不伪称无损。

MP4可下载与可内联播放是两件事。现有Web inline MIME需配套播放器及服务端策略才能支持播放；未支持预览不能妨碍安全下载。API不解析剪辑脚本或决定镜头流程。

验收：空技能集合生成真实可播放视频，修改参数复用脚本，音画/时长检查、下载内容一致。没有视频专属核心分支。

## 7. E6 提取、保存、安装与复用

### 7.1 正确职责与真实来源

- Web复用会话/成果入口，选择用户有权访问的来源并触发“提取技能”，展示候选、验证结果和保存/安装状态；不自行扫描历史拼脚本。
- API固定来源引用/版本/hash及当前ACL，管理候选和私有包版本；来源来自C5已保存的真实证据。失效/删除来源明确不可用。
- bridge把获准来源交给同一原生执行机制，不新增技能提取runner或业务编排器。
- 模型从实际会话、成功脚本、依赖和成果中提取方法，生成SKILL.md、必要脚本/模板和最小fixture；工具做实际包结构、依赖和脚本验证。模型自称“已验证”不是验证事实。

### 7.2 删除强制原生配方runner设计

**v3删除v2.1“每个提取技能必须新增原生配方runner/执行manifest”的要求。** 原生模型使用普通说明/脚本包即可，不把SKILL.md强装成旧EXECUTE_SKILL动作。技能包不是执行器，更不是权限来源。

复用已有包结构、hash、版本和安装状态。确有安装依赖/requiredPermissions等现行字段缺口时，在同一管理合同补最小包元信息；不要另建一套配方协议、假平台商品或假订单。依赖退役旧runner的包需适配新工具/包合同后才能用于新任务；未适配明确不可运行，不保留旧runner兜底，不自动重放原任务。

```text
<skill-key>/
  SKILL.md
  scripts/      # 仅实际需要的可复用脚本
  assets/       # 仅非敏感、可合法随包保存的模板/资源
  tests/        # 实际需要的最小验证材料
```

依赖/权限/来源等管理信息按既有包合同或本次明确最小扩展保存，不把上述目录名当强制空目录模板。

### 7.3 私有来源是管理业务，不是bridge新权限系统

现有平台发布服务只支持管理员商品，不能冒充普通用户私有安装接口。API在既有管理体系区分平台商品来源与Owner私有包来源：私有不可变版本/hash、来源证据及必要验证记录。平台包沿既有权益，私有包沿Owner ACL与目标Agent管理权；Runtime执行安装命令和摘要校验，不自行判断商品所有权。

已确认：包归当前用户私有；默认安装当前有管理权的Agent，无管理权只保存私有候选；其他有管理权的Agent可另行安装，不自动公开。用户可与共享Agent对话不等于可管理其技能。

### 7.4 验证、保存与重复操作

模型提取→候选文件→实际验证→保存不可变私有版本→按用户选择/已确认默认安装，复用任务/管理记录表达状态，不另建工作流引擎。重复触发按现有业务幂等绑定同一来源/候选操作，改变来源或明确重新提取属于新操作。

- 来源脚本缺失：允许明确标注重建/待验证的候选，但不得声称复用了历史成功脚本。
- 脱敏：不打包凭据、登录态、原视频/图片、账号、会话正文。脱敏件拥有新hash，不能冒充原来源。检测并移除实际秘密，但不声称自动扫描能保证消除所有敏感数据。
- 候选验证与安装准备分开。缺实际依赖不标READY；需要真实外部副作用的验证必须在实际授权范围，不因提取自动获得原任务的发布/付费权限。
- 保存的脱敏包独立保留到用户删除；源资料按既有保留/删除规则处理，尊重明确隐私/权利撤销要求，不永久保留原会话。
- 后续使用在新的执行中重新固定参数、输入、工具与授权；不继承旧租约、旧job、凭据或未知操作。

验收：成功文本任务来源→提取→验证→私有保存/安装→换参数新任务复用；视频技能在E5实际成功后覆盖相同链路。无E6时基础执行不受影响。

## 8. 扩展删除/验收约束
