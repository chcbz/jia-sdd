## 1. 用户确认的产品规则（覆盖 D1/D1.1 的相反默认）

1. 每个 Agent 独立开启/关闭接外单。**开启后默认面向同平台所有已认证用户**，不做用户白名单、邀请、分组或逐单人工审批。
2. **不限制外单任务类型；Agent 能力仅用于推荐承办**，不能因为能力标签不匹配、推荐分低、未声明某技能而禁止用户选择和委派。可接单不等于一定能完成；实际执行诚实报告能力/工具/运行问题。
3. **本期不考虑交付费用**，不做报价、费用确认、余额检查、冻结、扣费或结算。后续计划按委派内容预估交付费用；模型调用费用只作成本展示，不能直接作为交付价格。

不写死 `chcbz`、吴用、林冲或固定试点 agentId。图片编辑只是测试案例，不是服务类型或接单门槛。

## 2. 业务闭环

A 创建自己的任务后，在统一“可承办 Agent”列表选择：

- **自己的 Agent**：无需开启接外单，沿用本人任务授权。
- **其他用户的 Agent**：已开启接外单，按真实身份建立本单委派。

B 的 Agent 保持自己的认证身份与模型连接；任务、会话、授权资料及成果仍属于 A，执行成功后由 A 沿现有交付链验收。每单一个 Agent，不限制一个用户同时开放多个 Agent。

## 3. 边界

| 项目 | D2 决定 |
|---|---|
| 开关 | 每个真实 Agent/binding 独立；默认关闭，开启无需配置客户名单、任务类型或费用 |
| 能力 | 推荐排序/匹配理由；不作为接单或手动选人的硬门槛 |
| 在线/忙碌 | 真实状态展示；可委派并等待现有持久调度，不假称执行已开始，不新增硬等待时限 |
| 资料 | 可没有附件；如有，必须明确授权具体文件版本；任务不因不是图片而拒绝 |
| 执行 | 复用现有议事、任务执行与技能动作；可多步、多次合法动作，不设置“一单一次模型调用”限制 |
| 返工 | 沿现有需求修订/继续办理链；变更后更新授权与执行快照，不覆盖历史或重放旧效果 |
| 费用 | 本期不报价/结算；用量和成本可独立展示，未知不能记为0，不参与派单/启动/交付/验收资格 |
| 管理 | 接外单不授予客户修改 Agent 配置、安装、凭据或查看提供方私人资料的权限 |
| 关闭 | 只停止新外单，不影响本人任务、不取消存量已接外单；逐单撤回另行处理 |

“同平台所有用户”不等于匿名访问、任意跨租户读写或公开任务数据。平台范围须由可信身份解析；登录客户端差异不能被误当成客户白名单，具体平台域映射由实施者核对现行认证契约。

## 4. 本期不做

- 交付费用预估、报价/付款/退款/分账，按模型成本计价或成本审批。
- 用户白名单、任务类型目录或按能力评分拒单的策略系统。
- 多 Agent 同单协作、竞价/抢单、评级仲裁、跨平台联邦。
- 凭接单意愿自动安装技能、配置模型、改变 Agent 归属或开放全部本地文件/工具。
- 为“支持任意任务类型”新实现所有行业工具：使用真实已有能力，缺失能力如实澄清或报告无法完成，不伪造交付。

## 5. 交付状态

D2 是明确了业务规则的开发设计，不是已上线功能。实施需固定干净三端候选、落实平台域/数据库/锁/协议细节，并取得真实账号跨用户执行、资料隔离、恢复和成果验收证据。当前所有业务验收 NOT_RUN；本轮仅修订设计及此前离线原型；重新完成生产只读页面操作，不触发产品代码实现、付费调用、构建或部署。
