## 2. 已冻结规则

1. 技能只有 POSITION（职位技能）、GENERAL（通用技能）；不预建专属技能枚举、接口或授权分支。
2. 职位与技能多对多。职位技能通常归属一个职位，但允许多个职位引用同一个技能；不复制技能包。
3. 任职后缺少的默认技能自动安装。任职生效与技能安装成功是不同事实，待安装/失败显示待就绪，失败可恢复。
4. 卸任只撤销该职位的技能授予。POSITION 仍有其他有效任职授予则保留，否则停用并安排卸载；GENERAL 安装后保留，可由有权者单独卸载。
5. GENERAL 的保留形成独立可追踪的安装保留事实，不能只保留磁盘文件却被安装资格查询判成未安装；不保留原职位的业务权限。
6. 业务权限由后端维护、校验和撤销。Runtime 负责执行/装卸，不能因持有技能文件或伪造 ID 获得权限。
7. 复用当前 Runtime 会话认证及精确 native method/path 白名单，不使用用户 OAuth 令牌执行，不添加旧 API-key fallback。
8. 新增书籍是内容数据操作；书名、作者、来源、章节、正文、版本均不进入书籍专属程序分支。不需要修改、构建、部署、重启应用。
9. 首期固定 UTF-8 文本来源；不在本轮增加 OCR、通用 PDF/EPUB 转换或任意 URL 抓取平台。已有明确来源和权限时直接执行，缺项才补全，不凭空生成原著。
10. 默认草稿；显式授予发布权限且本次任务允许 AUTO 时自动发布。保留不可变版本、历史锚点、撤任 fencing、幂等和审计。
11. 职位默认技能变化：新增时向现任者补装；移除 POSITION 时按剩余任职授予回收；移除 GENERAL 默认配置不卸载已装技能。
12. 同一 Agent 可以有多条任职；岗位名额作为配置约束，避免把旧“一馆一个编修”的事实扩展成全系统硬编码。首个业务演示只启用一个编修岗位。

## 6. 最小逻辑模型与改动边界

不预先要求创建固定数量的新表；优先复用，字段落位在 P0 通过实际 schema 冻结。

- **技能定义**：key、type、批准版本/包引用。type 不决定资源权限。
- **职位定义及技能关系**：position、skill、默认配置；职位与技能多对多；职位权限模板独立配置。
- **任职与授予来源**：真实 Agent、owner/binding、position、有效状态/版本、技能引用；用于共享职位技能去重与回收。
- **技能保留/安装状态**：期望启用、实际安装回执、错误/待重试；GENERAL 卸任后继续具有合法安装资格；POSITION 卸任先失去使用资格，文件卸载异步收敛。
- **业务授权**：动作 + 书库/作品范围 + 来源任职 + revision；作业只缩小此范围。卸任/提交在一致的授权事务边界串行。
- **典籍数据**：沿用 develop 的 work/edition/chapter/paragraph；补齐必要 publication/草稿/审计，不再另起阅读数据源。

主要改动范围：API agent/economy 的技能来源适配与 archive 服务/接口；Web 既有 Agent/Library/Archive 组件；Client 当前 Runtime/技能适配与典籍技能；Root 规格和精确候选交付记录。若无需触及 economy 实体则不重构商城；不得伪造订单换取安装能力。

## 7. 必选验收矩阵

| ID | 场景 | 通过条件 |
|---|---|---|
| A01 | 类型与多对多 | 只有两种类型；职位引用多个技能、同一技能被多个职位引用；修改配置无需改程序 |
| A02 | 任职自动安装 | 测试 Agent 被任命后发出真实安装请求，收到当前 Runtime 的有效回执才显示就绪；失败/离线不报成功 |
| A03 | 普通卸任 | 唯一来源 POSITION 被停用并实际卸载；GENERAL 安装及合法资格保留 |
| A04 | 共享职位技能 | 卸任一个职位不移除另一有效任职所需 POSITION；最后一个来源撤销才回收；重复请求幂等 |
| A05 | 职位配置变化 | 新增默认技能触发补装；删除 POSITION 按剩余授予回收；删除 GENERAL 默认项不卸载已有安装 |
| A06 | 认证与权限负例 | 普通用户不能给公共书库任意授予权限；装技能不自动获得写权限；伪造 Agent、过期 session、越界书目/任务均拒绝 |
| A07 | 撤任竞态 | Runtime 未卸载/未收到通知仍不能在撤任提交后写入/发布；先提交的发布保留；新执行不得复用旧任职授权 |
| A08 | 全新书籍零代码改动 | 从仓库外新生成/提供的固定测试底本执行；导入前后各代码仓 commit/tree/源码状态一致，无重建/重启；书架、目录、正文真实读回 |
| A09 | 两种发布模式 | DRAFT_ONLY 不上架；明确权限 + AUTO 才发布；结果依据服务端 publication 与读回，不依据模型/ACK |
| A10 | 修订与读取 | 修订生成新 edition；旧未下架版本和原书签可读；书目/版本间私人数据不串；禁止已发布正文原地改写 |
| A11 | 未决响应恢复 | 模拟响应丢失，切页/刷新后先恢复原 operation/key；不生成平行维护单；身份切换不泄露旧身份恢复信息 |
| A12 | 当前候选交付 | API 编译/相关回归/分层、Web 相关测试及 production build 通过；Runtime 定向测试与真实链路匹配同一候选；复核无未关闭阻断项 |

A08 使用至少两个结构不同的新样本（含无引首样本），书籍包位于源码仓库外；不得为样本新增书名判断或固定章数。若已有合法且明确的《三国演义》底本，可追加完整样本；没有则不能宣称完整《三国演义》已验收，不因缺该底本否定已测的通用样本能力。
