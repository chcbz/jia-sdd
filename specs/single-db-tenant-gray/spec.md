## 用户确认的模型

tenant_id 表示业务区域，不表示 IT 灰度部署。例如 0 为华南区、1 为华南测试区、2 为华北区；名称为设计示例，现场归属待审核。多个区域共用现有 MySQL database 和业务表，不新增长期测试区域数据库。

client_id 是 OAuth 应用身份；一个 client 可以获准进入多个区域，一个区域可以允许多个 client。用户权限来自区域成员/角色，不能只凭应用登记获得数据权限。部署环境、版本、实例和工作器代次为第三个独立维度。

一套 Web/API 可承载多个区域；本地入口默认进入 1，本地实例可额外限定只服务 1。选择区域必须经过服务端授权并签发单区域 token，不改 header 就直接切区。

## 目标和范围

- 隔离会话、资料、Agent、任务、账本、事件、缓存、搜索、存储和后台处理。
- 已授权的 Web/移动端在同区域、同数据域、同资源权限下可访问同一业务对象。
- 现有 client-scoped 数据须先完成归属、隐私、唯一键与历史幂等审核，不能直接去掉 client 谓词。
- TEST 区域默认禁真实支付、生产托管等副作用；能力由区域策略决定，不硬编码 tenant=1。
- 区域暂停、区域成员撤销、停止本地部署分别控制，不相互混同。
- 中央账号安全共享，区域管理员不能修改全局账号安全状态。

覆盖聚义厅及可达依赖：OAuth/common、agent、chat/archive、workspace、task、economy、文件/搜索/后台工作器和相关前端。

## 非目标与约束

不提供通用跨区报表、自动复制正式私有数据、跨区资金转移或任意切租户权限。业务测试区域不隔离共享 schema/容量/故障域，不能替代技术测试环境。

0 不是公共租户。旧 tenant=owner 和 0/1/2 占用须审核；新区域写入前所有正式实例和工作器必须先完成严格隔离基线。新数据存在后不可回退至无范围过滤的版本。
