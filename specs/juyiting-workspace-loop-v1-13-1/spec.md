# 1.13.1 悬赏—议事—工作空间完整闭环

日期：2026-09-19。状态：**draft / 方案已编制，未开始本版实现、调用 Provider 或发布**。版本由用户指定为 **1.13.1**；它是 1.13.0 原定业务闭环的补齐，不因 patch 编号把工程规模视为小改动。

## 1. 目标与完成定义

**工作空间管文件，厅内议事管需求沟通，悬赏榜管任务与正式交付；三者使用同一份文件版本、执行记录和成果事实。** 用户不需要下载后重新上传、不需要手填内部 ID、不需要开发者搬文件或补成功状态。

完整路径：上传/选资料 → 关联悬赏或私人议事 → 自然语言提出需求 → 明确 Agent 和本轮授权 → 实际处理 → 自动归档 → 三处预览下载 → 指定成果继续修改 → 保留历史 → 任务 owner 验收。

无悬赏仍可私下议事和执行；私人资料不因进入聚义厅自动公开。保存、关联、授权、执行、交付、验收是不同动作。

## 3. 用户功能范围

- **BR01 统一选材**：三个入口共用文件选择器；上传、搜索、类型筛选、预览、明确版本、多文件选择；“上传新文件”直接保存到个人空间。
- **BR02 双向任务关联**：空间中“用于悬赏”；悬赏中“从工作空间添加资料”；INPUT/REFERENCE 分类，支持多任务复用，解除关联不删除文件。
- **BR03 议事附件**：消息区展示固定版本附件卡、已选执行资料、目标 Agent、所属任务；未发送草稿可移除；发送前确认授权范围。
- **BR04 会话与任务绑定**：从悬赏“进入议事”进入该任务的授权会话；空间“交给 Agent”进入私人议事；私人讨论可由用户明确“创建悬赏/关联已有悬赏”，仅带选中的资料，不自动复制私聊历史或开放旧授权。
- **BR05 一次真实执行**：一条文件请求只建立一次执行，不同时通过普通聊天和文件通道重复调用模型；排队、处理中、保存中、结果待确认、失败、可领取如实显示。
- **BR06 成果统一**：输出一次保存，空间、任务、议事引用同一版本和内容摘要；三处可预览/下载，展示 Agent、源版本、任务/会话、生成时间；任务成果进入正式交付后才显示待验收。
- **BR07 连续修改**：成果卡“继续修改”固定源版本和上下文；自然语言提出下一轮要求；新版本保留旧版，两个并发修改不得覆盖彼此。
- **BR08 统一验收**：owner 在悬赏或对应议事决定“验收通过/要求修改”；空间展示同一个正式结果及原任务入口。私人结果只“确认采用/继续修改”，不得伪造悬赏完成或结算。
- **BR09 可恢复**：刷新/退出再登录后找回附件、执行和成果；Agent 离线不影响已存文件领取；未知结果先查询，不重复生成收费。
- **BR10 安全及费用**：仅本人任务和自有/已授权 Agent；输入授权固定到执行、Agent、版本；群议事不自动授权所有参与者；显示实际 Provider/外发/费用边界，未知不写免费。
- **BR11 原 MVP 格式补齐**：生图、原图编辑、PPT 新建与外部 PPT 修改、Word、Excel、常规文本 PDF 修改逐项真实通过；图片对照、PPT/PDF 逐页预览、Excel 分工作表预览；保留文件原件和约定内容。

## 4. 非目标与边界

不建设在线 Office/图片编辑器、共享网盘、任意跨用户外单、模型智力值、市场/钱包结算、多 Agent 自动拆解或语音。模型/费用/接单/技能治理仍为 1.14.0；本版的真实费用告知、owner 隔离不后移。

格式边界沿用原约定：PNG/JPEG、DOCX/XLSX/PPTX、常规文本 PDF；旧 Office、宏执行、加密破解、扫描 OCR 全覆盖及复杂版式无损转换不承诺。不能以边界为由跳过常规格式。PDF 重建导致排版变化要先说明；PPT 不能以文字大纲/截图/PDF 替代可编辑 PPTX。

## 5. 验收与发布规则

- A 类：不调用 Provider 的存储、关联、权限、幂等、状态与 UI 集成自动化测试。
- B 类：明确账户/额度/外发授权后，真实 runtime 和真实工具逐格式端到端；生产替代数据、假成功、开发者代上传不能作证。
- C 类：精确 API/Web/必要 runtime 制品验证、线上三入口回归与用户验收。
- **A、B、C 均完成才宣布本版完整闭环完成。** 授权缺失时可推进 A 类与代码，不把 B 类跳过标 PASS，不把未完候选称为完整发布。
- 无独立 Reviewer，实施 Owner 自检；正式执行与发布遵守 AGENTS.md 最新授权/调度策略。方案不授权生产 DML、扣费或部署副本直接改写。
