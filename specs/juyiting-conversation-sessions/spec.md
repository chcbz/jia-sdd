# 聚义厅业务会话与 Codex 会话隔离

<!-- CYF-CURRENT-CONTRACT-20261107 -->
## 现行规格（2026-11-07）

**本专题：业务会话与原生thread的适用映射。**

### 责任与业务流程
API定义业务会话身份与范围；bridge持有按Agent/隔离边界的原生thread映射；Web切换业务会话。

首次发送创建→同一Agent在允许边界续接→显式切换隔离→历史分页继续。

### 明确边界
同一业务会话可涉及多个Agent的原生thread，不作全局严格1:1承诺；材料/工具合同变化不机械新建thread，必要更换必须说明具体隔离/能力原因。

通用开发/验证约束：[统一开发约束](../architecture-convergence/development-principles.md)。业务字段、状态、错误及测试细节仍由本专题下文和详设维护。

### 验收落点
同会话两轮原文记忆、不同会话/身份无串线、重启后映射恢复、材料输入不丢历史、20条历史分页。

**入口：** [需求](spec.md) · [设计](design.md) · [实施](tasks.md) · [验收](acceptance.md)

> 文档收口（2026-10-23）：保留业务会话到各Agent会话隔离合同；旧Reviewer/分配安排不是当前执行规则。 本轮仅核对文档归属与覆盖，不重新验证源码/上线；执行规则以根AGENTS为准。


用户授权：采用页面业务会话驱动 Agent 会话；本次最小闭环为严格 session 映射与聚义厅历史查看/切换。

- 新话头第一次发送时才创建业务/Codex 会话；新会话不得恢复无关历史。
- 同一业务会话中每个 Agent 分别续接自己的 Codex session。
- 用户可查看、切换当前聊天范围内的历史业务会话并继续聊天。
- 不删除历史、不迁移旧记录、不增加自动清理、长期记忆系统或后端权限模型。
- 历史列表不是 Codex 内部工具日志查看器；旧错误映射可能含混合上下文，本次不声称恢复被混合的历史。
