# 点将册：技能、本领展示与响应式布局

2026-10-23文档收口。当前设计承接D4，历史1.16.8/1.16.9的限定范围发布见验收入口；不再沿用“产品未开始/未发布”的旧状态，不声称今日线上复验。

## 目标

- 移动端名册→详情，返回保留列表上下文，密议/点将底部常驻；桌面约43/57分栏、独立滚动。
- 明确展示实际“技能”与原“本领”，安装核验与运行就绪分开，不把就绪当任务授权。
- 详情及刷新读取当前owner单Agent最新已入库信息；不触发Runtime扫描或重注册。
- 原接口保留本领投影；新只读GET复用原权威，不增表、不复制回退、不改派单。

## 当前交付入口

[详设](design.md) · [工作与回归](tasks.md) · [验收与证据](acceptance.md)。原型认可及指纹保留 [ui-review.md](ui-review.md)，实际过程保留handoff/integration/evidence；原型不等于产品通过。

非目标：技能交易/安装、本领编辑、Runtime重启、DB迁移、派单算法；后续接外单执行权限以外单特性合同为准，不从名册就绪推导任务授权。当前原型唯一入口是 `../../web/prototypes/juyiting/`。


| 问题 | 确定方案 | 达成标准 |
|---|---|---|
| 手机先滚过名册才看到详情 | ≤720px采用全屏名册→全屏详情，不上下堆叠 | 点选立即看到该Agent详情；“← 名册”返回原筛选和滚动位置 |
| 密议按钮在长内容底部 | 详情采用固定外框，中间内容滚动，底部动作独立常驻 | 320px窄屏、390×480短屏、长技能/本领均不需滚到底找按钮 |
| 桌面详情太窄、内容互相挤压 | >720px左右约43%/57%，两区独立滚动 | 名册可浏览，详情底部动作不随内容滚走 |
| 标签被误认为安装技能 | 明确“技能”“本领”两区 | 技能有版本、安装核验和运行状态；本领保留原标签 |
| 刷新含义不明确 | 单Agent只读聚合GET，读取最新已入库记录 | 不重新扫描、不重注册、不影响正在执行的任务 |
| 多接口都有本领容易重复实现 | 保留旧接口各自投影；新GET复用原权威投影 | 不删旧字段、不新增本领表、不复制回退逻辑 |

保持纸色、朱砂标签、头像和原按钮视觉体系，不重新换肤、不增加字体/依赖。运行就绪不等于任务已获调用授权。无任务时保留密议；待处理任务时保留密议与点将并议事，原busy/资格判断不变。
