### 哪个版本算可用，哪个算 MVP？

- **1.10.0：文件管理可用，但不是 Agent 交付 MVP。**
- **1.11.0：第一个能替用户实际处理文件的受控试用版。** 若只做完关联，没有真实 Word 修改交付，不能宣布此版目标完成。
- **1.12.0：达到最初“生图 / 改图 / 可下载 PPT”的实用目标。** 仍不得声称 Excel/PDF 等全部范围已完成。
- **1.13.0：按用户最新扩展后的范围，完整 MVP 交付点。** 必须实际验收通过，版本号本身不构成完成证据。

## 2. 1.10.0：个人工作空间基础版

### 本版范围

1. “我的工作空间”入口、全部文件/我的上传/回收站视图；界面按已实现能力提供动作，不添加假的 Agent 操作按钮。
2. 图片、`.docx/.xlsx/.pptx/.pdf` 等已声明格式的真实上传与私有保存，不依赖悬赏。文件允许保存不等于已支持 Agent 读取或修改。
3. 按名称搜索、按类型筛选、重命名、上传原件新版本、版本查看、精确下载；下载名称/扩展名与实际内容一致。
4. 图片/文本复用已有只读预览；Office/PDF 本版可先下载查看，明确标注其预览/编辑尚未开放，不能伪报支持。
5. 回收站/恢复、原件不静默覆盖；不提供永久清除或未经确认的自动清理策略。
6. owner-scoped 输入存储、元数据、幂等、版本 CAS、身份切换清理与跨用户权限隔离。

### 本版不做

悬赏选材、Agent 自动读取/回传、新文档渲染工具、在线编辑器、目录树、同步盘、团队共享、模型智力值/市场。保留现有成果入口，不承诺本版完成新成果自动归档。

### 验收与依赖

- 用户上传一个真实文件，刷新/重新登录后仍能找到并下载相同内容；上传下一版后前版仍可取。
- 同 key 重试不重复创建；双标签页并发重命名/上传版本不静默覆盖；回收站恢复不丢字节。
- 第二身份不能读列表、内容、预览或修改原用户文件。
- 新 owner 存储不传空 taskId 或伪造悬赏；不放宽现有 task artifact 的隔离范围。
- **可独立推进，不依赖付费模型或客户端改造。** 实施前完成当前 C1-A 的迁移/存储设计核对；既有 SDD 整体仍 draft，不因排期自动转 ready。

工作包：**C1-A + C4 基础空间界面 + C5 本版验收**。

实施准备已细化为 W00–W09，见 `specs/juyiting-creative-delivery-mvp/v1-10-implementation-plan.md`；本版 30 项验收全部未执行。工程投入初估 **72–118 人时（含 8–16 人时风险准备）**；按 API/Web 两线、各每天 6 小时有效投入的容量假设，约 **10–16 个工作日**，另计资源等待与发布窗口。此为工程判断，不是 Agent 耗时测量或确定上线承诺。

## 3. 1.11.0：悬赏关联与首个 Agent 闭环

### 本版范围

1. 悬赏选择空间文件，按 INPUT/REFERENCE/OUTPUT 查看材料与成果；同一原件可用于多条本人任务，各自固定版本。
2. 既有 artifact 在空间统一展示，不复制第二份文件或第二套验收状态；目录投影重放保留用户显示名/回收站管理状态。
3. 对话“上传/从空间选择 → 交给明确 Agent”；不发布悬赏也能执行，内部 task/run 在服务端隔离，不能泄露成公开 OPEN 悬赏。
4. 最小 runtime 文件桥接：领取被授权输入、指定输出上传、持久回执、断线恢复和源版本绑定。
5. **以普通 Word 为首个完整场景**：读取 `.docx`、按要求修改段落/基础表格、保留约定内容，输出真实 `.docx`，只读预览和下载；第二轮对话修改保留第一轮成果。
6. 执行进度、Agent/文件来源、费用及资料外发说明、可领取/待确认/已验收分开；默认仅 owner 的任务。

### 发布前必须明确

- 客户端最小改造范围与准确源码；不得直接改部署副本。当前客户端源/部署字节不一致，先归拢真实基线。
- 内部执行可见性、初始 lease、native 路由精确授权与 producer 适配；不能借用户 JWT 假扮 Agent，也不能把 E05 重派 lease 当作普通初始执行。
- 可用 Word 工具、预览路径、真实 Provider/账户/额度及资料外发授权。

### 验收

从真实 Word 原件完成“选择 → 执行 → 自动入库 → 预览/下载 → 对话修改 → 新版 → 确认”；Agent 只可读取所选文件，不可枚举整个空间；刷新、Agent 离线后仍可领取；回传失败优先恢复同一文件，不自动重复生成/收费。悬赏关联与无悬赏两条入口均需通过。

工作包：**C1-B/C/D + C6 Word 切片 + C4 对话/任务接线 + C5 本版验收**。技术实现可以按切片交付，但只完成关联不能替代本版真实 Agent 闭环。

## 4. 1.12.0：图片与 PPT 实用交付

### 本版范围

- 生图：需求、用途、风格/比例 → 实际图片 → 预览/下载。
- 改图：上传或选择原图版本 → 对话说明修改和保留项 → 实际使用原图编辑 → 对照、新版与原件均可下载。
- PPT 生成：用户文字、图片及已支持读取的资料 → 组织内容、排版 → 正常打开、正文可编辑的 `.pptx`；不以大纲/PDF/HTML/整页截图代替。
- 已有 PPT 修改：上传非本系统生成的 `.pptx`，通过 Agent 修改指定页、内容/风格，交付新版；逐页预览。
- 全部结果自动进入工作空间，保留会话/任务/Agent/源文件版本关系；继续修改仍通过对话，不做在线画布或幻灯片编辑器。

### 验收与边界

生图、原图修改、PPT 新建、外部 PPT 修改分别留真实工具和成果证据；原图保留项、PPT 关键数据和排版由实际任务核对。PPT 正文可编辑指下载后的办公软件能力。工具/额度未授权时只标未开放，不显示成功；PPT 不默认逐页付费配图。

本版 PPT 可用文字、图片、Word 等已支持资料；Excel/PDF 若尚未接通读取，必须提示，不因上传成功就假定 Agent 已读懂。保持 1.11 Word 场景回归。

工作包：**C2 + C3 + C6 PPT 切片 + C4 图片/逐页预览 + C5 本版验收**。图片与 PPT 在合同稳定、路径不重叠时可并行，不强制多 Agent。

## 5. 1.13.0：Excel / PDF 扩展与完整 MVP

### 本版范围

1. Excel `.xlsx`：读取工作表/数据/公式，按指令修改和整理，输出新版，按工作表预览。核对未修改内容及公式依赖，重算状态诚实，不把缓存值当重算结果。
2. 常规文本型 PDF：读取并完成约定的真实内容/页面修改，输出新 PDF，逐页预览；需要转换重建、可能改变排版时执行前说明并取得确认。只返回摘要不算修改交付。
3. 已支持的 Excel/PDF 内容可作为制作 PPT 等任务的资料，选择多个来源时版本与授权明确。
4. 统一回归空间、悬赏/对话两入口、所有格式、版本派生、原件保留、恢复、权限、预览与下载。
5. 记录用户真实采用与修改反馈，不编造节省时间或使用量。

### 首版明确不承诺

任意旧格式 `.doc/.xls/.ppt`、扫描 PDF/OCR 全覆盖、密码破解、宏/脚本执行、复杂嵌入对象和所有排版无损修改。支持矩阵按已验证样例说明，不支持时给明确下一步。该边界是首版文件处理范围，不得用它掩盖常规 Word/Excel/PPT/PDF 未实现。

### 完整 MVP 完成定义

**用户可独立管理上传和 Agent 成果；选择文件/描述需求，经真实 Agent 生成或修改；成果自动保存、可预览下载、能再次对话修改；悬赏关联可选；原件/版本/来源可追溯，刷新或 Agent 离线后仍可取件；所有已承诺格式逐项通过。**

只通过演示、文件上传、聊天文本或某一种格式，不得宣布整体完成。

工作包：**C6 Excel/PDF 切片 + C4 预览与多资料选择 + C5 全范围验收**。

## 6. 原四条需求怎样融入

| 原始需求 | 1.10–1.13 必需部分 | 1.14 完整治理 |
| --- | --- | --- |
| 显示模型，按费用定义智力值 | 有可信来源才显示实际 Agent/工具/模型，未知不伪造 | 模型来源、路由/价目表与计费智力值；分值不等于能力或权限 |
| 揭榜根据模型计算费用 | 真调用前说明是否收费、谁承担、额度与外发范围；未知不显示免费 | 版本化参考成本估算与预算展示；实际结算仍属于资金域 |
| 是否接外单，默认仅 owner | 从第一版就做 owner 隔离；1.11 起的 Agent 执行默认仅本人 | 显式 opt-in、符合合同的外部邀请与接受，不能直接开放市场 |
| 可交付技能与自动总结 | 每个开放场景必须有实际可用能力说明和交付证据 | 从已验收成果生成候选，owner 确认，再形成可信技能档案 |

`juyiting-agent-model-governance` 保留原 ready 设计，仅调整规划版本到 **1.14.0**；未修改冻结的经济交易合同，不因后移而推迟基础安全和费用诚实。

## 7. 执行、测试与发布安排

- **实施顺序**：先 1.10 存储/权限/文件库，再 1.11 实际 Agent 闭环，再扩 1.12 图片/PPT、1.13 Excel/PDF。各版自己拥有明确可用结果，不把未实现按钮或 mock 当版本交付。
- 同一版内可按不重叠路径准备前后端；Owner 自检，不创建独立 Reviewer。不要求全套后续版本方案完美后才实现 1.10，但身份、事务、迁移的本版合同须先明确。
- **目前没有承诺日历上线日期。** 1.10 已有分项工作量与条件周期估算；明确实施启动/资源，并完成 W00 和首个真实上传下载切片后再校准。1.11 以后还受真实工具与客户端授权影响，先记录复杂度和待核项，不编造确定天数。
- 普通缺陷用对应已发布 minor 的 patch 修复；本表的新功能使用 minor 版本。实际发布前核对组件版本与现有分支，不覆盖其他任务或已冻结的 release 分支。
- 每次发布有 exact source/tree、实际测试、制品 hash、安装/健康与业务回读。正式验证沿届时有效 Flow 政策或云效不可用期间的用户本地发布例外；Gradle 经 orchestrator 串行。
- 发布时间遵守既有 Asia/Shanghai 版本化发布安排；此计划不授权即时部署、不更改流水线/生产配置，也不自动授予付费、资料外发或客户端修改权限。
- 真实故障及时处理；慢请求只观测，不因任意秒数、包大小或无依据资源门槛取消正常执行。身份、幂等、事务、锁归属和用户取消保留。
