# 1.9.0 版本建议：协作运行看板与异常定位（只读首包）

日期：2026-09-17。状态：release candidate ready / 1.8+1.9已合develop并冻结release/1.9.0；未部署生产，等待用户安排。

## 来源与版本边界

- 从原平台增强待办抽取G07只读看板首包，并增加该增量必需的G01/G03相关回归；不是宣称整个M5/G07完成。
- 1.8.0为导航小版本，已冻结但未部署。新版本以已验证develop API `0b5cfe8c`、Web `7099b176`为起点，开工前再次fetch核对漂移；绝不改写release/1.8.0。
- 已核实D09存在受特权保护的 `/agent/internal/command-operations/metrics`、`/dlq`、`/audit` GET接口；当前Web未发现这些接口的使用入口。因此优先接现有只读能力，而不是重写投递状态机。
- API受 `agent.rabbit-operations.read-enabled` 与 `agent-command-ops-read` 约束；普通聚义厅权限不能进入。是否线上启用/谁有读取权限必须独立确认，不为让页面可用而发放权限或绕过原鉴权。

## 拟交付

1. 有权限账号从个人中心进入运行看板；无权限明确不可用，不显示跨scope聚合。
2. 展示现有接口实际支持的积压、投递/回执与失败指标；准确标明观测时间、字段含义及未知状态，不把命令投递成功称为Agent任务完成。
3. 失败/死信列表：关联任务、目标Agent、尝试次数、最后更新时间及现有状态；只有确有安全原因码来源才显示原因，不推测故障根因。
4. 只读操作审计：查看已有操作记录和结果；不新增重投、重发、终止、恢复或状态修改按钮。
5. 读取失败显示错误与重试，保留旧数据时标注过期；身份切换清空旧数据并拒收迟到响应，分页/刷新不得产生重复业务动作。

## 实施拆包

- P0盘点与合同：准确冻结现有DTO、权限/开关、分页、错误及入口发现合同；明确无需新表。缺失最小能力发现合同再按最小新增只读方式设计。
- P1 API Owner：仅必要的只读契约/权限安全投影、相关ACL/错误回归；不扩大ops授权。
- P2 Web Owner：合同冻结后可与API并行，实现看板、列表、审计和入口；不与1.8候选worktree互写。
- P3集成Owner：跨身份/无权限/禁用/错误/分页/刷新回归及生产bundle浏览器验证，合develop、冻结release/1.9.0；不创建独立Reviewer。
- Gradle与重型验证仍按实际资源串行；本地构建继续沿用用户云效不可用期间的授权，不自动部署生产。

初步净执行4–8小时墙钟（合同约1小时、实现并行2–4小时、相关验证/首轮修复1–3小时，按重叠安排）；资源排队另列。首次合同盘点后更新区间，不把此估算当今晚必定发布承诺。若接口缺少所需事实，删减到有可靠来源的只读首包，不用猜测数据填充UI。
