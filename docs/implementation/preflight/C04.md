## Frozen browser authorization subject

```text
(JWT.jiacn, JWT.client_id, path.taskId, query.actorAgentId)
```

The human JWT authenticates owner/client scope; task authorization is performed for the explicitly nominated canonical owned Agent. `actorAgentId` is required. Do not use username fallback, default tenant/client values, selected UI state, legacy assigned/coordinator projections, aliases, persona/runtime display names, or WebSocket identity.

Identifiers are byte-exact and bounded by schema lengths. Reject blank, padded, control-character or non-canonical inputs; never trim, case-fold or Unicode-normalize.

Inside the snapshot transaction require:

1. active canonical identity and active owner/client binding for `actorAgentId`;
2. non-built-in Agent;
3. exact scoped task row;
4. exact canonical member row for that Agent;
5. member status in `accepted | working | blocked | done | failed`.

`invited | rejected | left`, unknown states, foreign/inactive identity, metadata coordinator without membership and nonexistent task all return the same generic 404 behavior. Artifact projection applies B06 visibility only after this stricter outer membership gate succeeds.

## Snapshot contract

Use workspace-specific DTOs and one explicit outer `READ ONLY, REPEATABLE READ, REQUIRED` transaction. No locks, writes, lazy reads, thread creation, broker publication or `REQUIRES_NEW`.

Snapshot contains:

- task
- members
- workItems
- openRequests (`open | acknowledged` only)
- visible recentArtifacts + `recentArtifactsTruncated`
- nullable canonical `conversationId`
- bounded `recentEvents` + `timelineTruncated`
- exact decimal-string `currentVersion`

All aggregate/event BIGINT versions cross HTTP as decimal strings. Never expose scope columns, DB primary keys, lease tokens, artifact content/storage URI/arbitrary metadata, raw `event_json`, authentication or binding rows.

If Agent and Chat reads cannot demonstrably share one physical datasource/transaction, omit `conversationId` from the atomic contract instead of claiming false consistency.

## Timeline bootstrap

- Fixed `RECENT_EVENT_LIMIT = 100`; no caller-controlled bootstrap limit.
- Read an ascending contiguous suffix ending exactly at snapshot `currentVersion`.
- `currentVersion=0` returns empty/not truncated.
- `timelineTruncated=false` only when first returned version is `1`; otherwise true.
- Middle gap, duplicate, wrong scope, corrupt/unknown event, or missing final version fails the snapshot.
- ACL-hidden artifact events retain continuity as `{version: "N", redacted: true}` and expose no event ID/type/actor/aggregate/payload/time.
- `recentEvents` is display bootstrap only; do not replay it to reconstruct snapshot state.

## Limits

- Complete members/workItems/openRequests: query 500 as overflow sentinel, accept at most 499, fail rather than truncate.
- Visible recentArtifacts: return 100, query 101 visible rows for truncation.
- Maximum serialized response: 4 MiB UTF-8; fail rather than silently omit.
- Deterministic ordering is required for every collection.

## Error/side-channel behavior

- invalid authentication: resource-server 401
- missing required JWT scope claims: 403
- malformed identifier: 400
- absent/foreign/unauthorized/inactive/corrupt ACL subject: identical generic 404
- authorized-scope integrity failure, gap or overflow: generic 503
- success and errors: `Cache-Control: private, no-store`

Logs contain only bounded reason codes and trace IDs, never task/artifact content or credentials.

## Required acceptance probes

- byte-exact owner/client/task/actor isolation and all member-status rows
- coordinator without member row denied
- artifact visibility and redacted-event continuity
- event versions above `2^53` remain exact strings
- V=0/1/100/101 timeline boundaries and middle-gap failure
- 499/500 complete-collection overflow and 100/101 artifact truncation
- concurrent latch tests prove task/member/work-item/artifact/thread mutation and event/currentVersion appear entirely before or after the snapshot
- participating Agent/Chat mappers use one physical transaction
- no write, lock, broker or conversation creation occurs
