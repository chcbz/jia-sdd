## Current call chain and defect

```text
POST /juyiting/actions/{intentId}/dispatch
  -> JuyitingActionController
  -> HallActionDispatcher.dispatch
  -> online: AgentWebSocketHandler direct send
  -> offline/send failure: JVM ConcurrentHashMap<agentId,List<HallAgentMailboxItem>>

GET /juyiting/agents/{agentId}/mailbox
  -> HallActionDispatcher.mailbox
  -> mutable in-process list keyed only by agentId
```

The list is lost on API restart, is not exact tenant/client/task scoped, has no ACK/drain/reissue, and may be concurrently mutated through a non-thread-safe `ArrayList`. D08 removes its reliable-fact role.

## Frozen target flow

```text
trusted HTTP scope + explicit task + explicit target Agent
  -> producer-side exact ACL
  -> canonical Hall command draft
  -> REQUIRED MySQL: command_delivery + outbox
  -> commit
  -> D03 Rabbit relay
  -> D05 exact WS dispatch / WAITING_AGENT
  -> D06 ACK or reconnect reissue
```

- DB delivery is the only mailbox fact when the exact scope is in M3 dispatch mode.
- WebSocket and Rabbit publish stay outside the producer transaction.
- `SENT` is not `RECEIVED`.
- Offline completion is `WAITING_AGENT + next_retry_at`, then Rabbit ACK; no hot loop.
- Reissue uses a new message/event ID and the original command ID.

## Canonical command extension

D02 currently accepts only `TASK_INVITE`, while Hall actions map to the existing Protocol v1 command allowlist:

- `TASK_INVITE`
- `WORK_ITEM_EXECUTE`
- `WORK_ITEM_RESUME`
- `WORK_ITEM_CANCEL`
- `REQUEST_RESPOND`
- `REVIEW_EXECUTE`
- `CONTEXT_REFRESH`

D08 must extend the canonical draft/codec without changing existing TASK_INVITE bytes. Use a typed or discriminated bounded payload; do not persist an arbitrary map.

Hall payload allowlist:

- required: `actionType`, `instruction`, `conversationType=juyiting`;
- optional: `reason`, `conversationId`, `triggerEventId`, `autonomyLevel`, `requiresApproval`;
- context: only explicitly enumerated scalar or bounded string-list fields needed by accepted Hall behavior;
- forbidden: credentials/auth headers, private keys, full unbounded chat transcripts, nested arbitrary objects, unknown fields and identity fields that conflict with the envelope.

Command identity:

```text
commandId = cmd_hall_action_ + sha256(
  tenantId NUL clientId NUL taskId NUL targetAgentId NUL intentId NUL commandType)
```

- `intentId` is required, byte-exact and bounded.
- Same command ID + same canonical bytes is idempotent.
- Same command ID + changed payload/scope/type is a conflict with zero overwrite.
- `correlationId = taskId`; `causationId = triggerEventId` when present, otherwise the exact intent ID.
- TTL is fixed per frozen command class; no caller-controlled expiry.

## ACL and query contract

Before persistence, require exact trusted tenant/client scope, task membership/access and explicit target Agent authorization. Do not depend on selected UI state, first roster entry, coordinator fallback or `/agent/active`.

The mailbox query becomes a bounded delivery projection scoped by trusted tenant/client plus explicit target Agent, with optional task filter and stable pagination. It may expose business-safe fields such as command/intent reference, task, command type, status and timestamps. It must not expose raw payload bytes, hashes, lease owner/token, publisher internals, replay approval metadata, or cross-scope existence.

Terminal, expired and superseded rows require explicit inclusion rules; default results should be bounded and operationally useful rather than an unbounded audit dump.

## Flag and compatibility contract

- All M3 flags off: existing M1 behavior remains available, no M3 writer/query bean requirement, no M3 table access and no Rabbit side effect.
- `DB_SHADOW`: durable capture remains non-dispatchable and API wording must not claim delivery.
- `DISPATCH_CANARY` or later: only the exact allowlisted scope uses durable transport; the same command must not also take legacy direct-send/mailbox path.
- Rollback disables durable dispatch and returns to approved M1 compatibility behavior; it does not delete or rewrite durable rows and does not restore the JVM mailbox as a reliable fact source.
