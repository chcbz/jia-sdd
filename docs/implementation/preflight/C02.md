## Frozen boundary

C02 is a transaction-commit-local process wakeup mechanism. MySQL `agent_task_event` and `current_event_version` remain the only fact source. C02 does not implement replay, SSE, ACL, outbox, RabbitMQ, cross-instance fan-out, event caching, or payload delivery.

```text
AgentTaskEventWriterImpl.append()
  insert durable event
  -> CAS current_event_version
  -> enqueue immutable scope/version wakeup in the current physical transaction
  -> commit: publish in append order
  -> rollback: publish nothing
```

## Required behavior

1. Exact key is `(tenantId, clientId, taskId)`; reject blank, padded or control-character IDs and never trim/case-fold/Unicode-normalize.
2. Broker publishes only immutable `eventVersion` wakeups; no `event_json`.
3. `directBestEffort` semantics: no subscriber means drop; slow subscriber may miss wakeups; blind publish must not create a channel.
4. Last subscriber cleanup must be identity-safe and exactly once.
5. `enqueue` requires both an actual transaction and active synchronization; otherwise fail closed.
6. One ordered transaction-local buffer and one synchronization per physical transaction.
7. REQUIRED nesting shares the buffer and REQUIRES_NEW is independent. Savepoint handling is rollback-safe: one lazily registered synchronization checkpoints buffer positions for observed savepoints; rollback to a known savepoint truncates to its checkpoint, rollback to an unknown pre-registration savepoint clears the current buffer, and later valid outer enqueues may continue. A savepoint already released or rolled back before first enqueue leaves no public Spring 7.0.2 trace and does not invalidate later events.
8. `afterCommit` broker failures are logged/metriced and do not turn a committed DB mutation into an apparent business failure.
9. Shutdown is bounded and cancellation-based: broker close must detach and cancel internal subscription leases even when a subscriber callback blocks forever; shutdown completion delivery is best effort, while durable MySQL replay remains authoritative.
10. Only `AgentTaskEventWriterImpl.append()` integrates publication; do not modify every C01B caller.
11. No RabbitMQ dependencies, topology, listener, tests, or production changes.

## Minimum tests

- byte-exact scope isolation including case and composed/decomposed Unicode
- invalid identity fail closed
- no-subscriber publish does not allocate
- fast/slow subscriber and backpressure behavior
- cancel/complete/error/final-subscriber cleanup and publish/dispose race
- commit visibility, outer rollback, multiple appends/order, append failure, no-transaction registration failure
- unrelated transactions register no C02 synchronization; an active publisher transaction has exactly one lazy synchronization
- known savepoint rollback truncation, unknown pre-registration savepoint rollback conservative clear, release/rollback before first enqueue followed by valid outer events, REQUIRED and REQUIRES_NEW isolation
- afterCommit broker failure preserves DB commit and drains later wakeups
- existing task writer transaction tests remain passing
