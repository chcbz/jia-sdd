## Frozen invariants

- Owner scope is server-derived exact `(tenantId, clientId, ownerJiacn)`; missing claim fails closed with zero writes.
- Progress is one row per owner scope + edition; bookmark/note IDs are lowercase UUID; unauthorized and absent resources both return 404.
- Every mutation requires valid ASCII `Idempotency-Key`, exact request hash and same-transaction replay record.
- Resource versions are canonical decimal strings, create at expected 0, CAS updates advance by one, Long.MAX_VALUE fails closed.
- DELETE requires exact `If-Match: "vN"`, creates/advances a DELETED tombstone, and replay returns the original response.
- Locations/anchors must point to authoritative active edition blocks/paragraphs; completion only at the final byte of chapter 120.
- Notes are private plain text, at most 20,000 UTF-8 bytes; no Agent prompt/search coupling.
- No Elasticsearch dependency; existing content and `/chat/library/search` behavior remain unchanged.

## Architecture packet (binding implementation defaults)

- Add a separate additive H03 schema/catalog/initializer for `archive_reader_progress`, `archive_bookmark`, `archive_note`, `archive_idempotency`; do not enlarge H02's four-table all-or-none set.
- Current identity mapping: direct JWT only; `(tenantId, clientId, ownerJiacn)=(jiacn, client_id, jiacn)`. Persist and predicate all three exact binary values; never use `tenant_id='0'`, `sub`, `aud`, username or `EsContextHolder` fallback.
- Progress key: exact scope + edition. States `IN_PROGRESS|COMPLETED`; completion monotonic and only at authoritative final byte of chapter 120.
- Bookmark/note IDs: canonical lowercase UUID. States `ACTIVE->DELETED`; tombstones terminal and clear private/location payload while retaining scope/id/edition/version/timestamps.
- Wire versions/cursors are canonical decimal strings through `Long.MAX_VALUE`; create expected version `"0"`; each success increments once; exhaustion is zero-write 409.
- DELETE requires exact single `If-Match: "vN"`; no weak/wildcard/list/OWS form.
- Mutations require exact visible-ASCII `Idempotency-Key` 1..128 bytes. Scope is exact owner + method + validated canonical path + key. Store request hash and byte-exact successful response in the same transaction for at least seven days; same key/different hash is 409.
- Strict write JSON: bounded UTF-8, duplicate-key detection, no trailing/unknown fields, floats/BOM/invalid Unicode rejected. Canonical hash preimage is `METHOD + LF + canonicalPath + LF + recursively-key-sorted compact UTF-8 JSON`.
- Point location contains manifest hash, block type/id, paragraph id, byte offset and paragraph hash; validate active edition, exact relations, hashes, range and UTF-8 code-point boundary inside the mutation transaction.
- Note anchor follows frozen H01 text-anchor contract: 1..16 contiguous ordered segments in one block, max 8192 authoritative selected bytes joined with exactly two LF, exact hashes/boundaries. Note text is preserved exactly and capped at 20,000 UTF-8 bytes.
- Lists expose only ACTIVE rows, use immutable internal `row_id DESC`, canonical decimal cursor as exclusive boundary, limit 1..100/default 100, and fetch limit+1.
- Absent/foreign/wrong-client/tombstoned resources use indistinguishable 404. Version conflict may return only current version, never resource/private data.
- Lock order: idempotency -> active content pointer/edition/location rows -> exact-scoped personal row -> CAS -> idempotency finalization. External systems are never called.
- Successful PUT/DELETE use HTTP 200. Empty note text is allowed. Mutation routes reject query strings. Existing edition of a bookmark/note is immutable. Tombstoned IDs cannot be resurrected.
