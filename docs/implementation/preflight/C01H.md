## Frozen scope

C01H creates an auditable, manually approved, idempotent baseline event for every byte-exact task-level `ELIGIBLE` task in one explicitly selected sealed B09 manifest and matching successful B09 run. It does not run B09, infer blocked tasks, fabricate historical transitions, or perform production DML.

Each exact `(tenant_id, client_id, task_id)` may have one deterministic `HISTORICAL_BASELINE_IMPORTED` event:

- actor: `system` / `c01h-b09`
- aggregate: `task` / byte-exact task ID
- `occurred_at`: selected B09 successful run `completed_at`
- event version: locked pre-apply `current_event_version + 1`
- `task_version`: unchanged
- payload: canonical bounded metadata only: `contentSha256`, `decisionCode=c01h_b09_v1`, `memberCount`, `source=b09`, `workItemCount`
- event ID: `c01h-` plus SHA-256 of a domain-separated, length-prefixed encoding of tenant/client/task bytes

Comparisons must combine binary equality and octet length. No trim, case-folding, accent-folding, delimiter-concatenated digest input or `GROUP_CONCAT` digest is allowed.

## State and idempotency

- `INSERT_REQUIRED`: no prior baseline, complete event chain, exact approved snapshot; insert one event and CAS event version.
- `EXACT_NOOP`: prior byte-exact baseline has sealed manifest and successful C01H run evidence; no business/event/version change, one new audit run is allowed.
- `BLOCKED`: version gap/ahead/behind/overflow, unapproved or conflicting baseline, partial migration, scope/snapshot/B09 drift, active or inconsistent lease, invalid ID/scope, or count mismatch.
- Approval requires `T = R + O + X`, `X = 0`, and sealed rows `= T`.
- Apply requires `event inserts = version updates = R`, `R + O = T`, no member/work-item/task-version change, and full rollback on any failure.
- Zero candidates produce a signed read-only report only; no empty sealed batch or run.

## Transaction and authorization

Production order is fixed: stop task writers and drain transactions; backup/restore prerequisite; B09 dry-run/review/approve/apply; verify the selected successful B09 run; regenerate C01H export; independent C01H review/approve/apply; verify; dual sign-off; resume writers.

C01H uses a separate locked definer (`cyf_c01h_definer@localhost`). Operator direct DML to event/meta/audit tables is denied; only required reads, temporary staging and routine execution are allowed. Named locks are acquired in this order:

1. `b09-manifest-approve:<db>`
2. `b09-task-backfill:<db>`
3. `c01h-historical-baseline:<db>`

Within one InnoDB transaction, lock the sealed batch, then all task roots in binary scope/task order, then event/member/work-item snapshots, then append/CAS in the same order, insert the run and commit. Initializer may create and validate empty audit tables/triggers only; it must not install accounts/routines/grants or execute migration DML.
