## 4. 关键设计决定

- 保留 legacy `agent_task_meta.assigned_agent_id` 和全局 `UNIQUE(task_id)`，新多人关系以 `agent_task_member` 为事实源；B01 不迁移历史数据。
- 历史 `agent_task_meta.tenant_id/client_id` 继续允许空值，避免部署时破坏存量任务；B09 负责审计和回填。
- 四张新表不建立数据库外键，避免 task 来源、身份 registry 和后续 thread/event/outbox 任务之间形成跨模块迁移耦合；服务层后续必须执行同 scope 引用校验。
- 不在 B01 对 canonical ID 使用数据库正则 CHECK：ADR-001 兼容集合还包含 registry 显式登记的 legacy canonical ID 和 `builtin-songjiang`，合法性由 A02/B02 之后的身份服务校验。
- `agent_task_request.target_id` 为非空，要求诉求显式指向 Agent、角色、用户或系统目标。
- 未加入 identity registry/alias、thread、event、outbox/inbox/delivery、Entity/DAO 或历史回填实现。

## 7. 未解决问题与风险

- 迁移脚本按索引名称保证幂等；若生产库已存在同名但错误定义的索引，脚本不会自动破坏性替换，应用启动会由 `AgentSchemaInitializer` 快速失败。部署前应先检查 `SHOW INDEX` 并人工修复。
- MySQL `ALTER TABLE` 可能持有 metadata lock；应在低峰期执行并先备份。不要与仍在写 `agent_task_meta` 的长事务并行。
- B01 不回填历史 task member/work item，也不收紧历史 task meta scope；新服务不能假设所有历史记录已有完整 scope。
- 四张新表没有数据库外键，后续 B02/B03/B06 必须在事务和 DAO 查询中强制同 `tenant_id + client_id + task_id` 校验。
- 新增表一旦产生业务数据，回滚应用时应保留表和新增列；直接删除会造成不可逆数据丢失。
