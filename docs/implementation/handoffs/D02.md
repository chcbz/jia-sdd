## 事务与身份

```text
task root lock
-> identity/runtime validation + domain mutation
-> agent_task_event append/version CAS
-> agent_command_delivery
-> agent_outbox_event
-> commit
```

- 四类事实参加同一 Spring `REQUIRED` MySQL 事务，任一步失败整体回滚。
- `TASK_ASSIGNED` 的真实持久化 `eventId` 是 `causationId`；`correlationId=taskId`。
- `commandId` 按 exact tenant/client/task/target/`TASK_INVITE` 确定性 SHA-256 派生。
- `messageId` 是单次运输 UUID；outbox `eventId` 是独立 UUID；初始 `attempt=1`。
- exact duplicate 返回已有 delivery，不新增 outbox；同 commandId 不同 identity/bytes/hash fail closed。

## Canonical payload

- `command_payload` 保存稳定、bounded、白名单化的业务信封 UTF-8 bytes 与 SHA-256。
- `wire_payload` 保存可直接投递的完整命令信封，并显式包含 `messageType=command.dispatch`、`messageId` 和 `attempt`。
- key 顺序、数组 UTF-8 顺序、TTL（1 小时）、`workItemId:null` 均已测试冻结。
- payload 禁止 credential-like 内容；tenant/client/task/target 使用 byte-exact、长度和 scope 校验。

## 安全门禁

- `agent.command-outbox.enabled=false`：不解析 writer，不访问 transport 表。
- enabled 但 writer wiring 缺失：fail closed。
- `DB_SHADOW`：delivery/outbox 均写终态 `DEAD`，`last_error=DB_SHADOW_CAPTURE_ONLY`，未来 relay/reconnect 不得自动晋升该 backlog。
