## 2. v2 加固变更

本轮为独立 Review 结论 REJECT 的修复实施。Reviewer 指出 3 项问题，全部修复如下：

### P1-1：真实事务回滚验证

- 原测试 `secondCasConflictRollsBack...` 使用 mock `PlatformTransactionManager` + mock DAO，无法证明真实持久层在第二笔 CAS=0 时回滚第一笔 write。
- **修复**：新增 `AgentTaskStateServiceRealTransactionTest`（2 tests），使用真实 H2 内存数据库 + 真实 MyBatis-Plus SqlSessionFactory + 真实 DataSourceTransactionManager + Spring `TransactionInterceptor` + `ProxyFactory`，调用生产 service：
  - `memberWriteIsRolledBackWhenWorkItemCasFailsWithRealDbAndRealTransactionManager`：先让 member CAS 成功（version 匹配），work item CAS 失败（version=999 不匹配），断言异常后 DB 中 member 和 work item 状态/version 完全未变。
  - `combinedTransitionSucceedsAndCommitsWhenBothCasPass`：正向验证两笔 CAS 都成功时事务提交。
- **测试通过 Spring transaction interceptor / Proxy 代理调用生产 service，满足「真实事务」要求。**

### P1-2：组合转换 fail-closed on 空/不匹配 assignee

- 原代码 `if (!StringUtil.isBlank(assigneeAgentId) && !agentId.equals(...))` 在 assignee 为空时放行任意 member。
- **修复**：改为两段式检查：先判 blank → `INVALID_REQUEST "non-blank assignee"`，再判不匹配 → `INVALID_REQUEST "assignee does not match"`。work item 必须有非空 assignee_agent_id 且严格等于 member 的 agentId，否则不产生任何写。
- 补充 3 项测试：`combinedTransitionRejectsBlankAssigneeBeforeAnyWrite`、`combinedTransitionRejectsEmptyStringAssigneeBeforeAnyWrite`、`combinedTransitionRejectsMismatchedAssigneeBeforeAnyWrite`，均验证 DAO 未被调用。

### P2-3：持久化状态精确匹配

- 原代码对请求 target 和持久状态统一使用 `fromValue()`（trim + lowercase 归一化），导致非 canonical 持久值被静默接受。
- **修复**：
  - `AgentTaskStatus`、`AgentTaskMemberStatus`、`AgentTaskWorkItemStatus` 各新增 `fromPersistedValue(String value)` 方法，做 **精确 Map 查找**（不 trim、不 lowercase）。
  - service 中 `persistedTaskStatus`、`persistedMemberStatus`、`persistedWorkItemStatus` 改用 `fromPersistedValue`。
  - 请求 target 仍使用 `fromValue`（保留友好归一化，由 `requested*Status` 调用）。
- 补充 8 项测试覆盖：task/member/workItem 的 uppercase、whitespace、empty 非 canonical 持久值均返回 `INVALID_PERSISTED_STATE`；并确认请求 target 归一化仍有效。

## 3. 冻结的状态转换（无变更）

### 3.1 Task

```text
open       -> planning | assigned | cancelled
planning   -> assigned | cancelled
assigned   -> running | blocked | cancelled
running    -> reviewing | blocked | failed | cancelled
blocked    -> running | failed | cancelled
reviewing  -> running | completed | failed | cancelled
completed  -> archived
failed     -> archived
cancelled  -> archived
archived   -> (none)
```

### 3.2 Member

```text
invited  -> accepted | rejected
accepted -> working | left
working  -> done | blocked | failed | left
blocked  -> working | failed | left
done/rejected/failed/left -> (none)
```

### 3.3 Work item

```text
pending   -> ready | cancelled
ready     -> claimed | cancelled
claimed   -> running | ready | cancelled
running   -> blocked | submitted | failed | cancelled
blocked   -> ready | failed | cancelled
submitted -> completed | ready | cancelled
completed/failed/cancelled -> (none)
```

所有 source/target 涉及 `claimed` 的边均由 B04 专用 claim 协议执行。
