## 2. 实现结论

B07 建立了任务与既有聊天存储之间的显式、scoped 绑定：

- 复用 `chat_conversation`、`chat_message`，新增 `agent_task_thread`。
- MVP 仅开放每个任务唯一的 `team` thread；schema 预留 `review/work_item` 类型。
- 创建采用独立 Spring 事务：先创建 conversation，再插入唯一 binding；并发 loser 的 conversation 随事务回滚，随后读取 winner。
- 所有 binding/message 读写均携带精确 `tenant_id + client_id + task_id` 业务 scope；conversation/message DAO 还校验 tenant/client/conversation scope。
- 消息读取按 `create_time DESC, id DESC` 取最新 N 条，再反转为稳定升序返回。

## 3. HTTP actor 身份和成员 ACL

HTTP 请求中的 `actorAgentId` 只是调用者提名的执行身份，不是可信认证信息。服务端按以下顺序 fail closed：

1. `tenantId/jiacn` 与 `clientId` 只来自认证后的 `EsContext`，Controller 不接受请求覆盖。
2. 调用既有 `AgentService.requireApiKeyOwnedAgent(clientId, jiacn, actorAgentId)`；该边界与 WebSocket API-key handshake 共用，要求 runtime Agent 的 client/owner 匹配，并存在 active persona binding。
3. system Agent（`builtin-songjiang`）、跨 tenant/client Agent、缺失或 inactive binding 全部拒绝。
4. 所有权通过后，再按精确 task scope 查询成员 ACL。
5. 所有权或成员失败都映射为相同的通用 `TASK_THREAD_NOT_FOUND`，不暴露 Agent、task、binding 或成员是否存在；所有权失败发生在 task/member/thread/message DAO 访问前。

成员状态语义：

- `accepted/working/blocked`：可读写。
- `done/failed`：历史只读，不可追加消息或创建 thread。
- `invited/rejected/left`：无访问权。
- 未知持久化状态：无访问权。
- `observer` 只有在存在 member row 时才按相同状态规则授权；task metadata 中的 coordinator 字段本身不构成授权。

## 4. API

```http
POST /chat/task-threads/{taskId}/team
GET  /chat/task-threads/{taskId}/team?actorAgentId=...
POST /chat/task-threads/{taskId}/team/messages
GET  /chat/task-threads/{taskId}/team/messages?actorAgentId=...&limit=...
```

- `POST team`：幂等获取/创建团队 thread。
- `POST messages`：写入 scoped 消息，覆盖调用者伪造的 `taskId/threadType/actorAgentId` metadata。
- `GET messages`：`limit` 为 1..500，稳定返回最新消息。
- 内容及 metadata 按 UTF-8 `TEXT` 上限校验；title、senderName、scope ID 按 schema 长度在 DAO 前校验。

## 5. Generic ChatController 防绕过

Task thread conversation 使用保留标记 `conversation_scope_type='task_thread'`。普通聊天入口不能：

- 创建 direct 或 metadata `mode=task_thread` 会话；
- 通过 `/chat/stream` 复用 task-thread conversation；
- 通过普通 conversation get/content/update/delete 访问；
- 在普通 conversation list 中看到；
- 通过普通 stop-stream 或 conversation-events 路由操作/订阅。

Generic Controller 对上述访问统一返回普通 conversation 404，不暴露 task-thread ACL 细节；既有 Juyi Hall `public/bounty/private` 和 normal conversation 行为保留。
