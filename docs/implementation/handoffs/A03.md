## 4. 关键设计决定

- wire canonical 类型采用小写点分命名；旧外层 `type` 只作为兼容 transport hint，canonical 语义由 `messageType` 表达。
- `type` 与 `messageType` 若解析为不同语义则拒绝，避免 `task.event` 被伪装成 command 或 chat/result 混用。
- 只有 `command.dispatch` 可被客户端视为执行请求；`task.event` 不保留会触发旧客户端执行的 `task_event` 外层类型。
- 普通聊天暂时保留 `agent_direct_message` 外壳以维持旧客户端收件能力，但必须携带 `messageType=chat.message`；客户端按该字段停止任务执行和 task report 属于 A05。
- `agentId/sourceAgentId/targetAgentId` 表示 canonical 稳定领域身份；`runtimeInstanceId` 只表示进程实例，不参与任务、ownership 或业务外键。
- legacy `task.report` 继续调用旧单 Agent report 流程；canonical result 不提前接入旧聚合逻辑，避免越界实现 B08。
- A03 不持久化 ACK、不做命令幂等、不做客户端队列、不做 tenant/client/task/target 广播隔离。

## 9. 建议 ADR-002 文本

### 决策

1. Agent Protocol v1 使用 `schemaVersion=1` 和小写点分 canonical `messageType`。
2. v1 基础类型包括 `protocol.hello`、`protocol.error`、`agent.register`、`agent.presence`、`chat.message`、`chat.message.delta`、`command.dispatch`、`command.ack`、`work.progress`、`work.heartbeat`、`work.result`、`help.request`、`artifact.publish`、`task.event`。
3. 只有 `command.dispatch` 是执行触发消息；`task.event` 仅描述已发生事实，`chat.message` 即使携带任务上下文也不得隐式转为 command 或 result。
4. `agentId/sourceAgentId/targetAgentId` 均表示 ADR-001 canonical Agent 身份；`runtimeInstanceId` 只表示客户端进程实例，不得作为 ownership、任务成员、工作项、命令、ACK 或成果的业务外键。
5. `command.dispatch` 必须携带 `messageId`、`commandId`、`commandType` 和 `targetAgentId`；correlation/causation/task/work item 字段用于追踪，不改变消息类别。
6. 兼容期允许保留旧 transport 外壳和 alias，但必须归一化为唯一 canonical 语义；`type` 与 `messageType` 冲突时拒绝，不能猜测或静默降级。
7. legacy `task.report` 只进入兼容 adapter；多人任务聚合由 B08 实现。客户端队列由 A05 实现，ACK 持久化和幂等由 A06 实现，scope 隔离由 A04 实现。
8. WebSocket send 成功只代表服务端已尝试发送，不代表 Agent 已接收或执行；可靠状态由后续持久 delivery/ACK 协议定义。

### 兼容策略

- 普通聊天在 A05 完成前可保留 `agent_direct_message` 外壳，但必须携带 `messageType=chat.message`。
- legacy `agent.action` 归一化为 `command.dispatch`；legacy `task_event` 归一化为 `task.event`；legacy `task.report` 归一化为 `work.result` 并打 legacy adapter 标记。
- `codex.result` 可识别为 legacy result，但不得自动调用旧 `task.report` handler，避免重复副作用。
- 未实现的 canonical handler 必须返回显式协议错误，不得回退到 chat、command 或 legacy report 路径。

### 后果

- 服务端和客户端可以独立演进，RabbitMQ/Outbox/Inbox 复用同一 Envelope。
- 兼容期会同时存在 legacy transport 字段和 canonical `messageType`；监控应统计 legacy 命中率，并在 A05/A06 上线后逐步移除旧 alias。
- 在 A05 完成前，旧客户端仍可能忽略 `messageType`，因此普通聊天误报告风险仍存在，不能把 A03 视为端到端迁移完成。
