## Dedicated infrastructure

- `agentRabbitConnectionFactory` 只读取 `agent.rabbit-broker`，配置 correlated confirms 与 returns；非 `@Primary`、非 default candidate，不复用或覆盖 `spring.rabbitmq` / SMS beans。
- Bean 创建不建立网络连接；OFF/DB_SHADOW 不注册 D04 Rabbit infrastructure。
- `agentRabbitAdmin` 使用 dedicated connection factory，`autoStartup=false`、explicit declarations only；未注册自动发现的 `Declarables`。
- 显式 provision 仅在调用时按 exchange → queue → binding 声明；不 delete、purge 或 recreate。
- `agentCommandListenerContainerFactory` 仅 consume gate 开启时注册：manual ACK、prefetch 20、concurrency/max 1、default requeue false、consumer batch false。
- D04 未注册 listener endpoint，未实现 RabbitTemplate、Relay、业务 publish、Inbox、WS 或 retry scanner。

## Readiness 语义

- 成功 `provision()` 才能产生 `READY / CANONICAL_TOPOLOGY`，并由 `canonicalTopologyReady()` fail closed 判断。
- Passive API 只能确认 exchange/queue 名称存在，因此仅产生 `EXISTENCE_CONFIRMED / RESOURCE_EXISTENCE`；不能证明 type、arguments、TTL、DLX、DLRK 或 bindings。
- Binding 声明失败后再 passive verify 不会恢复 canonical READY。
- Broker 操作异常只暴露固定错误码与安全异常类型，不保留可能含 URI、凭据或 reply detail 的原始 cause/suppressed graph。
