## Relay 与事务语义

```text
bounded discovery
  -> REQUIRES_NEW delivery→outbox claim
  -> transaction-outside Rabbit publish
  -> REQUIRES_NEW delivery→outbox fenced settle
```

- discovery 为无锁 hint；claim/settle 都重新锁定并核验 exact tenant/client、identity、status、attempt、lease、version、wire bytes/hash。
- 网络发布永远在数据库事务外；ACK+NOT_RETURNED 优先结算为 `PUBLISHED`，即使 callback 时已经到达或越过 expiresAt，消费侧 expiry 由 D07/D05持久化。
- confirm NACK、mandatory return、timeout 按确定性退避进入 RETRY；超过 attempt/expiry 后进入 FAILED/EXPIRED。
- crash-after-confirm 允许重复 Rabbit publish；D07 Inbox 负责消除重复副作用。
- scheduler 有 bounded max-inflight 与 graceful drain；未取得 claim 不调用 Rabbit。

## Provenance 与合同

- 原始 wire bytes 与 SHA-256 不重序列化；eventId、deliveryId、commandId、tenant/client/task/targetAgent、commandType、delivery activeAttempt、expiresAt、topology digest 和 source settlement retry 通过冻结的 13 个 typed `x-jia-agent-*` headers 传递。
- 仅允许 D04 exact command routes；无广播、wildcard 或 hidden selected state。
- outbox publish attempt 与 delivery transport/reissue attempt 分离；D05/D06 不得混用。

## Corruption 与版本边界

- 正常 discovery 在 SQL 层排除可识别 poison；独立 bounded corruption lane 对 deliveryId<=0、blank/control scope、missing delivery 和版本耗尽做 fenced quarantine，避免 poison-head 饥饿和 250ms 热扫描。
- 可安全关联时同一事务把 delivery/outbox 置为 DEAD；孤立 outbox 使用 PK + 原始 scope/version/status 严格 quarantine；Rabbit 调用为零。
- `Long.MAX_VALUE` 与 `MAX-1` 使用饱和 quarantine，不回绕；claim 必须为 settle 预留一次 version increment。
- `MAX-2` 双 claimant 只允许一个 winner：败者锁后识别 fresh superseded CLAIMED 并零 mutation 返回；winner ACK 后 delivery/outbox 原子结算为 `PUBLISHED/MAX`。
- stale callback、partial claim/settle/quarantine CAS 失败均不能覆盖新状态；事务整体 rollback。
