## 2. 实现摘要

1. `AgentTaskDTO`、`AgentActionIntentDTO` 显式携带 `tenantId/clientId`；任务 meta 在当前可信 `EsContext` 下写入并校验 scope，task briefing command 从任务事实源继承 scope。
2. 新增显式 scoped 的任务成员解析：优先读取 `agent_task_member`，排除 `rejected/left`；仅在没有成员行时兼容 legacy `agent_task_meta.assigned_agent_id`。
3. `publishTaskEvent()` 不再调用全 session `broadcastEvent()`；先按 `tenantId + clientId + taskId` 解析成员，再为每个成员生成明确 `targetAgentId` 并逐一投递。
4. `command.dispatch` 及任务类 canonical 下行必须具备字符串类型的 `tenantId/clientId/taskId/targetAgentId`；顶层或嵌套 scope/target 冲突、缺字段、非字符串字段、目标与可信方法参数不一致时 fail closed。
5. 投递时以握手固定的 canonical `agentId`、session `jiacn/clientId` 和任务成员事实源共同授权；不解析 agentId 字符串，也不使用 `runtimeInstanceId` 作为业务身份。
6. `HallActionDispatcher` 的 tenant/client 来自当前服务端认证上下文，task target 还会在 WebSocket handler 中通过 scoped 成员关系复核；跨 scope 的同名 Agent session 不视为可连接目标。
7. 普通 `chat.message` 继续走既有 `agent_direct_message` 兼容外壳，不要求任务 scope；A03 的 messageId/requestId、sentAt/timestamp alias 和最终 Envelope 行为保持不变。
8. 未实现 A06 ACK、commandId 去重或 durable delivery；未部署、未重启后端、未执行生产迁移。
