## 2. 第三轮修复闭环

### MySQL 8.0.21 migration

- 删除不支持的 `CREATE TRIGGER IF NOT EXISTS`；统一为四个
  `DROP TRIGGER IF EXISTS` + `CREATE TRIGGER`，脚本可连续执行。
- 提供真实 b0 → 当前升级 DDL：
  - registry/alias 转为 `utf8mb4_0900_bin`；
  - 重建 11 个 CHECK、alias composite FK 和四个保护触发器；
  - 固定关键列类型、nullability、generated expression、唯一索引和 scope 索引；
  - 补齐 `agent_runtime.owner_jiacn/persona_code/binding_id` 及索引；
  - 历史数据或结构不兼容时 `SIGNAL`/DDL 失败，禁止猜测或静默重写。
- registry/alias DB 层保护：canonical ID/type、owner scope、binding ID 不可变；
  RETIRED/REVOKED 不可恢复；物理删除被拒绝，因此已签发 canonical ID 不可删除后复用。

### Dry-run

- 删除重复 `linked_candidate_counts` / `exact_candidate_counts` CTE。
- 在 `resolved_candidate` 前保留 `linked_runtime_candidates`、
  `exact_runtime_candidates` 和 `raw_candidate_evidence`。
- 同 binding 的 unique linked canonical 与 exact canonical 不一致时输出：
  `runtime_match=LINKED_EXACT_CONFLICT`、
  `resolution_status=BLOCKED_LINKED_EXACT_CONFLICT`。
- task 引用的 `client_id/tenant_id` 缺失或空白时输出
  `BLOCKED_TASK_SCOPE_MISSING`。

### Initializer

- 新库创建的触发器与 migration 使用同一精确定义。
- 对已有 identity 表 fail closed 验证：
  - registry/alias 必须同时存在；
  - 列 data type、column type、nullability、binary collation、generated expression；
  - required index 唯一性、顺序和 prefix；
  - 11 个 CHECK 的完整规范化定义；
  - alias composite FK 列顺序、引用列、`RESTRICT/RESTRICT`；
  - 四个 trigger 的 timing/event/action 完整规范化定义；
  - runtime projection 三列和两个索引。
- b0 `utf8mb4_0900_ai_ci` identity 表不会被误判通过；partial identity 表在
  `CREATE TABLE IF NOT EXISTS` 掩盖前即失败。
