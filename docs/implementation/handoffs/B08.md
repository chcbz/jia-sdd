## 2. 本轮独立审查发现关闭

### P1-1 suspended/retired 历史成员阻塞聚合

- A08 身份边界拆分为两类：
  - `lockActiveCanonicalAgentIdsInScope(...)`：新 assign/report 使用，要求 direct canonical、ACTIVE registry、ACTIVE binding，并持锁到事务提交。
  - `requirePersistedCanonicalAgentIdInScope(...)`：aggregation 历史引用使用，允许曾合法激活后进入 ACTIVE/SUSPENDED/RETIRED，但拒绝 PROVISIONED、system、unknown、cross-scope、alias 文本、padding/control、registry/binding/alias 篡改。
- 历史引用仍要求 byte-exact direct canonical、完整 tenant/client/owner/registry/binding 投影；legacy binding 文本只能由 ACTIVE/REVOKED 审计 alias 证明，不能把任意格式正确字符串当作合法身份。
- 团队 A+B 中 A suspend/retire 后，ACTIVE B 可继续 report 并完成聚合；A 自己的新 assign/report 仍由 active ownership gate 拒绝。

### P2-1 并发首次 assign root

- `AgentTaskMetaMapper.reserveOpenTaskRoot(...)` 使用 scoped `INSERT IGNORE` 创建确定性 root：`open/single/low/maxAgents=1/reviewRequired=0/taskVersion=0/currentEventVersion=0`。
- 随后使用 byte-exact scoped `SELECT ... FOR UPDATE` 锁 root；已存在行不会被后续请求覆盖。
- taskId 在 DAO 入口拒绝 padding/control/超长；MySQL 宽松 collation 下大小写碰撞只会导致 exact lock 查不到并 fail closed，不会合并或修改另一 task。
- 真实事务并发覆盖：同集合首次 assign 恰好一 changed、一 no-op；不同集合恰好一成功、另一业务拒绝，最终一 root、一 member、一 item，无部分写或 500 UNIQUE 泄漏。

### P2-2 unscoped `findByAgentId`

- DAO 改为 `findByAgentId(tenantId, clientId, agentId, limit)`。
- SQL 下推 tenant/client/agent 的普通等值索引条件与 `BINARY + OCTET_LENGTH` byte-exact 复核。
- 排序固定为 `update_time DESC, task_id ASC, id ASC`，limit 最大 500；调用方在 `size >= 500` 时 fail closed。
- `AgentServiceImpl` 旧 fallback、stats 和 `AbilityEvaluationServiceImpl` 均传入当前 scope，并对 mapper 返回的 scope/agent/taskId 漂移再次 fail closed。

### P2-3 identity TOCTOU

- assign/report 锁序统一为：`task root -> persona binding -> identity registry`。
- registration/suspend 锁序统一为：`persona binding -> identity registry`。
- 多 Agent identity 按 unsigned UTF-8 byte 顺序逐个获取 binding/registry 锁；生产路径不存在 `identity -> task` 反向锁序。
- 真实事务竞争覆盖 assign/report 与 suspend 的两种提交顺序：操作先持锁则先提交后 suspend；suspend 先提交则操作等待后拒绝且不写 task；无死锁或 suspend 后后发 mutation。

- 多个 `legacy_default`：`INVALID_PERSISTED_STATE`，明确 multiple legacy defaults。

## 3. 锁序与副作用

```text
legacy assign/report: task root -> binding(s, unsigned UTF-8 canonical order) -> registry(s)
registration/suspend: binding -> registry
aggregation:          task root -> snapshot reads -> persisted identity reads (no identity row lock)
```

- 不存在 identity 锁后再请求 task root 的生产路径，因此未形成 suspend/registration/aggregation 反向环。
- dispatch、task/status event、scene publication 仍仅在 changed 或首次 terminal transition 后注册 after-commit；duplicate/no-op 不触发副作用。
