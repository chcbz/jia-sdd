### P0-2: 持久队列恢复路径可执行非 `command.dispatch` —— 已修复
- `enqueue()` 入口：调用 `normalizeInboundMessage()`，断言 `messageType === command.dispatch` 且 `targetAgentId` 匹配，否则抛 `AgentProtocolError` 拒绝入队。
- `readAndValidate()`: 对每条持久记录重新调用 `normalizeInboundMessage()`，校验 `messageType`、`targetAgentId`、`messageId`、`commandId`、`commandType` 一致性；不合法记录抛异常 → quarantine。
- `assertExecutable()`: 执行前再次全量校验，不通过则 quarantine + reject，不执行。
- `runDrain()`: claim 后调用 `assertExecutable()`，失败 quarantine 并 continue 处理下一条，不 pause。

### P0-3: 持久化 fail-closed —— 已修复
- 所有文件系统操作通过可注入 `fs` 参数（默认 `DEFAULT_FS_OPERATIONS`），测试可注入故障。
- `ensureSecureDirectory()`: mkdir → chmod 0700 → fsync 目录 → 新目录 fsync 父目录。
- `atomicWriteText/atomicWriteJson`: 临时文件 → fsync → close → rename → chmod 0600 → fsync 目标目录。**fsync/rename 异常均向上传播，不回吞。**
- `durableRename()`: rename → chmod → fsync 源目录，跨目录额外 fsync 目标目录。
- `durableUnlink()`: unlink → fsync 目录。
- `initialize()`: 递归 ensureSecureDirectory 所有队列目录，secureExistingQueueFiles 修复既有文件权限为 0600。

## 6. 升级与回滚风险

1. **目录权限**：部署前必须确保 systemd service user 有 create/rename/delete/fsync 权限。
2. **禁止双实例**：新旧客户端不能同时以相同 canonical `agentId` 运行。
3. **回滚会遗留队列**：回滚前必须先 drain 或保留目录。
4. **A06 重复窗口**：外部副作用已发生但 completed marker 未落盘时崩溃，重启可能重复执行。
5. **Node 20 需 `npm ci --omit=dev`**：部署后必须安装 ws 依赖。
