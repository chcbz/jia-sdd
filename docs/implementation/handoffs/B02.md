## 6. B03 仍需处理的并发与事务边界

1. **CAS 失败归因**：DAO 返回 0 affected rows 时，B03 需要在业务层区分 stale version、记录不存在和 tenant/client scope 不匹配，并映射为稳定错误码；不能把 scope 不匹配泄露成跨租户记录存在性信息。
2. **状态迁移矩阵**：当前 DAO 提供完整快照 CAS 原语，不判断 member/work item/request 的合法状态迁移；B03 需定义 from/to 状态、调用方权限和终态规则。
3. **聚合事务边界**：成员状态、工作项状态与 `agent_task_meta.task_version` 的联动需要由 B03 在同一事务中协调，避免部分成功。
4. **冲突策略**：B03 需决定 CAS 冲突是直接返回、有限次数重读重试，还是由上层重新决策；不得在 DAO 内无限重试或静默覆盖。
5. **多实体原子性**：创建/更新成员、工作项、诉求、成果以及后续任务事件写入需要明确原子边界；C01 事件能力接入后应确保业务变更和事件版本一致。
6. **完整快照约束**：work item/request 的 CAS 更新当前要求必要非空字段完整提供，B03 应从持久对象构造更新快照，避免调用方用缺字段 DTO 将可空业务字段意外清空。
7. **同 scope 引用完整性**：B01 未建立数据库外键；B03/B06 必须验证 task、member、work item、request、artifact 引用属于同一 tenant/client scope。
