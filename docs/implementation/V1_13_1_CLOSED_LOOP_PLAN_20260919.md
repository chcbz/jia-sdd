## 2. 用户得到什么

- 一次上传，空间/悬赏/议事均可选择并引用，不下载重传。
- 空间选文件可“关联悬赏”或“交给Agent”；任务中可“从空间添加资料”和“进入议事”。
- 在议事通过文字要求生成/修改，明确本轮Agent、材料版本和授权；不用另填私人执行表单。
- 真实成果自动保存，三处同版本预览下载并显示来源；任务成果依既有formal-delivery提交。
- 点击“继续修改”固定源版本产生新版；原件/旧版保留；需要验收的任务由owner在悬赏或议事操作同一正式决定。
- 无悬赏可私人议事；事后选择关联任务时不自动公开私聊或整个文件库。
- 刷新、重登、Agent离线后仍可找回已存结果；失败先恢复同一次输出，不自动重新生成收费。

## 3. 一条可独立验收的业务旅程

```text
空间上传 DOCX + XLSX
  → 悬赏“制作项目汇报PPT”选两份资料v1
  → 进入该任务议事，确认资料/Agent/调用范围
  → 说“生成5页中文汇报PPT”并执行
  → 真实PPTX自动归档，议事/任务/空间同版本可预览下载
  → 说“缩短第三页、增加总结页”，交付新版、保留旧版
  → owner正式验收，三处显示同任务同批次结果
  → 重登后仍能下载全部授权版本
```

同时跑无悬赏私人路径，以及生图、原图修改、外部PPT修改、Word、Excel、常规PDF场景。不能用单条PPT旅程替代全部原MVP格式。

## 4. 不是仅前端接线的原因

本轮源码核对发现：
1. `/tasks/{taskId}/file-links`已有，但Web未接入。
2. 私人执行仅保存可选conversationId，不足以证明会话授权；Web也未传任务/会话上下文。
3. `useOutputs.js`的conversation查询固定为空，不是“只缺入口”。
4. 当前输出commit新建空间文件v1，未接任务artifact/正式交付，连续修改也缺明确派生版本闭环。
5. 正式交付必须有真实task/workItem/run/producer/lease及版本前提，不能拿私人执行的保存回执替代。
6. 现有Office/PDF预览主要是文本；PPT/PDF逐页、Excel分表及真实Provider处理仍需实现/验证。

所以本版需覆盖 **Web + API/Chat + 必要runtime适配 + 文件预览/处理验证**。原手工成果传输面板不作为用户闭环方案，也不能用有组件/接口就推导线上整条流程可用。

## 5. 实施与验收安排

- W00合同/真实依赖盘点；W01关系/ACL；W02执行/租约；W03会话与消息；W04成果/正式提交；W05统一选择器；W06空间/悬赏；W07议事；W08修改验收；W09格式/预览；W10全回归；W11发布。
- 源码并行按任务与路径，Owner自检，不创建独立Reviewer。Gradle由orchestrator串行；不改别的任务进程/证据或脏文件。
- 初估基础168–274人时，风险24–48，总192–322；属于工程判断，不是确定工期。W00和首个真实纵向闭环后校准。
- **20项A类**：无Provider的合同/权限/关联/恢复/前端集成。
- **8项B类**：真实Provider和文件业务效果，预先取得账户/额度/资料外发授权。
- **3项C类**：精确制品、实际部署后三入口回归、用户通知与独立验收。
- 当前已完成W00–W09源码候选与局部静态自检；**A01–A20尚无正式PASS，B01–B08仍为0项，C01–C03仍为0项**。1.13.0历史回归只证明其已测范围，不能搬作本版新验收结果。精确候选与阻塞记录见 `V1_13_1_IMPLEMENTATION_STATUS_20260919.md`。

## 6. 发布约束

自检测试后合入组件develop，经过验证的exact SHA冻结release/1.13.1；不动release/1.13.0。API/必要runtime/Web兼容升级，遵守实际发布窗口、互斥与健康；Flow正常则复用既有流水线，临时本地授权仍有效时真实标记build_origin，不伪造Run。

代码候选、技术部署、业务验收分别记录；授权缺失、格式失败、正式交付不通都不得宣称完整闭环通过。方案不是Provider付费/生产数据修改的自动授权，发生此类操作前必须有明确范围。
